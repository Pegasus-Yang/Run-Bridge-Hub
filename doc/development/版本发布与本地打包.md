# Hub 版本发布与本地打包

每次更新本项目版本号，都必须在本机生成可直接安装的发行包。标准交付目录是**当前项目根目录的 `dist/`**，不能只把新版放到私有验收目录；Hub 和 Node 分别在自己的项目内构建。

## 发布顺序

1. 同步 `pyproject.toml`、`src/runbridge_hub/__init__.py`、`uv.lock`、当前文档与安装示例中的版本。历史验收和旧发布记录保留原版本。
2. 完成受影响的检查并提交版本变更，记录实际构建提交。安装包应来自预期发布提交，不能把旧文件改名充当新版。
3. 在本项目根目录执行下方构建命令，生成 wheel 和源码分发包。
4. 核对文件名、包内 `METADATA/PKG-INFO` 和运行时版本，使用独立目录与全新 `.venv` 安装 wheel，运行版本查询、`--help` 与必要的配置检查。
5. 检查通过后在同一版本提交上创建本地附注 tag，并交付**本次版本的完整文件名**。已有 tag 保持原指向；重新构建同一发行版应使用原 tag 对应的源码。

服务运行验证与打包检查分别记录。用户要求不启动服务时，只做安装、帮助和配置检查；不要为验收启动日常环境。提交、tag 与本地构建都不包含推送或对外发布授权。

## 构建当前版本

基础 Python/uv 的要求同[开发手册](本地开发与联调.md)，不在这里重复基础工具安装方法。在项目根目录执行：

```bash
uv build --out-dir dist --no-sources -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

该命令先构建源码分发包，再从中构建 wheel。0.9.3 应得到：

```text
dist/runbridge_hub-0.9.3-py3-none-any.whl
dist/runbridge_hub-0.9.3.tar.gz
```

下一版本使用对应的新文件名，不能只沿用本例的版本号。`.whl` 用于安装运行，`.tar.gz` 用于分发对应源码；它们是两种形式，不需要同时安装。`dist/` 被 Git 忽略，本地包不提交到仓库，不删除旧版本来掩盖新包缺失。

## 在独立环境安装检查

下面假定新环境位于 `/absolute/runbridge-hub-check/`，请替换为自己创建的实际目录；其虚拟环境放在该目录的 `.venv/`。以下命令从**本项目根目录**执行，避免相对 `dist/` 指向别处：

```bash
uv venv --python 3.14 /absolute/runbridge-hub-check/.venv
uv pip install --python /absolute/runbridge-hub-check/.venv/bin/python "dist/runbridge_hub-0.9.3-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
/absolute/runbridge-hub-check/.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'
/absolute/runbridge-hub-check/.venv/bin/runbridge-hub serve --help
```

输出版本应为 `0.9.3`，帮助中应包含 `--settings`、`--disable-web` 、`--web-token-file`、`--hub-token-file`、`--public-url` 和两项grant超时配置。`[mcp]` 用于 MCP；仅使用 HTTP 时可以省略。其他 extras 的用途见[参数详解](../reference/参数详解.md)。

升级自己已有的测试环境时，使用其真实 `.venv/bin/python` 指定安装位置，不要再次运行 `uv venv` 重建环境，也不重新生成登记文件、数据库或身份。配置相对路径的基准和默认值见[参数详解](../reference/参数详解.md)。

## 发现安装版本不匹配时

先检查虚拟环境实际安装元数据和安装来源。源码已更新、Git 有新 tag、或者另一个 `.venv` 是新版本，都不能证明自己的环境已升级。不同版本的同名命令还可能来自不同目录，应使用目标环境的完整 CLI 路径。

收到旧 wheel 时，改用当前 `dist/` 中明确带目标版本的文件重新安装；不要只重命名旧 wheel。若安装的是 editable 源码，则它属于开发方式，不等同于验证发布包可安装。

版本与变更见[发布记录](../project/版本发布记录.md)。

## PyPI 提交前检查

公开分发使用英文 README 作为长描述，中英文首页的文件链接均为完整 GitHub 地址，架构图使用静态 SVG。构建前按当前版本提交；构建后执行 Twine 严格检查、独立 wheel 安装、配置解析和文件摘要核对。首次实际上传前先同步 GitHub 提交与 tag，使介绍中的文档和图片可公开访问。具体命令、凭据来源、预演和上传后核验见 [PyPI 发布准备](PyPI发布准备.md)。
