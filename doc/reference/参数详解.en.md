# Hub parameter reference

[简体中文](参数详解.md) · English

Applies to **Hub 0.9.3**. Start with the [quick start](../user-guide/快速开始.en.md). Use this reference for defaults, paths, and scenarios, or copy the [annotated YAML](examples/Hub启动配置.en.yaml).

## Startup forms and paths

Recommended YAML startup:

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

Direct CLI options remain available, for example for local-only binding:

```bash
.venv/bin/runbridge-hub serve --enrollment-token-file .runbridge/enrollment.token
```

`--settings` cannot be combined with other startup options, even explicit defaults. Edit YAML and restart to change settings.

- The `--settings` path itself is relative to the working directory.
- YAML file paths (`database_path`, `enrollment_token_file`, `web_token_file`, `hub_token_file`) resolve from the **YAML directory**, including the default database path.
- Without YAML, CLI paths are relative to the working directory.
- YAML does not expand `~`, `$HOME`, or shell expressions. Use relative or absolute paths.
- Files are UTF-8, space-indented, with an object at the top level. Unknown fields and unsupported format versions are rejected.

For example, `database_path: data/hub.sqlite3` inside `/srv/runbridge/hub.yaml` resolves to `/srv/runbridge/data/hub.sqlite3` regardless of the working directory.

## All serve options

| CLI option | YAML field | Default | Purpose |
| --- | --- | --- | --- |
| `--settings FILE` | — | No YAML | Read all settings for an environment; do not combine with other options |
| — | `config_version` | `1` | Hub YAML format; only 1 is accepted; independent of Node YAML |
| `--host ADDRESS` | `host` | `127.0.0.1` | Bind address; use a reachable interface or `0.0.0.0` for remote access |
| `--port NUMBER` | `port` | `8787` | Usually 1–65535; 0 requests a temporary system-assigned port for tests; update handoff URLs when changed |
| `--db-path FILE` | `database_path` | `.runbridge/hub.sqlite3` | SQLite path; parent/database are created initially; retain the original for existing deployments |
| `--enrollment-token-file FILE` | `enrollment_token_file` | Unset | Original enrollment token file, generated by `generate-token`; overrides its environment variable |
| `--hub-token-file FILE` | `hub_token_file` | Unset | Claim credential; overrides `RUNBRIDGE_HUB_TOKEN`; without either, pool/claim APIs return 503 |
| `--public-url URL` | `public_url` | Unset | Actual HTTP(S) base URL exported in access files; proxy prefix allowed, credentials/query/fragment forbidden; required for claims |
| `--grant-max-lease-seconds N` | `grant_max_lease_seconds` | `86400` | Positive maximum duration for claims and renewals |
| `--grant-idle-timeout-seconds N` | `grant_idle_timeout_seconds` | `600` | Positive idle timeout snapshotted for new leases; status, frames, heartbeats, and renewal do not reset it |
| `--disable-web` | `web_enabled` | `true` | CLI flag or YAML `false` disables `/dashboard`, its assets, and API |
| `--web-token-file FILE` | `web_token_file` | Unset | Separate read-only token; overrides `RUNBRIDGE_WEB_TOKEN`, otherwise generate/reuse `web.token` beside the database |
| `--heartbeat-interval SECONDS` | `heartbeat_interval_seconds` | `30` | Application heartbeat interval sent to Node; positive |
| `--heartbeat-timeout SECONDS` | `heartbeat_timeout_seconds` | `90` | Lost-connection threshold; greater than heartbeat interval |
| `--enable-mcp` | `mcp_enabled` | `false` | Expose `/mcp`; install `[mcp]` in this `.venv` |
| Repeated `--mcp-allowed-host HOST` | `mcp_allowed_hosts` | `[]` | Empty means unrestricted Host; a nonempty list permits only its entries |
| Repeated `--mcp-allowed-origin ORIGIN` | `mcp_allowed_origins` | `[]` | Allow supplied Origin values; clients without Origin need no entry |

One Hub process and one worker use a database; sharing it across Hub processes is unsupported. HTTP, MCP, and dashboard share a listener. Bind host does not populate an MCP allowlist. Dashboard access is read-only and uses a separate credential. RTT requires the standard CLI; see [dashboard](../user-guide/节点总览.en.md).

## Configuration scenarios

### Local-only access

```yaml
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://127.0.0.1:8787
```

This binds to `127.0.0.1:8787`. With the extra installed, add only `mcp_enabled: true` for local MCP. Other devices need the next configuration.

### Remote Nodes over HTTP

```yaml
host: 0.0.0.0
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787
```

Replace `hub.example` with an actual reachable IP or resolvable name, never `0.0.0.0`. Default port and database need not be repeated.

### Restrict MCP Host when needed

An omitted or empty list permits all Hosts, still requiring a valid lease token. Binding and `public_url` do not generate restrictions. To restrict a stable endpoint:

```yaml
host: 0.0.0.0
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787
mcp_enabled: true
mcp_allowed_hosts:
  - "hub.example:8787"
```

Client URL: `http://hub.example:8787/mcp`. Entries are the URL's hostname/IP plus port, without scheme/path. They do not identify the client or Node IP. Manage DNS separately.

`"hub.example:*"` accepts any port for that host. Standalone `*`, `*.example`, and `192.168.*.*` are unsupported; omit the list or use `[]` for all Hosts. A nonempty list must explicitly contain each required hostname, IP, and loopback entry.

### Web clients supplying Origin

```yaml
mcp_allowed_origins:
  - "https://console.example"
```

An Origin contains scheme, host, and any required port, with no path. HTTP and HTTPS Origins differ. This validates MCP requests; it is not a full browser cross-origin deployment configuration.

## Token generation and precedence

```bash
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
```

`--output FILE` is required. The generator exclusively creates a UTF-8 single-line random token, mode `600`, creating parent directories as needed and refusing overwrite. Generate enrollment, claim, and read-only tokens separately.

`RUNBRIDGE_ENROLLMENT_TOKEN` is used only when no enrollment file is set. An explicit missing, unreadable, empty, or invalid file fails without fallback. Tokens must be 32–256 characters. YAML stores paths and policy, not token contents, Node identities, or client permits. See [credentials](部署配置与凭据.en.md).

## Help and errors

Root, `serve`, and `generate-token` accept `-h` / `--help`:

```bash
.venv/bin/runbridge-hub serve --help
```

Invalid configuration exits nonzero before starting service. YAML syntax/model errors hide input secrets. Check spelling, paths, heartbeat relation, port range, unsupported wildcards, and mixed CLI/YAML. See [common problems](../user-guide/快速开始.en.md#common-problems).

## Lease options and offline review

For claims/renewals, omitted `lease_seconds` means `min(3600, grant_max_lease_seconds)`; explicit values above the maximum fail. Browser sessions separately allow 1–3600 seconds. After configuration changes and restart, a new maximum affects later claims/renewals without shortening existing `expires_at`; a new idle policy affects new leases only. Renewal does not reset idle time. See [lease API](Node使用权租约接口.en.md).

`confirm-cleanup --db-path FILE --grant-id ID --evidence-file FILE --confirm-node-stopped` is local offline maintenance after stopping Hub and related Nodes, using reviewed evidence rather than a shared token. The process lock prevents online maintenance and preserves original UNKNOWN cleanup. Follow [operations](../deployment/运行与排障.en.md).
