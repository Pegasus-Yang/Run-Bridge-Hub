# Hub 部署与运行

适用于 Hub/Node 0.6.0。本文所有命令在 **Hub 服务器**执行，面向部署者。调用方另读[调用教程](../user-guide/调用方对接与使用.md)。

## 1. 准备要求与交接材料

需要 Python **3.14.x**、可用的全局 uv、Shell、可供 Node 与调用方访问的 HTTP(S) 地址及端口，以及发布者交付的 `runbridge_hub-0.6.0-py3-none-any.whl` 和本手册。

基础工具由环境管理员准备；安装和升级参考 [Python 官网](https://www.python.org/downloads/)与 [uv 官网](https://docs.astral.sh/uv/getting-started/installation/)。Hub 不依赖浏览器、Playwright 或 Node.js。以下示例假定 wheel 位于 `~/Downloads/`。本机路径可以调整，但后续须保持一致。

## 2. 建立独立部署目录和 Python 环境

```bash
mkdir -p ~/runbridge-hub
cd ~/runbridge-hub
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_hub-0.6.0-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
```

`[mcp]` 同时安装 MCP 入口所需依赖；只使用 HTTP 时可去掉。`.venv` 是本次程序环境，`.runbridge` 保存数据和秘密。后续运行都使用该 `.venv/bin/` 下的命令。Windows 使用 `.venv/Scripts/` 的对应命令；本文 Shell 示例面向 macOS/Linux。

## 3. 生成登记文件

```bash
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
```

命令生成随机秘密，排他创建文件，拒绝覆盖已存在文件；目录权限私有、文件权限 `600`。**此文件就是要交给 Node 所有者的登记文本**，Hub 和 Node 使用同一份内容。已有部署继续使用原文件，不要每次重启都重新生成。

文件是 UTF-8 单行纯文本，末尾可以有换行。格式示意：

```text
EXAMPLE_ONLY_ENROLLMENT_TOKEN_DO_NOT_USE_00000000000000000000000
```

示例不能用于登记。生成器通常产生 64 个字符，合同接受 32～256 字符。文件里不写 JSON、引号、`Bearer ` 或 `token=`；Hub 启动时从指定路径读取内容。

## 4. 保存 YAML，启动并确认服务

在部署目录创建 `hub.yaml`，以下为允许远程 Node 连接的最小配置：

```yaml
host: 0.0.0.0
enrollment_token_file: .runbridge/enrollment.token
```

`0.0.0.0` 是监听所有 IPv4 网卡；仅本机访问时可省略 `host`。默认端口为 `8787`、数据库为 `.runbridge/hub.sqlite3`，无需重复填写。YAML 相对路径以本文件目录为准，不展开 `~`、`$HOME` 或 shell 表达式。完整[注释样例](../reference/examples/Hub启动配置.yaml)和[参数详解](../reference/参数详解.md)说明全部字段、默认值和场景。

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

此命令前台常驻，保留终端；不能同时追加 `--port` 等启动参数，统一修改 YAML。另开终端在 Hub 本机检查：

```bash
curl --fail http://127.0.0.1:8787/health
```

响应为 `{"status":"ok","protocol_version":2}`，不含安装包版本。安装版本可在本部署环境运行 `.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'`，应为 `0.6.0`。再从 Node 所在网络检查实际基址的 `/health`；`0.0.0.0` 不能作为交付地址。健康检查只证明 Hub 可用；浏览器由 Node 所有者检查。

需要 MCP 时，在已安装 `[mcp]` 的前提下增加 `mcp_enabled: true` 并重启。本机 MCP 客户端通过 localhost/127.0.0.1 访问时无需额外允许项。远程 MCP 才增加：

```yaml
mcp_allowed_hosts:
  - "hub.example:8787"
```

用实际 URL 的主机名或 IP 加端口替换示例，不含协议和路径；该参数不填写 Node 或调用方 IP。使用稳定名称前要确保对应机器可以将其解析到当前 Hub 地址。普通不带 Origin 的客户端无需填写 `mcp_allowed_origins`。

HTTP 与 MCP 共用监听地址，MCP URL 为实际基址加 `/mcp`；未启用时入口不存在。跨公网部署的 HTTPS、WebSocket 代理由环境管理员管理。单 Hub 进程、单 worker；代理须转发 WebSocket 并允许长连接。

## 5. 把完整材料交给 Node 所有者

通过私密渠道交付 **第 3 步真实生成的 enrollment.token 文件**，以及以下填写完整的说明：

```text
Hub 版本：0.6.0；配套 Node：0.6.0
Hub 基址：http://192.168.50.10:8787
登记附件：enrollment.token（与 Hub 启动读取的文件相同）
Node 安装包：runbridge_node-0.6.0-py3-none-any.whl（由发布负责人提供）
Node 手册：RunBridge Node 的《部署与运行》及配置样例
MCP：按实际填写“未启用”，或“已启用，入口 http://192.168.50.10:8787/mcp”
```

基址不能以 `/health`、`/v1`、`/v2` 或 `/mcp` 结尾。应分别从 Node 网络和调用方网络确认可达。Node 所有者完成登记后会自行签发 `access.json` 交给调用方；这份访问 JSON 与登记文本不同。Hub 部署者无需手工编写节点身份、访问令牌或浏览器地址。

登记文件仅用于接纳节点，不能用于浏览器调用；`access.json` 中的访问令牌也不能代替登记令牌。文件字段、来源和保管职责见[凭据参考](../reference/部署配置与凭据.md)。

## 6. 长期运行、停止与备份

使用所在环境的进程管理器固定部署目录、命令与 YAML 的绝对路径和日志，复用全局 uv 管理 `.venv`；本项目不安装系统服务管理器。相对 CLI 路径以进程工作目录为准，长期服务建议使用绝对路径。

停止前通知调用方结束会话，使用 Ctrl+C 或 SIGTERM。备份前停止 Hub，复制 `hub.yaml` 和 `.runbridge/`，其中 SQLite 保存身份哈希、许可、会话及请求元数据。完整动作参数、上传与截图不保存在 SQLite，结果缓存在内存中。重启后原会话中断，调用方检查旧请求后明确创建新会话；不会自动重放。

升级与故障处理见[运行与排障](运行与排障.md)。源码构建和同机调试只在[开发文档](../development/本地开发与联调.md)中说明。
