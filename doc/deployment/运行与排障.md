# Hub 运行、排障与升级

适用于 0.7.0；安装与文件格式见[部署手册](部署与运行.md)和[配置参考](../reference/部署配置与凭据.md)。

| 现象 | 检查和处理 |
| --- | --- |
| YAML 读取或路径错误 | 相对路径以 YAML 所在目录为准，不展开 shell 变量；字段查[参数详解](../reference/参数详解.md)，使用 --settings 时不追加其他启动参数 |
| Node 无法访问 health | 实际地址、监听网卡、防火墙、代理和证书；不能交付 0.0.0.0 或服务器回环地址 |
| 登记 401 | Node 收到的单行文本是否就是 Hub 启动读取的真实文件，不能另生成一个秘密 |
| 调用 401/403 | 检查访问许可到期/撤销/节点和资源范围；身份令牌不能用于调用 |
| ONLINE 但不能执行 | Node 资源是否 READY/FREE、能力是否 stale、双方是否使用本次发布的 0.7.0 |
| 资源 BUSY/UNKNOWN | 查询会话和 cleanup；由 Node 所有者核查明确拥有的 worker/Profile，不能直接删除预留强行复用 |
| 旧 SDK 接口 410 | 已退役，按项目 HTTP/MCP 教程迁移，不能重试原生连接 |
| HTTP 202 或动作结果未知 | 保存 session_id/request_id，查询原请求并核对业务结果，不自动重新点击/提交 |
| RESULT_EXPIRED | 状态仍保留，完整结果已淘汰；不代表未执行 |
| MCP 404/421/403 | 检查启用选项、实际 Host/Origin 允许列表；不是浏览器连接地址问题 |
| 图片停留 | 检查查询 visual 状态/新鲜度和目标；超过 5 秒无有效新帧应撤图，不能继续展示 LIVE |

## 从 0.6.0 升级到 0.7.0

0.7.0 增加 Hub YAML 启动、完善上手文档；执行协议 2、工具 API 1、画面协议 1 与数据库 schema 4 不变。正常停止原实例后备份数据库、登记文件和启动配置，使用本部署环境的 uv 安装新 wheel，再按[参数详解](../reference/参数详解.md)保存 YAML。原 CLI 方式仍可使用；使用 `--settings` 时不追加其他启动参数。

保留原数据库和登记文件。YAML 的相对文件路径以 YAML 所在目录为准，迁移时确认实际仍指向原文件。未新增数据库迁移，不重建节点身份或访问许可。升级安装本身不启动服务；由操作者启动后验证 health、Node 状态与实际动作。

## 从 0.5.x 升级

0.6.0 阶段引入了执行协议的破坏性变更；从更早版本升级到当前 0.7.0，仍需要完成以下迁移，并统一两端发布版本。先停止接收新任务，让原调用方释放会话并确认业务结果，再正常停止原服务。不要将新版本连接到旧测试数据库作试验。

停止后备份 `.runbridge`、`hub.yaml` 和启动命令，用 uv 在本部署 `.venv` 安装发布者交付的新 wheel（需要 MCP 时保留 `[mcp]`）。原登记文件、节点长期身份和访问许可可以继续使用。SQLite 升至 schema 4，旧会话保留历史版本，未结束记录变为 INTERRUPTED/UNKNOWN；不恢复旧 SDK 对象、不重放命令。回滚需要停止新服务，恢复升级前数据库备份及匹配旧包，不能只降级包并继续使用新 schema。

删除启动命令中的 `--mcp-native-url`。Node YAML 与浏览器环境的迁移由 Node 所有者按其当前 0.7.0 手册完成。调用方改用项目 `/v2` 或 MCP，原 SDK 直连代码必须替换。复核 health、Node ONLINE/READY/FREE、一次业务读取和 cleanup，再投入使用。

## 数据与进程边界

Hub 只管理自身进程和数据库，浏览器由 Node 回收。备份在正常停止后进行；日志不应包含秘密。HTTP/MCP 成功只代表请求处理，不等于业务目标已写入，业务验证须读取最终记录。
