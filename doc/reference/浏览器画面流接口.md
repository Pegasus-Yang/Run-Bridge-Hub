# 浏览器画面流接口

[文档导航](../README.md) · [当前架构](../architecture/浏览器画面采集与分发.md) · [接入指南](../user-guide/浏览器画面流接入.md)
## 当前来源与版本

Node 0.8.1 的 managed 由 Node Python worker 对同一 Page 采集并上传；target_id 与动作 page_id 相同，约 300 毫秒一次，独立于动作队列。borrowed 使用 Node 的可选 Browscreen 扩展，并把内部 CDP target 映射为当前会话的 Page 引用。Hub 只分发，不持有 Playwright 或采集连接。

执行通过 HTTP 或 MCP 创建的会话均可按实际声明能力提供画面。会话在第一条动作后进入 ACTIVE，Node 上传此时可被接纳；MCP 启动会自动执行只读状态动作激活。画面格式版本仍为 1，与执行协议 2 分开。

上传 hello 新增 capture_backend，值 python-playwright 或 browscreen。前者报告实际 runtime_version，browscreen_version 必须 null；后者报告实际 Browscreen 版本 >=0.3.1,<0.4.0。PNG 截图动作最大 2 MiB，画面 wire 的上限仍为 4 MiB；managed 当前也限制为 2 MiB。无法采集时不宣称 LIVE。

## 查询入口

| 查询 | 画面字段 |
| --- | --- |
| GET `/v1/nodes/{node_id}` | `visual.supported` 与当前许可的 `visual.streams` |
| GET `/v1/nodes/{node_id}/capabilities` | 与节点查询相同 |
| GET `/v2/sessions/{session_id}` | 单个会话的 `visual` |

查询使用访问许可 Bearer；会话查询还要求 grant_id 与创建者相同。节点流列表只包含当前许可创建的活动会话，即使其他许可也允许访问同一资源，也不能读取该会话流。

`supported` 表示声明支持，不代表 LIVE；离线节点的历史能力快照须结合原有 `capabilities_stale` 判断。活动会话声明画面协议后即返回订阅路径，在等待首帧或等待选择期间也可订阅。未安装或未声明扩展、后端不支持、Node 离线、会话尚未激活或已经结束时，入口为空。节点没有当前许可的活动流时 `streams=[]`。

会话查询的画面字段示例：

```json
{
  "visual": {
    "supported": true,
    "state": "LIVE",
    "visual_protocol_version": 1,
    "transport": "websocket",
    "content_type": "image/png",
    "stream_path": "/v1/sessions/session_example/visual/stream",
    "target_id": "page_example",
    "targets": [{"target_id": "page_example", "label": "页面 1"}],
    "stream_id": "stream_example",
    "last_frame_id": 42,
    "capture_started_at": "2026-10-12T12:00:00Z",
    "frame_age_ms": 80,
    "reason_code": null,
    "selection": null
  }
}
```

数值仅为合同示例。节点查询 `streams` 每项在上述字段之外包含 session_id、resource_id。查询不包含 PNG、令牌、本机监听地址或 CDP 地址；画面字段只由当前内存状态生成，不写入持久化记录。

## 只读订阅

`WS /v1/sessions/{session_id}/visual/stream` 使用创建会话的有效访问许可。HTTP(S) Hub 基址转换为 WS(S)，保留既有部署路径前缀，再拼接查询返回的 stream_path。

支持自定义请求头的客户端在握手时提交 `Authorization: Bearer <access_token>`。浏览器调用方没有请求头入口时，在连接后 5 秒内发送首条认证消息：

```json
{"type":"auth","access_token":"<由调用方私有配置取得的访问令牌>"}
```

认证完成前不交付页面目录、状态或图片。令牌不放入 URL，接口拒绝查询参数。已提供错误请求头时不会降级到首消息认证。未获授权、不属于创建许可或会话不可订阅时拒绝连接；首消息模式已接受 WebSocket 后以 1008 关闭。

订阅先发送文本状态，若有新鲜缓存帧则发送该帧，再发送后续更新。文本消息为：

```json
{"type":"state","visual":{"supported":true,"state":"WAITING","stream_path":"/v1/sessions/session_example/visual/stream"}}
```

此处省略 VisualView 的其他字段。后续文本状态使用同一结构，含目标列表、选择进度、错误及新鲜度。订阅保持只读，认证后发送其他应用消息会关闭订阅。多名消费者共享同一画面源，不占用项目执行 caller。

二进制消息布局：

```text
4 字节大端无符号 JSON 长度 + UTF-8 JSON 元数据 + PNG 字节
```

元数据字段：visual_protocol_version、connection_generation、session_id、resource_id、stream_id、target_id、frame_id、capture_started_at、content_type。单帧 JSON 最大 4096 字节，PNG 最大 4 MiB；content_type 固定 image/png。二进制消息整体不是裸 PNG，不能直接作为图片解码；须先移除长度和 JSON 部分。

同一流的 frame_id 必须递增，新采集实例或目标切换更换 stream_id 后可从 1 开始。消费者应识别状态和来源，忽略旧目标/旧流的在途数据；允许丢弃中间帧，不提供历史回放。结束、撤销或过期时停止新帧并关闭订阅。

## 目标选择

`PUT /v1/sessions/{session_id}/visual/target` 使用同一访问许可，请求体只有目标 ID：

```json
{"target_id":"page_example"}
```

目标来自查询或数据流中的 `targets`，标签为“页面 1”等，不包含真实标题、URL 或调试地址。202 响应返回 request_id、target_id、state、error_code；受理时设为 PENDING，响应和后续流状态、查询中的 `selection` 返回实际进度。首个有效新帧确认 APPLIED；失败返回 FAILED 和原因。该接口不激活或操作页面，不改变浏览器实例授权。

## 状态与常用错误

| 状态 | 含义 |
| --- | --- |
| UNAVAILABLE | 未声明扩展、后端不支持或 Node 不可用 |
| WAITING | 会话未激活、上传待接入、没有页面或首帧生成中 |
| WAITING_TARGET | 多页面需选择，或已选页关闭 |
| LIVE | 有已接收的新鲜帧 |
| STALE | 超过 5 秒没有新帧，旧图已撤下 |
| ERROR | 采集、上传或选择失败 |
| STOPPED | 会话已结束或正在关闭，入口为空 |

| 错误/条件 | 行为 |
| --- | --- |
| INVALID_ACCESS_TOKEN / SESSION_OUTSIDE_GRANT | 401/403；认证失败或非创建许可 |
| SESSION_NOT_ACTIVE / 已结束 | 尚未激活的订阅返回 409，结束后返回 410 |
| UNSUPPORTED_BACKEND / EXTENSION_NOT_ADVERTISED | 查询返回原因和空入口，执行功能保持原行为 |
| VISUAL_UPLOAD_NOT_READY / TARGET_SELECTION_PENDING | 409；上传尚未就绪或前一选择未完成 |
| VISUAL_TARGET_NOT_FOUND | 404；目标不在当前目录 |
| TARGET_SELECTION_TIMEOUT | 选择超过 10 秒未产出新图，失败并丢弃迟到确认 |
| FRAME_STALE / TARGET_CLOSED | 清空旧图并更新状态 |
| FRAME_TOO_LARGE / CAPTURE_FAILED / BROWSER_WAIT_TIMEOUT | 采集端通过状态报告；不自动调整视口 |
| STALE_SESSION / INVALID_GENERATION | 上传身份、连接代次或会话不匹配，拒绝连接 |
| INVALID_VISUAL_MESSAGE | 上传帧或状态不符合合同，1008 关闭画面上传，原执行不受该错误影响 |

## Node 内部上传

GET `/v1/nodes/{node_id}/visual/support` 仅供 Node 身份探测，返回 visual_protocol_version、header_max_bytes、png_max_bytes。

WS `/v1/nodes/{node_id}/sessions/{session_id}/visual/upload` 使用 Node 身份 Bearer 和 `x-runbridge-generation`，仅允许当前 ACTIVE 会话。首条消息在 5 秒内声明 `type=hello`、visual_protocol_version=1、capture_backend，并按来源报告实际 runtime_version 或 browscreen_version；其后上传 `targets`、`state` 文本与二进制帧。采集端只能声明 WAITING、WAITING_TARGET 或 ERROR，LIVE 由 Hub 实际收帧确认。

Hub 接受 `browscreen>=0.3.1,<0.4.0`，按 Python 分发版本规则排除预发布版。0.3.1、0.3.2、0.3.10 等正式版本符合范围，0.3.0、0.4.0 和 0.3.2rc1 不符合；无效版本以 INVALID_VISUAL_MESSAGE 关闭画面上传，原执行继续。0.3.1 是目前实机验收版本，后续版本的范围接受不等于已完成实机验收。握手示例中的版本应按 Node 实际安装值填写：

```json
{
  "type": "hello",
  "visual_protocol_version": 1,
  "capture_backend": "browscreen",
  "runtime_version": null,
  "browscreen_version": "0.3.1"
}
```

managed 握手使用 `capture_backend=python-playwright`、实际 `runtime_version` 和 `browscreen_version=null`。Hub 通过该连接向 Node 发送 select_target 请求。该通道不接受任意 CDP、鼠标、键盘或导航命令。执行和控制使用协议 2，不能把历史 SDK 隧道消息发到这些连接。

查询响应新增字段需要旧的严格解析器升级为 NodeQueryView/SessionQueryView 或对应扩展模型；新模型允许 visual 缺省以查询旧 Hub。创建和释放响应仍为基础 SessionView。
