# 跨机器部署与中文字体

[文档导航](../README.md) · [安装方式](安装与运行.md) · [首次登记](../user-guide/快速开始.md) · [虚拟机实测](../project/虚拟机Node跨机器验收记录.md)

本指南将 Hub 与 Node 放在不同机器，说明地址、安装、凭据交付及中文字库。已有实测组合是 macOS Hub + Ubuntu 26.04 ARM64 Node + 明确授权的 Chromium CDP；其他系统、生产 TLS/代理与容量仍须在目标环境验证。

## 1. 区分三种地址

| 地址 | 谁访问 | 例子与注意点 |
| --- | --- | --- |
| Hub 的 HTTP(S) 基址 | Node 与调用方 | 可达网桥/局域网地址或 HTTPS 域名；他们可以使用不同网络，但访问文件中的基址必须对调用方可达 |
| Chrome CDP 地址 | Node 本机 | 固定 ws://127.0.0.1:端口/devtools/browser/ID，不暴露到外网 |
| 被测试应用地址 | Node 上的浏览器 | Node 网络可达的业务地址；调用方本机 localhost 指向调用方，不是 Node |

Node 主动建立 control、tunnel 和可选 upload，通常不需要向外开放 Node 监听端口。Hub 则需要接收 HTTP 与 WebSocket；浏览器原生入口和画面入口均在这个 Hub 地址下。

## 2. 在宿主机监听可达地址

以下是独立测试部署的示例，192.168.20.1 是本次宿主机网桥地址，不是所有机器都固定的默认值。先确认目标网卡和端口，再在 Hub 源码根目录运行：

```bash
uv run --locked --no-sync runbridge-hub serve --host 192.168.20.1 --port 8787 --db-path .runbridge/hub.sqlite3 --enrollment-token-file .runbridge/enrollment.token
```

127.0.0.1 只允许本机连接；也可按部署环境选择监听所有网卡的 0.0.0.0，但客户端应填写实际可达 IP/域名，不能把 0.0.0.0 当访问地址。不要把已有测试服务的固定端口复制成另一个部署，端口冲突时选独立端口和数据目录。

在 Node 虚拟机检查：

```bash
curl --noproxy '*' --fail http://192.168.20.1:8787/health
```

返回 status=ok 后再做登记。失败时依次检查 Hub 进程/监听 → 网桥路由与地址 → 防火墙 → 代理，不把节点身份重建当作网络修复。

## 3. 将 Node 安装到虚拟机

本例 SSH 为 pegasus@192.168.20.129，替换为自己的主机。先在本机 Node 项目构建 wheel，再复制：

```bash
uv build -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
ssh pegasus@192.168.20.129 'mkdir -p ~/runbridge-node-deploy'
scp dist/runbridge_node-0.4.0-py3-none-any.whl pegasus@192.168.20.129:~/runbridge-node-deploy/
```

登录虚拟机，在该部署目录使用已安装的 uv：

```bash
cd ~/runbridge-node-deploy
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python './runbridge_node-0.4.0-py3-none-any.whl[visual]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/runbridge-node --help
```

不需要画面时安装不带 [visual] 的 wheel。Chrome 借用模式不要求 Node.js/npm，但需要本机已经存在、依赖完整、由所有者授权的浏览器入口；系统没有浏览器时先由所有者准备，Node 不负责安装或自动接管。

## 4. 交付登记文件，登记并启用浏览器

从 Hub 的实际登记文件安全复制到虚拟机私有配置目录，例如 .runbridge/enrollment.token，并限制读取权限。不要把正文令牌粘贴到 SSH 命令行、仓库或文档。

在虚拟机部署目录：

```bash
.venv/bin/runbridge-node register --hub-url http://192.168.20.1:8787 --enrollment-token-file .runbridge/enrollment.token --config .runbridge/node.json --name vm-node
```

随后按[Chrome 指南](../user-guide/Chrome复用快速开始.md)保存本机 chrome.json 并启动：

```bash
.venv/bin/runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

--chrome-config 内仍是虚拟机自己的回环端点。浏览器 URL 中的 localhost 也指虚拟机自己，不指宿主机或调用方。

另一个虚拟机终端签发许可：

```bash
.venv/bin/runbridge-node grant --config .runbridge/node.json --resource-id chrome --expires-in 3600 --output .runbridge/chrome-access.json
```

若本机配置 resource_id=vm-chrome，就将该值用于 grant 和所有后续调用。将访问文件交付给调用方，再按[调用方指南](../user-guide/调用方对接与使用.md)进行查询与官方 SDK 连接。

许可文件中的 hub_url 来自 Node 登记地址，必须对调用方也可达；必要时调用方选择指向同一个 Hub 的可达基址，不能改变身份或混用另一个 Hub。已有身份保存了自己的 Hub URL，不应随意把 node.json 改成另一个部署。

## 5. 代理、TLS 与长连接

Node 控制与对外原生连接使用库标准代理/证书行为；Node 本机 CDP、画面合同探测和回环取图采用直接连接。机器曾配置旧代理时，HTTP/WS 网络表现可能不同，应检查实际配置而不是关闭证书验证。

临时局域网联调可对本次 Node 命令指定绕过本地地址，保持其他配置：

```bash
NO_PROXY=192.168.20.1,127.0.0.1,localhost no_proxy=192.168.20.1,127.0.0.1,localhost .venv/bin/runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

这只作用于本次进程，地址替换为实际值。安装器/APT 还可能有各自独立代理配置，NO_PROXY 不一定覆盖它们。下载不可达时可在可联网机器下载、校验 wheel/字体包后通过 SSH 传入，不修改全局代理作为默认方案。

生产提供可信 HTTPS/WSS；Hub CLI 本身不提供证书参数，TLS 终止由部署设施负责。反向代理要转发 Authorization、User-Agent、x-playwright-*、WS Upgrade，并让连接超时覆盖心跳/执行租期；路径前缀应一致映射到原 Hub 路由。生产反向代理、TLS 与长时容量尚未由局域网测试得到验证结论。

## 6. 在 Ubuntu 补齐中文字体

中文显示取决于 **浏览器所在的 Node 机器**。DOM UTF-8 正确但截图出现方框时，先查字库：

```bash
fc-list :lang=zh family
fc-match 'sans-serif:lang=zh-cn'
```

第一条为空说明没有匹配中文字库；第二条可能退到 DejaVu 等不覆盖汉字的字体。字体安装后需要刷新缓存，并由所有者在会话结束后重启测试浏览器，让旧进程的字体缓存更新。

### 有管理员权限：系统字体

在 Ubuntu 上：

```bash
sudo apt-get update
sudo apt-get install fonts-noto-cjk
fc-cache -f
```

这是系统级安装；与本次实际采用的 pegasus 用户级安装不同。没有 sudo 时不要阻塞在密码请求，使用下一种方式。

### 无管理员权限：用户字体

在 Node 部署/源码根目录下载字体包到专用目录：

```bash
mkdir -p .runbridge/font-package
cd .runbridge/font-package
apt-get download fonts-noto-cjk
cd ../..
```

只在包成功取得后执行解包。下载遇到旧 APT 代理时可对本次命令使用 -o Acquire::http::Proxy=DIRECT -o Acquire::https::Proxy=DIRECT；直连仍不可达时，从可联网机器下载该发行版的官方包，核对 APT 元数据的 SHA-256 后传入这个目录。本次实际包版本、源和摘要见[字体核验](../reference/虚拟机中文字体核验记录.json)，不把该固定版本当作所有发行版的默认候选。

下面的标准库脚本在 Node 根目录运行；wheel 环境使用 .venv/bin/python，源码使用 uv run --locked --no-sync python：

```bash
.venv/bin/python - <<'PYCODE'
import shutil
import subprocess
from pathlib import Path

root = Path(".runbridge/font-package")
packages = list(root.glob("fonts-noto-cjk_*.deb"))
if len(packages) != 1:
    raise RuntimeError("请提供一份已校验的 fonts-noto-cjk 包")
extracted = root / "extracted"
subprocess.run(["dpkg-deb", "--extract", str(packages[0]), str(extracted)], check=True)
fonts = Path.home() / ".local/share/fonts/noto-cjk"
fonts.mkdir(parents=True, exist_ok=True)
for source in (extracted / "usr/share/fonts/opentype/noto").glob("*.ttc"):
    target = fonts / source.name
    if target.exists() and target.read_bytes() != source.read_bytes():
        raise RuntimeError("已有同名字体不同，请先核对")
    shutil.copy2(src=source, dst=target)
shutil.copy2(src=extracted / "usr/share/doc/fonts-noto-cjk/copyright", dst=fonts / "copyright")
config = Path.home() / ".config/fontconfig/conf.d/70-fonts-noto-cjk.conf"
config.parent.mkdir(parents=True, exist_ok=True)
source = extracted / "usr/share/fontconfig/conf.avail/70-fonts-noto-cjk.conf"
if config.exists() and config.read_bytes() != source.read_bytes():
    raise RuntimeError("已有字体配置不同，请先核对")
shutil.copy2(src=source, dst=config)
subprocess.run(["fc-cache", "--force", str(fonts)], check=True)
subprocess.run(["fc-match", "sans-serif:lang=zh-cn"], check=True)
PYCODE
```

用户字体仅对运行浏览器的这个用户生效。包内语言匹配规则让 zh-CN、zh-TW 分别匹配 SC、TC 字形；没有声明页面语言时可能用同字体集合的其他区域字形，不能据名称含 JP 判断仍缺汉字。

浏览器重启后 CDP 浏览器 ID 会变化，所有者重新确认本机端点并用新配置重启 Node，保留 node.json 和 Profile。完成后验证简体/繁体实际截图，再通过 Node → Hub 订阅 PNG；fc-list 非空或 DOM 文本正确都不能单独证明浏览器已经使用新字体。

## 7. 验收与保留服务

按顺序检查 Hub health → Node ONLINE → 资源 READY/FREE → SDK 会话 ACTIVE → 独立消费者解码 PNG → 正常释放 COMPLETE → streams=[]。确认浏览器/登录保留的含义与模式一致。

本次已保留的具体测试地址、安装目录、停止脚本与核验证据在[虚拟机验收记录](../project/虚拟机Node跨机器验收记录.md)，其中运行状态是当次快照、访问许可有期限。指南中的 8787 是新部署示例，不是本次保留测试服务的实际端口。是否保留测试服务由部署者决定，正常结束会话仍会停止画面采集。
