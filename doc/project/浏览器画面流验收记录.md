# 浏览器画面流验收记录

[文档导航](../README.md) · [当前架构](../architecture/浏览器画面采集与分发.md) · [接口合同](../reference/浏览器画面流接口.md) · [安装与接入](../user-guide/浏览器画面流接入.md)

验收日期：2026-10-13（Asia/Shanghai），Hub/Node 版本 0.4.0。实施范围为已确认的 Browscreen 可选扩展：仅在授权执行会话期间上传，Hub 提供数据流，并在原有查询中返回入口。Browscreen 项目源码无需修改。

下方实现结果及 JSON 记录保留首轮 0.3.1 的验收快照；后续依赖范围调整见本文末尾。

## 实现结果

- Node 的 `visual` extra 固定 Browscreen 0.3.1；基础安装不引入 Browscreen、FastAPI 或 Pillow，缺包、版本不兼容或导入失败时禁用扩展。
- 只有 Chrome CDP 会话进入 ACTIVE 才启动采集；单页自动选择，多页等待明确选择，关闭所选页后不会自动改截另一页。
- 独立采集进程、上传连接和订阅连接；Hub 每个会话只缓存最新帧，每个消费者仅保留一个待发更新。状态与 PNG 从查询返回的 stream_path 对外提供，Hub 没有展示页面。
- 画面权限沿用创建会话的许可；控制代次、会话、资源、目标和帧编号均核验。终止、撤销、过期或失联时撤下缓存并结束数据流。
- 原生执行与画面关闭并行，等待画面清理不会延迟调用方收到断开。正常释放只清理自有观察资源，保留借用 Chrome 和登录；强杀后的整体状态仍按证据报告 UNKNOWN。

## 验证结果

完整 pytest 回归：Hub **36 项**、Node **39 项**，共 **75 项**通过，零失败、零跳过。其中新增画面验证为 Hub 14 项、Node 7 项；Node 本轮完整运行耗时 103.84 秒。Hub 有一条已有的 Starlette/httpx TestClient 弃用提示，不影响结果。

| 验证层次 | 实际证据 |
| --- | --- |
| Hub 合同与状态测试 | 查询发现、不同许可过滤、两种订阅认证、多订阅者、错误帧归属、非法包隔离、选择与超时、同流重连编号下限、过期帧撤下、有界队列、许可撤销、控制代次替换、原生断开不等待画面清理 |
| Node 真实浏览器测试 | 由查询路径订阅；官方 SDK 保留原登录并提交业务输入；独立 Pillow 解码颜色变化、目标 ID 和递增帧；多页选择与关闭页行为；采集父进程强杀后目录及监听消失，外部 Chrome 存活 |
| 基础/extra 独立安装 | 基础 wheel 的可选库和画面探测均为 False；extra wheel 安装后探测为 True。人为提供兼容分发元数据但缺失模块，隔离导入失败时返回 False |

运行版本为 macOS arm64、Python 3.14.7、Google Chrome 154.0.8037.99、Playwright 1.63.0、Browscreen 0.3.1、Pillow 12.3.0。Node/Hub 分别使用自己的项目 `.venv`；真实 Chrome 由测试所有者以隔离 Profile 启动，不连接日常浏览器。运行事实和源码摘要见[运行核验记录](../reference/画面流运行核验记录.json)，安装包摘要见[构建核验记录](../reference/画面流构建产物核验记录.json)，文档静态核对见[文档核验记录](../reference/画面流文档核验记录.json)。

## 本机测量与限制

一轮带测量的真实场景，PNG 为 756×469，实际收到 3 帧，大小 11,408–11,520 字节；三个匹配目标和像素的递增帧编号为 1、2、3，允许丢弃中间帧。订阅建立后首个匹配颜色的帧耗时 0.501 秒，完成三帧观察耗时 1.042 秒，接收间隔为 0.303、0.302 秒。

从 SDK 发起页面改色请求，到独立消费者解码出匹配像素耗时 0.233 秒，两端观察使用同一测试进程的单调时钟。这些数值是同机短场景结果，包含执行请求、截图、上传、订阅、解码和测量开销；不是从会话激活开始的冷启动时延、远程部署延迟或固定帧率承诺。

首个解包帧时读取 `ps` 的服务进程快照：

| 进程 | CPU % | RSS KiB |
| --- | ---: | ---: |
| Hub | 3.1 | 64,096 |
| Node | 4.6 | 57,200 |
| Browscreen 采集进程 | 43.2 | 67,664 |

CPU 为 `ps` 报告的进程平均使用值，RSS 为当次快照；采集刚启动时读取，不含 Chrome 和测试 SDK，也不是稳态均值、峰值或容量基准。连续 PNG 的实际成本随页面、视口、网络和观看人数变化；100 用户/10 并发、真实慢网络、远程 TLS/代理、锁屏及 Windows 未在本轮专项验收。后续已完成 Ubuntu 26.04 ARM64 虚拟机 Node 的跨机器测试，具体版本、部署状态和系统字体限制见[虚拟机验收记录](虚拟机Node跨机器验收记录.md)。

完整回归曾暴露画面关闭串行等待导致原生中断延迟，已并行关闭并用可控等待测试及 Node 强杀场景确认修复。另有 Chrome 测试冷启动在 11.446 秒才生成调试端点，超过原 10 秒等待；仅将测试所有者的启动等待改为 20 秒，保留进程退出和真实端点检查，最终完整回归通过。产品超时参数未因此调整。另补齐采集恢复后再次发生相同错误的回归：成功出图时恢复源状态基线，下一次相同错误仍通知 Hub 并清空旧图。

严格解析旧 NodeView/SessionView 的查询客户端需要同步升级为扩展查询模型；新模型允许 visual 缺省。创建、释放和持久化会话合同保持原样。画面不包含音频、录制、回放或远程输入，业务正确性仍由实际页面和业务状态独立判断。

## Browscreen 版本范围调整（2026-10-13）

- Node 的 `visual` extra 改为 `browscreen>=0.3.1,<0.4.0`，包含 0.3.1，排除 0.4.0 和预发布版。Node 探测、隔离进程加载与 Hub 上传握手采用同一范围；Node 上报实际安装版本。两端使用基础依赖 `packaging` 比较分发版本，基础 Node 仍不引入 Browscreen、FastAPI 或 Pillow。
- uv.lock 保留已实测的 Browscreen 0.3.1；放宽包依赖不会使源码的 `--locked` 安装自动升级。后续更新步骤和 Hub/Node 升级顺序见[安装与运行](../deployment/安装与运行.md)。
- 本轮验证：Hub 全量 56 项、Node 画面相关单元回归 14 项、真实 Chrome 采集回归 1 项，共 71 项通过。范围内握手可上传并向消费者分发帧；越界或预发布握手以 1008 关闭画面通道，原生执行仍能传输。真实采集使用安装的 0.3.1，完成像素解码与页面对应检查。
- 0.3.2、0.3.10 等后续版本使用模拟安装元数据或握手声明验证版本规则，未安装对应库进行采集实测。文内前述安装版本、运行及构建 JSON 保留首轮快照；本轮重建的 0.4.0 安装包包含新的范围声明。保留的跨机器联调服务没有在本轮重新部署或重启，真实回归使用独立临时 Hub、Node 和 Chrome。
