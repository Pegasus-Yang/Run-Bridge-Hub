# 安装与运行

[文档导航](../README.md) · [首次登记与连通](../user-guide/快速开始.md) · [跨机器部署](跨机器部署与中文字体.md)

本指南对应 0.4.0，面向安装和维护人员。Hub、Node、调用方是三个角色；可以放在同一机器的不同目录，也可以分别部署。下文的 shell 命令面向 macOS/Linux；没有经过 Windows 部署验收。

## 1. 先确定在哪台机器装什么

| 位置 | 必需项 | 按模式增加的依赖 |
| --- | --- | --- |
| Hub 服务端 | uv、标准 CPython 3.14.x、runbridge-hub、可写 SQLite 目录 | 默认无需浏览器 SDK；可选 MCP 模式安装 `mcp` extra，仍无需 Hub 本机 Chrome/Chromium 或 Browscreen |
| Node 所有者机器 | uv、标准 CPython 3.14.x、runbridge-node | 已有 Chrome 模式：所有者授权的本机浏览器级 CDP 入口；受管理模式：Node.js >=20、npm、私有 Playwright/Chromium 运行时 |
| Node 可选画面采集 | 上述 Node 环境 | visual extra，安装 `browscreen>=0.3.1,<0.4.0`；当前仅用于已有 Chrome |
| 调用方机器或服务 | HTTP 客户端、访问许可 | 浏览器操作使用官方 Playwright SDK；画面订阅使用 WebSocket 客户端 |
| MCP Agent 客户端 | 支持 Streamable HTTP 和 Bearer 请求头的 MCP 客户端、访问许可 | 无需安装 Playwright；浏览器操作由 Hub 的 SDK 发起 |

项目要求 Python >=3.14,<3.15。Hub/Node 各有自己的环境和锁文件；互相不安装对方作为内部包依赖。源码 Node 的开发依赖含 Playwright 1.63.0，生产 wheel 不自动安装调用方 SDK。当前已验证 macOS arm64 与特定 Ubuntu 26.04 ARM64 的借用 Chrome 组合，具体版本见[验收记录](../project/虚拟机Node跨机器验收记录.md)。

先检查工具：

```bash
uv --version
```

没有 uv 时按[官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)安装；Python 可由 uv 在创建环境时准备。不要把第三方日常项目的虚拟环境用于 RunBridge。

## 2A. 从源码安装

以下命令分别在 runbridge-hub、runbridge-node 项目根目录执行，会使用各自 .venv 和 uv.lock：

```bash
uv sync --locked --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

这是开发/联调方式，默认安装开发依赖。生产源码安装可增加 --no-dev。需要 Chrome 画面时，只在 Node 根目录使用：

```bash
uv sync --locked --extra visual --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

需要 Agent MCP 工具时，在 **Hub** 根目录使用 `uv sync --locked --extra mcp --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com`，启动时增加 `--enable-mcp`。完整参数、Host/Origin 配置和客户端授权见 [MCP 浏览器接入](../user-guide/MCP浏览器接入.md)。浏览器继续运行在 Node，不需要在 Hub 执行 `playwright install`。

版本范围包含 0.3.1，接受后续正式 0.3.x，排除 0.4.0 和预发布版。uv.lock 仍记录本次实际解析的 0.3.1，用于复现环境；范围声明不会让 `--locked` 自动升级扩展。新版本发布后，需要更新源码锁文件时，在 Node 根目录执行：

```bash
uv lock --upgrade-package browscreen -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv sync --locked --extra visual --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

升级 Browscreen 前先部署支持上述范围的 Hub 和 Node，再正常重启 Node。早先仅接受 0.3.1 的 Hub 会拒绝其他版本的画面握手。范围内版本仍需通过隔离导入探测；已有实机验收使用 0.3.1，不代表所有后续版本都已实测。

安装 extra 后，运行服务使用 uv run --locked --no-sync，或在重新同步时继续指定 --extra visual；普通不带 extra 的同步可能移除可选依赖。[uv 同步行为](https://docs.astral.sh/uv/concepts/projects/sync/)

后续源码命令统一采用：

```bash
uv run --locked --no-sync runbridge-hub --help
```

Node 项目用 runbridge-node。--locked 检查锁定约束；--no-sync 直接使用已准备的环境，不在启动服务时调整依赖。

## 2B. 从已有 wheel 安装

适合部署机器没有完整源码的情况。使用实际构建产物路径；下文不假定 RunBridge 0.4.0 已发布到公共 PyPI。先在各自源码根目录构建：

```bash
uv build -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

分别得到 dist/runbridge_hub-0.4.0-py3-none-any.whl 和 dist/runbridge_node-0.4.0-py3-none-any.whl。将产物传到目标机器，为 Hub、Node 各选一个独立部署目录。

在 Hub 部署目录：

```bash
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python /absolute/path/runbridge_hub-0.4.0-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/runbridge-hub --help
```

在 Node 部署目录（二选一，不必重复安装）：

```bash
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python /absolute/path/runbridge_node-0.4.0-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

需要画面的 Node 改用带 extra 的包路径：

```bash
uv pip install --python .venv/bin/python '/absolute/path/runbridge_node-0.4.0-py3-none-any.whl[visual]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/runbridge-node --help
```

wheel 部署目录没有项目 uv.lock，后续通过 .venv/bin/runbridge-hub、.venv/bin/runbridge-node 运行；不要照搬源码方式的 --locked。依赖仍用 uv 管理。完整示例脚本和指南从源码或 sdist 的 doc 目录取得。[uv 包安装](https://docs.astral.sh/uv/pip/packages/)

wheel 安装默认按包内依赖范围解析，不自动应用源码 uv.lock；固定 wheel 版本不等于所有依赖都固定。需要复现源码验收依赖时，在相应源码根目录导出部署约束，并随产物交付：

```bash
uv export --locked --no-dev --no-emit-project --no-hashes --format requirements-txt --output-file deploy-constraints.txt
```

启用画面的 Node 导出时增加 --extra visual。部署机器在前面的 uv pip install 命令中增加 --constraint /absolute/path/deploy-constraints.txt；wheel 本身仍作为安装目标。调用方 SDK 和 npm 浏览器运行时分别按本指南/对应模式准备，不混入 Hub 的依赖。

## 3. 启动与配置 Hub

源码根目录首次生成登记凭据并启动：

```bash
uv run --locked --no-sync runbridge-hub generate-token --output .runbridge/enrollment.token
uv run --locked --no-sync runbridge-hub serve --host 127.0.0.1 --port 8787 --db-path .runbridge/hub.sqlite3 --enrollment-token-file .runbridge/enrollment.token
```

文件已经存在时跳过生成；命令拒绝覆盖。wheel 部署将 uv run --locked --no-sync runbridge-hub 换成 .venv/bin/runbridge-hub。保持当前终端运行，另一个终端执行 curl http://127.0.0.1:8787/health，预期返回 status=ok。

| 参数 | 默认值 | 用法 |
| --- | --- | --- |
| --host | 127.0.0.1 | 本机联调使用回环；远程 Node 必须连接可达的监听地址 |
| --port | 8787 | HTTP 与 WebSocket 共用端口 |
| --db-path | .runbridge/hub.sqlite3 | 相对启动命令当前目录；生产可指定固定绝对路径 |
| --enrollment-token-file | 无 | 私有登记文件；提供时优先于环境变量 |
| RUNBRIDGE_ENROLLMENT_TOKEN | 无 | 不提供文件时的备用来源，32–256 字符 |
| --heartbeat-interval | 30 秒 | Hub 告诉 Node 的心跳间隔 |
| --heartbeat-timeout | 90 秒 | 必须大于间隔，决定何时判定控制连接失联 |

CLI 固定一个 ASGI Worker 和 asyncio；当前活连接、预约和画面位于该进程内存。增加 Worker 或多个 Hub 实例不能直接共享现有路由，属于另行设计范围。

## 4. 准备并启动 Node

先按[首次连通](../user-guide/快速开始.md)登记身份，然后按任务选择一种模式：

| 模式 | 源码启动命令 | 就绪判断 |
| --- | --- | --- |
| 仅登记/查询联调 | uv run --locked --no-sync runbridge-node run --config .runbridge/node.json | ONLINE；没有可执行浏览器资源 |
| 已有 Chrome | 同上增加 --chrome-config .runbridge/chrome.json | chrome-cdp，BORROWED_CHROME_CDP，READY/FREE |
| 受管理 Chromium | 同上增加 --playwright-config .runbridge/playwright.json | playwright，MANAGED_CHROMIUM，READY/FREE |

--chrome-config 和 --playwright-config 互斥。所有相对文件路径按当前工作目录解析；日常运行固定在同一目录。身份、授权和配置不能用文件存在与否替代真实就绪检查。

| 常用 Node 命令 | 目的 |
| --- | --- |
| register --hub-url ... --enrollment-token-file ... --config ... | 首次登记或同一身份重试 |
| grant --config ... --resource-id ... --expires-in ... --output ... | 由所有者签发调用许可；可重复 --resource-id |
| revoke grant_example --config ... | 撤销指定调用许可 |
| inspect node_example --access-file ... | 使用调用许可查询节点与资源 |
| session create/get/close --access-file ... | 调用方管理执行会话 |
| prepare-playwright --runtime-dir ... --node-executable ... | 仅受管理模式安装私有 npm/Chromium 运行时 |

register/run/grant/revoke 的 --config 默认 .runbridge/node.json。grant 不带资源范围时允许该节点可见资源，不带期限时许可无到期时间；指南示例显式使用资源与 3600 秒期限。签发期限上限为一年，会话租期另有 1–3600 秒限制。

## 5. 凭据、文件与正常停止

| 文件 | 持有者 | 是否交给调用方 |
| --- | --- | --- |
| enrollment.token | Hub 部署者、首次登记的 Node 所有者 | 不交付 |
| node.json | Node 所有者，含稳定 node_id/node_token | 不交付 |
| chrome.json / playwright.json | Node 所有者的浏览器端点或启动设置 | 不交付 |
| access.json | 一个调用许可，含 hub_url/node_id/grant_id/access_token/expires_at | 交给获授权调用方 |
| hub.sqlite3 | Hub 部署者，存节点、许可与会话元数据 | 不交付 |

凭据文件在 POSIX 上以私有权限生成；例子不显示令牌原值。创建命令拒绝覆盖已有身份或访问文件。不要复制 node.json 启动两个同身份的常驻 Node，后接入会替换旧连接。撤销 access.json 对应的许可不注销 Node，也不撤回已经产生的业务动作。

先结束调用方执行并检查 cleanup，再正常停止 Node，最后按需要停止 Hub。Node/Hub 所在终端可用 Ctrl+C 正常结束；长期部署由自己的进程管理设施保留工作目录、环境和日志。

Chrome 借用模式停止的是连接与采集进程，用户浏览器保留；受管理模式还要回收 Node 自建浏览器。强杀或失联时不能根据画面消失推断清理已确认。运行、恢复与清理异常见[排障](Playwright运行与排障.md)。

## 6. 备份、升级与验证

保留 Node 身份及 Hub SQLite，不能通过删除身份修复临时网络故障。备份数据库时先正常停止 Hub，或使用 SQLite 一致性备份；活跃 WAL 模式下不能只随意复制主数据库文件。数据库模型为 v2，v1 自动增加会话表；旧 0.1.0 程序不能直接回退读取 v2。

升级后确认两端版本、能力就绪和调用方查询模型；0.4.0 查询增加可选 visual，旧的严格字段模型需要升级。重启 Hub 不恢复旧 SDK Browser/Context/Page 对象；重新建立节点连接后申请新会话，先核对上次业务效果。

源码开发环境可以执行：

```bash
uv run --locked --no-sync pytest -q
```

Python 包不包含 browser cache 或 node_modules。受管理模式安装 wheel 后仍需 prepare-playwright；visual extra 不包含音频、录制或输入控制。当前实施/验证边界见[画面流验收](../project/浏览器画面流验收记录.md)及[虚拟机实测](../project/虚拟机Node跨机器验收记录.md)。
