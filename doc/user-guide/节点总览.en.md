# Node dashboard

[简体中文](节点总览.md) · English

Applies to **Hub 0.9.2 / Node 0.8.1**. The read-only `/dashboard` page is enabled by default on Hub's existing listener, e.g. `http://127.0.0.1:8787/dashboard` locally. Its HTML, CSS, JS, and icons are included in the wheel, without an extra port, Node.js, frontend build, browser runtime, or CDN dependency. UI labels remain Chinese.

The page reads real Hub connections, Node capabilities, and Hub reservations. It offers no allocation, execution, disconnect, or authorization actions. Blue identifies primary navigation/selection; green online/healthy, amber occupied/preparing, red errors, and gray offline states also have text labels.

## Startup and token

Start normally:

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

Startup logs print the read-only token and direct-entry link. Illustrative token only:

```text
Dashboard 只读口令：example-readonly-token-0123456789abcdef
Dashboard URL：http://127.0.0.1:8787/dashboard?token=example-readonly-token-0123456789abcdef
```

Open the logged URL to enter directly; the `token` query remains for refresh/bookmarking. Special characters are URL-encoded by the CLI. Wildcard binding (`0.0.0.0` / `::`) logs a loopback URL; replace the host for remote access. The actual bound port is used, including a system-assigned port for `port: 0`.

If no token is configured, Hub initially creates/reuses `web.token` **beside the database**, mode 600; the default is `.runbridge/web.token`. Alternatively open `/dashboard` without a query and enter the plain single-line token manually, without quotes or Bearer.

The token can view host/capability/connection information for all Nodes. The page keeps it in memory and sends Bearer API requests rather than cookies/browser storage; a supplied URL query retains it too. **退出** (Sign out) or invalid authentication clears the URL token and returns to login. Enrollment, device identity, claim, and lease tokens cannot replace it.

For a predefined separate file:

```bash
.venv/bin/runbridge-hub generate-token --output .runbridge/dashboard.token
```

Add to `hub.yaml`:

```yaml
enrollment_token_file: .runbridge/enrollment.token
web_token_file: .runbridge/dashboard.token
```

Relative paths use the YAML directory. Precedence: explicit file → `RUNBRIDGE_WEB_TOKEN` → generated/reused database-side file. Missing/empty explicit files or token lengths outside 32–256 fail without fallback. Keep enrollment, claim, and read-only secrets distinct. Restart after replacing a token; the old token then fails.

## Disable the dashboard

Add to YAML:

```yaml
web_enabled: false
```

Without YAML:

```bash
.venv/bin/runbridge-hub serve --enrollment-token-file .runbridge/enrollment.token --disable-web
```

This makes `/dashboard`, its assets, and `/dashboard/api/nodes` return 404, without reading/generating/logging a dashboard token. Node/HTTP/MCP behavior remains. Do not combine `--settings` with other startup options.

## Connections, resources, and capabilities

The page refreshes every five seconds and supports connection-state filters and search by name, ID, hostname, OS, and architecture. Summary counts cover all nodes regardless of filter. Polling pauses while backgrounded and resumes immediately on return. Open a node for host, versions, generation, heartbeat, resource state, methods, and backend coverage.

| Field | Meaning |
| --- | --- |
| Online | Current control connection is valid, within heartbeat timeout, and has its current capability snapshot |
| Preparing | Current connection exists but is waiting for fresh capabilities; old snapshots are historical |
| Offline | No current connection or heartbeat expired; retained registration and capability history |
| Available resources | Online, READY, FREE, and not reserved by Hub |
| Occupied resources | Online BUSY or Hub-reserved, including session preparation/unconfirmed cleanup |
| Partly occupied | Some resources occupied while other ready/free resources remain |
| Unknown / not ready | Not counted as free; details separate probe/authorization/unavailable/unknown occupancy |
| Supported capabilities | Only `coverage_status=SUPPORTED`; installed tools alone do not prove execution support |
| Latest heartbeat | Most recent update on the current control connection, separate from RTT |

Preparing/offline occupancy is unknown and excluded from live resource counts. Historical capabilities are labeled. A Hub with no registered Nodes shows an empty list, not demonstration data.

## Measured control-channel RTT

RTT measures Ping on the current Node control WebSocket to the corresponding Pong, including the network and peer scheduling. It is not heartbeat interval, snapshot age, page-to-Hub HTTP latency, or action duration.

The standard CLI uses `runbridge_hub.transport.ControlWebSocketProtocol`, measuring on connection and then reusing the default approximately 20-second keepalive cycle. This uses standard control frames without changing Node's application contract or opening browser sessions for dashboard refresh.

- Before a valid Pong, display pending, not 0 ms. Small local values retain fractions.
- Samples under 60 seconds show measured values; older ones are stale. Details include sample time.
- Offline RTT is cleared; reconnect starts new measurements.
- Another ASGI server without the extension shows measurement unavailable. Use the standard CLI to verify RTT.

UI hints are good below 100 ms, medium from 100 to below 300 ms, and high at 300 ms or more; they do not change allocation. See [websockets latency documentation](https://websockets.readthedocs.io/en/stable/topics/keepalive.html).

When the page loses Hub, prior results are labeled historical while reconnecting. Invalid authentication clears node data and shows login.

## API and verification

`GET /dashboard/api/nodes` requires the independent dashboard Bearer token and disallows caching. It includes query time, Hub version, refresh period, connection/resource counts, per-node connections/capabilities/resources, and `latency`.

`latency.status`: PENDING, MEASURED, STALE, UNAVAILABLE, or OFFLINE. Without a valid value, `rtt_ms`, `measured_at`, and `sample_age_ms` are null. It exposes no identity/permit secrets, hashes, action parameters, page URLs, or execution contents.

Verify direct URL entry/refresh and sign-out; rejection of missing/wrong/other-role tokens; actual Node host/capability display and Pong-derived RTT; occupied/free transitions after allocation and confirmed cleanup; offline status after Node stops; and all dashboard entries returning 404 when disabled. A page HTTP 200 or a running process alone does not verify live state.

Assets reside in installed `runbridge_hub/web/`. [Phosphor Icons](https://github.com/phosphor-icons/core) 2.1.1 retain their bundled MIT license.

## Node lease state versus browser occupancy

The list separately shows unclaimed, held, releasing, or review-required ownership. A browser resource can be FREE while Node is still HELD. The lease holder's `node_inspect` sees actual resource state; dashboard access remains read-only and cannot claim or force-release.
