# Current dependencies and implementation scope

[简体中文](当前依赖与实现边界.md) · English

Applies to **Hub 0.9.3**. `pyproject.toml` defines package constraints and `uv.lock` locks development dependencies. Historical candidates and early npm/SDK research are not current requirements.

| Area | Current scope |
| --- | --- |
| Python | 3.14.x; [official documentation](https://docs.python.org/3.14/) |
| HTTP / WebSocket | FastAPI, Uvicorn, websockets; one ASGI worker with in-process resource routing; [Uvicorn settings](https://www.uvicorn.org/settings/) |
| Database | aiosqlite + SQLite schema 5; [WAL](https://www.sqlite.org/wal.html); Hub/offline maintenance uses an exclusive process lock per database |
| Startup | PyYAML safe loading and Pydantic validation; [parameters](参数详解.en.md) define defaults and paths |
| Dashboard | Packaged HTML/CSS/JS and local icons on the same listener; separate read-only token; no frontend build or CDN runtime dependency; RTT uses standard CLI WebSocket Ping/Pong |
| MCP | Optional `mcp==2.3.0`, Streamable HTTP, 27 project tools; browser execution is on Node |
| Browser | Hub and ordinary HTTP clients need no Playwright, Node.js, or browser; 33 methods form the project's versioned interface |
| Versions | Management HTTP `/v1`, execution protocol 2, Playwright tool API 1, visual protocol 1 are independent |

Current public behavior is defined by the [tool protocol](工具调用协议.en.md), [methods](Playwright方法表.en.md), and [visual contract](浏览器画面流接口.en.md). Backend SDK methods do not automatically become public project methods. Direct official SDK connections, arbitrary scripts, callbacks, and transparent object proxies are outside the supported interface.

The [architecture (Chinese)](../architecture/代码结构与执行流程.md), [isolated acceptance record (Chinese)](https://github.com/Pegasus-Yang/Run-Bridge-Hub/blob/main/doc/project/Python%E5%B7%A5%E5%85%B7%E6%89%A7%E8%A1%8C%E9%AA%8C%E6%94%B6%E8%AE%B0%E5%BD%95.md), and [historical sources (Chinese)](公开依据与研究边界.md) provide implementation/history context. Recorded macOS and Ubuntu ARM64 scenarios do not establish every platform, browser/window state, or capacity limit, nor prove a current deployment upgrade.
