# Hub 参数详解

适用于 Hub 0.9.2。首次部署从[快速开始](../user-guide/快速开始.md)执行；本文用于选择参数、查询默认值和维护多个环境的启动配置。可复制[完整注释 YAML](examples/Hub启动配置.yaml)。

## 两种启动方式与路径规则

推荐把参数保存在 YAML：

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

也保留直接传 CLI 参数的方式，例如仅本机访问：

```bash
.venv/bin/runbridge-hub serve --enrollment-token-file .runbridge/enrollment.token
```

`--settings` **不能与其他启动参数混用**，包括显式写出的默认参数。修改端口等设置应编辑 YAML，然后重启本实例。

- `--settings` 本身的相对路径以当前工作目录为准。
- YAML 内的 `database_path`、`enrollment_token_file`、`web_token_file`、`hub_token_file`，包括省略时的默认数据库路径，均以 **YAML 文件所在目录**为准。
- 不使用 YAML 时，CLI 文件路径以当前工作目录为准。
- 文件内容不展开 `~`、`$HOME` 或 shell 表达式；使用相对路径或完整绝对路径。
- YAML 使用 UTF-8、空格缩进；顶层为对象；未知字段和不支持的 `config_version` 会被拒绝。

例如 `/srv/runbridge/hub.yaml` 写 `database_path: data/hub.sqlite3`，实际文件就是 `/srv/runbridge/data/hub.sqlite3`，不会因从其他目录启动而改变。

## serve 的全部参数

| CLI 参数 | YAML 字段 | 默认值 | 用途与使用场景 |
| --- | --- | --- | --- |
| `--settings FILE` | 无 | 不读取 YAML | 保存并复用某个环境全部启动参数；使用后不再传表中其他选项 |
| 无 | `config_version` | `1` | Hub YAML 格式版本，只接受 1，可省略；与 Node 的 YAML 版本分别管理 |
| `--host ADDRESS` | `host` | `127.0.0.1` | 监听地址；仅本机访问可省略；远程 Node 或调用方需设置本机可达网卡地址或 `0.0.0.0` |
| `--port NUMBER` | `port` | `8787` | TCP 端口，通常使用 1～65535；0 保留给需要系统分配临时端口的测试；端口冲突或需要其他入口时修改，交付 URL 同步改变 |
| `--db-path FILE` | `database_path` | `.runbridge/hub.sqlite3` | SQLite 文件；首次自动创建父目录与数据库，已有部署应复用原文件 |
| `--enrollment-token-file FILE` | `enrollment_token_file` | 无 | Hub 接纳 Node 的登记秘密文件；使用 `generate-token` 生成，优先于环境变量 |
| `--hub-token-file FILE` | `hub_token_file` | 无 | 独立 Hub 申请凭据，文件优先于 RUNBRIDGE_HUB_TOKEN；未配置时资源池 API 为 503，不回退到登记凭据 |
| `--public-url URL` | `public_url` | 无 | 导出访问文件的实际 HTTP(S) 基址，可含代理前缀；不得含凭据、query、fragment；未配置时领取为 503 |
| `--grant-max-lease-seconds N` | `grant_max_lease_seconds` | `86400` | 正整数秒；申请及续租上限，默认一天，可配置更高或更低 |
| `--grant-idle-timeout-seconds N` | `grant_idle_timeout_seconds` | `600` | 正整数秒；新租约空闲策略快照，默认十分钟；状态查询、画面、心跳和续租均不刷新 |
| `--disable-web` | `web_enabled` | `true` | 默认启用同端口 `/dashboard`；CLI 参数或 YAML 的 `false` 关闭页面、资源和总览接口 |
| `--web-token-file FILE` | `web_token_file` | 无 | 独立只读口令文件，优先于 `RUNBRIDGE_WEB_TOKEN`；均未提供时在数据库同目录生成/复用 `web.token` |
| `--heartbeat-interval SECONDS` | `heartbeat_interval_seconds` | `30` | 下发给 Node 的应用心跳间隔，必须大于 0；普通部署无需调整 |
| `--heartbeat-timeout SECONDS` | `heartbeat_timeout_seconds` | `90` | 超过此时间未更新视为失联，必须大于心跳间隔；按实际网络条件选择 |
| `--enable-mcp` | `mcp_enabled` | `false` | 增加 `/mcp` 工具入口；须在同一 `.venv` 安装发布包的 `[mcp]` extra；纯 HTTP 可省略 |
| `--mcp-allowed-host HOST`，可重复 | `mcp_allowed_hosts` | `[]`，不限制 Host | 仅在非空时限制允许访问 MCP 的 HTTP Host；只允许列表中的地址，不追加隐式本机地址 |
| `--mcp-allowed-origin ORIGIN`，可重复 | `mcp_allowed_origins` | `[]` | 允许请求携带的 Origin；通常只在浏览器网页客户端有 Origin 时需要；不携带 Origin 无需填写 |

不支持多 worker 或多个 Hub 进程共享一个数据库的部署方式。HTTP/MCP/节点总览共用监听地址；`--host` 不会改变 MCP 允许列表。总览口令不能复用登记令牌，页面不提供执行或授权动作。启动成功后日志输出只读口令和带参数的 `Dashboard URL`，使用实际绑定端口；RTT 使用标准 CLI 实测，见[节点总览](../user-guide/节点总览.md)。

## 常见场景的最小配置

### 本机访问

```yaml
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787  # 本机场景改为 http://127.0.0.1:8787
```

监听 `127.0.0.1:8787`；Node 或调用方在其他设备时，应选择下一场景。本机 MCP 在已安装 extra 后只增加 `mcp_enabled: true` 即可，不需要额外 Host。

### 接纳远程 Node，使用 HTTP

```yaml
host: 0.0.0.0
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787  # 本机场景改为 http://127.0.0.1:8787
```

监听所有 IPv4 网卡。交付给 Node 的 URL 使用服务器实际 IP 或可解析名称，例如 `http://hub.example:8787`，不能写 `http://0.0.0.0:8787`。默认端口和数据库无需重复配置。

### 按需限制 MCP Host

省略 `mcp_allowed_hosts` 或设为 `[]` 时，所有 Host 均可访问 MCP；仍需有效的本次 Node 租约令牌。`host` 只控制监听地址，`public_url` 控制导出基址，它们不自动生成 Host 限制。

只有需要限制入口地址时，才设置非空列表。例如使用稳定主机名：

```yaml
host: 0.0.0.0
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787  # 本机场景改为 http://127.0.0.1:8787
mcp_enabled: true
mcp_allowed_hosts:
  - "hub.example:8787"
```

对应客户端 URL `http://hub.example:8787/mcp`。允许列表填写 **URL 中的主机名或 IP，加端口**，不带 `http://` 或路径，也不填写调用方/Node 的 IP。填写名称并保持名称解析指向 Hub 当前 IP 后，IP 变化不影响这项配置；本项目不配置 DNS。Node 的 Hub 基址也应使用适当的稳定名称，才能避免其地址随 IP 变化。

支持 `"hub.example:*"` 表示该名称的任意端口；不支持单独 `*`、`*.example` 或 `192.168.*.*`，允许全部 Host 请省略列表或设为 `[]`。列表非空时，主机名、IP 与本机地址都须按实际访问方式列出；不会额外允许 localhost、127.0.0.1 或 [::1]。

### 网页客户端带 Origin

在原配置中按实际请求追加，例如：

```yaml
mcp_allowed_origins:
  - "https://console.example"
```

Origin 包含协议和必要端口，没有页面路径；`http://console.example:8080` 与 HTTPS 是不同 Origin。该参数用于 MCP 请求校验，不是完整的浏览器跨域部署方案。普通不带 Origin 的 MCP 客户端省略即可。

## generate-token 与凭据来源

```bash
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--output FILE` | 必填 | 排他创建 UTF-8 单行随机凭据文件，可分别用于登记、Hub 申请或总览只读；文件权限 600，自动创建父目录；已有文件时拒绝覆盖 |

`RUNBRIDGE_ENROLLMENT_TOKEN` 是登记秘密的环境变量备用来源，仅在未设置令牌文件时读取。显式配置的文件缺失、不可读或为空时直接失败，不会静默使用环境变量。秘密长度为 32～256 字符；不要把真实内容放进命令行或公开 YAML。

`hub.yaml` 保存文件路径，不保存节点身份或调用许可。`enrollment.token`、SQLite、`access.json` 的产生和持有人见[配置与凭据](部署配置与凭据.md)。

## 帮助与失败提示

根命令、`serve` 和 `generate-token` 均支持 `-h` / `--help`，例如：

```bash
.venv/bin/runbridge-hub serve --help
```

配置失败以非零状态退出，不启动服务；YAML 语法或模型错误不会输出输入秘密。常见原因是字段拼写、令牌路径、心跳大小关系、端口范围、全局通配符或混用 CLI/YAML。具体处理见[快速开始的常见问题](../user-guide/快速开始.md#常见问题)。

## 租约参数与离线核查

每次申请/续租的 lease_seconds 默认 min(3600, grant_max_lease_seconds)，显式超限拒绝；浏览器会话 lease_seconds 仍为 1～3600，与 Node 租期分开。修改 Hub YAML 后重启：新上限用于后续申请/续租，存量 expires_at 不追溯缩短；新空闲时间只用于新租约，续租不重置计时。完整生命周期见[租约接口](Node使用权租约接口.md)。

`confirm-cleanup --db-path FILE --grant-id ID --evidence-file FILE --confirm-node-stopped` 是停止 Hub 和相关 Node 后的本地维护命令，需要原租约核查证据，不接受共享 Hub 凭据。数据库进程锁阻止在线维护；会话原始 UNKNOWN 保留。步骤见[运行与排障](../deployment/运行与排障.md)。
