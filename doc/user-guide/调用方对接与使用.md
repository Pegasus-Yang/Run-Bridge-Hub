# 调用方对接与使用

简体中文 · [English](调用方对接与使用.en.md)

适用于 Hub 0.9.2 / Node 0.8.1。本指南在**调用方机器**操作，前提是远程 Hub 与 Node 已就绪。无需在本机同时启动两端，也无需安装官方 Playwright SDK。浏览器操作由 Node 执行。

## 1. 从 Hub 领取 Node 使用权

从 Hub 部署者取得独立 `hub_token` 和真实基址，从资源池或设备维护者取得目标 `node_id`。Hub 不建立用户账号。将认证数据保存为私有 `hub-auth.json`：

```json
{"hub_url":"https://hub.example/runbridge","hub_token":"请填写Hub独立申请凭据"}
```

认证文件设为 600，不能放进 Git。复制文档包中的 [node_lease.py](../reference/examples/node_lease.py)，在调用方机器的 Python 环境执行：

```bash
chmod 600 hub-auth.json
.venv/bin/python node_lease.py claim --hub-auth hub-auth.json --node-id node_example --output access.json --lease-seconds 3600
```

node_example 换成真实 Node ID。首次成功后私有 access.json 严格包含 hub_url、node_id、grant_id、access_token、expires_at 五字段，数据来自 Hub 的 access_config；不得使用整份申请响应代替此文件。也可将这五字段保存为 YAML（Node 诊断 CLI 与 DSH 支持）；本页标准库示例只读 JSON。

一份租约独占整个 Node。默认租期 3600 秒，默认上限 86400 秒、空闲回收 600 秒；后两项由 Hub 配置。明确填写时长不得超限。持有 Hub 凭据不能操作已领取的 Node；执行和释放必须使用本次 access_token。申请响应丢失时同 request_id 不再返回秘密，不能覆盖原占用，应等待空闲回收再发起新申请。

领取前可用 Hub 凭据访问 GET /v1/pool/nodes 和 GET /v1/pool/nodes/{node_id}/tools 查询状态与 MCP 声明，不占用设备；自动化插件应先完成计划与审核，再领取。详细请求、状态与错误码见[租约接口](../reference/Node使用权租约接口.md)。

## 2. 先运行完整示例

需要 Python 3.14.x 与全局 uv，准备方式参考 [Python](https://www.python.org/downloads/)及 [uv](https://docs.astral.sh/uv/getting-started/installation/)官网。HTTP 示例只用标准库，不需要安装 Hub、Node 或浏览器库。

把文档包中的[执行会话调用.py](../reference/examples/执行会话调用.py)复制到调用目录，与收到的访问文件放在一起：

```bash
mkdir -p ~/runbridge-client
cd ~/runbridge-client
uv venv --python 3.14 .venv
# 在此目录保存真实 access.json 和文档包中的 执行会话调用.py。
chmod 600 access.json
.venv/bin/python 执行会话调用.py --access-file access.json --resource-id chromium --url https://example.com --screenshot page.png
```

资源 ID 使用实际能力中报告的值；网页地址换成 Node 网络能访问的业务地址。成功输出实际 URL/title、会话 ID 和 `cleanup: COMPLETE`，本机出现 PNG 文件。此处页面地址是给 **Node 浏览器**访问的；`127.0.0.1` 指 Node 自己，不指调用方。

已有 Chrome 使用对应资源，并用 `--page-url '已打开页面的精确URL'` 唯一选页；示例随后会导航该原页面到 `--url`。如只需读取已有页而不导航，按照第 3 节直接提交读取动作。

多个页的 URL 相同时，示例会拒绝选页。使用第 3 节的只读方法检查各 Page 的内容，再明确选择引用，或请所有者先准备可区分的测试页面地址。不要取页面数组的第一项。borrowed 的鼠标、键盘和表单输入会将指定页切到前台；只读查询和画面订阅不切页。

## 3. 理解调用顺序，再增加业务操作

1. `GET /v1/nodes/{node_id}/capabilities`：确认 ONLINE、非过期、资源 READY/FREE。
2. `GET /v2/nodes/{node_id}/tools`：查询当前许可可用方法，含输入类型、默认值、结果 schema。
3. `POST /v2/nodes/{node_id}/sessions`：JSON 为 `{"resource_id":"chromium","tool":"playwright","request_id":"open_order_1","lease_seconds":300}`。保留返回的 `session_id` 和 `objects`。
4. `objects.root` 是 Browser 引用；`objects.contexts` 为上下文；`objects.pages` 为 Page 引用和 URL；`objects.default_page_id` 为默认页或 `null`。引用在当前会话中有效，不自己编造，也不能跨会话复用。
5. `POST /v2/sessions/{session_id}/commands`：按下列格式提交动作。
6. 检查 `status` 和 `execution_outcome`，再读取页面或业务服务验证实际结果。
7. 每个用例结束 `DELETE /v2/sessions/{session_id}`，确认 `cleanup=COMPLETE`。borrowed 不关闭原 Chrome。
8. 整个任务或批次结束，执行下面的 Node 释放命令并等待终态；关闭会话不会交还 Node。

例如 Page 引用来自上一步，假设为 `page_example`：

```json
{
  "request_id": "fill_order_1",
  "method": "locator.fill",
  "target": {
    "type": "page",
    "id": "page_example",
    "locator": [{"method":"get_by_label","params":{"text":"用户名","exact":true}}]
  },
  "params": {"value":"测试用户","timeout":10000}
}
```

然后使用**新的** request_id，`method=locator.click`，把定位步骤改为 `{"method":"get_by_role","params":{"role":"button","name":"保存","exact":true}}`，参数 `{}`。最后用 `locator.inner_text` 读取“保存结果”对应元素；必要时再查业务服务最终记录。不要用 HTTP 200 或 `completed=true` 代替业务成功。

`locator.inner_text` 成功结果的取值层次是 `响应.result.value.value`，而 `page.title` 的字符串直接在 `响应.result.value`。例如读取结果的局部结构为 `{"status":"SUCCEEDED","result":{"kind":"json","value":{"value":"已保存","truncated":false}}}`。是否截断由内部 `truncated` 表示，不要把整个对象当作文本比较。

项目方法借鉴 Python Playwright 的命名和参数，**只支持方法表中列出的子集**。参数用 snake_case，默认超时 10000 毫秒，范围 1～30000；不能传任意 Python、`evaluate` 脚本、回调或 Node 文件路径。完整定位步骤、33 项动作和结果格式见[工具协议](../reference/工具调用协议.md)与[方法表](../reference/Playwright方法表.md)。

## 4. 超时、断线与重复请求

终态 HTTP 200 的 JSON 仍需检查：`SUCCEEDED` 表示技术动作完成；`FAILED` 表示已知错误；`UNKNOWN` 表示未获得可信最终结果。`execution_outcome=OUTCOME_UNKNOWN` 时可能已经发生点击、上传或提交。

HTTP 202 表示已接受仍在处理。保留原 `request_id`，调用 `GET /v2/sessions/{session_id}/commands/{request_id}` 查询，不另发一次动作。HTTP 断线也采用相同策略。

同一许可、同一会话中，同 ID 同方法/目标/参数只返回原状态或缓存；不同内容复用 ID 返回 `REQUEST_ID_CONFLICT`。重新创建会话、重启 Node/Hub、结果过期都不会自动重放。缓存淘汰返回 `result_available=false` / `RESULT_EXPIRED`，仍可知状态；不能据此当作没执行。

会话创建的 request_id 用于找回同一次分配，重复同内容的创建请求会返回同一会话，即使它已关闭，也不会重新启动。会话租期默认 300 秒、上限 3600 秒，受许可到期时间约束。需要新任务时明确使用新的创建 ID。

## 5. 画面和 Agent

持续画面使用查询返回的 `visual.stream_path`，见[画面指南](浏览器画面流接入.md)。Agent 使用[项目 MCP](MCP浏览器接入.md)，工具参数由 `tools/list` 提供。两种入口最终执行同一套 Node 动作。

## 6. 任务结束交还 Node

```bash
.venv/bin/python node_lease.py status --access-file access.json
.venv/bin/python node_lease.py release --access-file access.json
```

release 等待原租约回收：RELEASED 才表示交还，QUARANTINED 表示清理未知、仍不能交接。出错时保留原访问文件，使用原令牌查询；不要换新令牌重放动作。正常结束、取消和失败路径都应在 finally 中完成收尾。此命令不删除访问文件，便于查询原终态。

需要续租时，用本次 access_token POST /v1/grants/{grant_id}/renew，正文如 {"lease_seconds":3600}；返回期限不早于原期限，但不刷新空闲计时，也不延长已有浏览器会话。纯状态轮询、MCP握手、持续画面及连接保活均不能维持闲置占用。
