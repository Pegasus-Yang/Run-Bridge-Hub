# 首次登记与连通

[文档导航](../README.md) · [安装与运行](../deployment/安装与运行.md) · [下一步：调用方对接](调用方对接与使用.md)

本指南对应 Hub 0.5.1 / Node 0.5.0，先打通 Hub 与 Node。下面使用同一电脑上相邻的 runbridge-hub、runbridge-node 源码目录，Hub 为 http://127.0.0.1:8787。不同机器时改用 Node 实际可达的 Hub 地址，并单独交付登记文件；不能在虚拟机里用 127.0.0.1 访问宿主机 Hub。

## 1. 分别准备两个环境

在 Hub、Node 各自项目根目录执行：

```bash
uv sync --locked --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

需要 Chrome 画面时，Node 改用 --extra visual 的安装方式。wheel 安装的环境与启动命令见安装文档，以下不再混用两套方式。

## 2. 终端 A：Hub 首次启动

在 runbridge-hub 根目录：

```bash
uv run --locked --no-sync runbridge-hub generate-token --output .runbridge/enrollment.token
uv run --locked --no-sync runbridge-hub serve --host 127.0.0.1 --port 8787 --enrollment-token-file .runbridge/enrollment.token
```

已有 enrollment.token 时直接启动，不重复生成。数据库默认位于当前目录 .runbridge/hub.sqlite3；保持服务终端运行。在另一个终端检查：

```bash
curl --fail http://127.0.0.1:8787/health
```

预期为 {"status":"ok","protocol_version":1}。这只证明 Hub 健康，不证明 Node 已在线或浏览器可用。

## 3. 终端 B：Node 登记稳定身份

在 runbridge-node 根目录：

```bash
uv run --locked --no-sync runbridge-node register --hub-url http://127.0.0.1:8787 --enrollment-token-file ../runbridge-hub/.runbridge/enrollment.token --name local-node --config .runbridge/node.json
```

预期输出 node_id 和 created。首次 created=true，node_id 类似 node_加随机标识；保存实际 ID，后面的 node_example 需要替换为它。Node 身份已写入 .runbridge/node.json，原凭据不打印。

登记失败后用相同命令重试，保留同一身份文件。既有身份属于另一个 Hub 地址时命令拒绝复用，应为另一个部署选择独立配置文件。运行/重连使用 node.json，不再依赖首次登记文件。

## 4. Node 所有者签发一份查询许可

仍在 Node 根目录：

```bash
uv run --locked --no-sync runbridge-node grant --config .runbridge/node.json --expires-in 3600 --output .runbridge/access-control.json
```

预期输出许可 ID 和保存路径。这个基础联调许可未限制资源，期限为一小时；浏览器指南将演示只允许指定资源的许可。文件已存在时使用原有效许可或换一个新文件名，命令拒绝覆盖。

调用方只需要收到该访问文件；不交付 Node 身份、登记文件或本机浏览器配置。

## 5. 终端 B：运行控制连接

```bash
uv run --locked --no-sync runbridge-node run --config .runbridge/node.json
```

保持该终端运行。当前没有提供浏览器配置，所以仅建立控制连接、心跳和主机能力报告。之后启用浏览器模式时，正常停止这个 Node，再用同一身份加一种浏览器配置启动；不要另开同身份常驻进程争抢连接。

## 6. 终端 C：用调用许可查询

在 Node 根目录，把 node_example 替换为实际登记 ID：

```bash
uv run --locked --no-sync runbridge-node inspect node_example --access-file .runbridge/access-control.json --output json
```

| 字段 | 预期与解释 |
| --- | --- |
| connection_status | ONLINE，节点已经完成连接确认 |
| connection_generation | 节点这次连接的代次，重连后递增 |
| heartbeat_count / last_seen_at | 心跳与最后观察时间 |
| capabilities_stale | 在线且已上报时应为 false；离线历史快照不能当作就绪 |
| capabilities.host | 实际 Python、客户端版本和系统架构 |
| capabilities.resources | 本步骤为空，因为未启用浏览器 |
| visual.supported / streams | 不支持采集或无活动会话时为 false/空列表 |

调用方也可以直接使用 HTTP API，详见[对外接口总览](../reference/对外接口总览.md)。安装 Node CLI 只是查询的一种工具，并不是所有调用方的必需依赖。

## 7. 选择浏览器模式继续

- 需要复用原页面与登录：按[Chrome 复用指南](Chrome复用快速开始.md)准备本地固定 CDP 端点、启动 Node，并签发 chrome 资源许可。
- 需要每次新建独立浏览器：按[Playwright 指南](Playwright快速开始.md)准备受管理运行时，再启用 chromium 资源。
- 需要实时画面：已有 Chrome 模式完成后，再按[画面流接入](浏览器画面流接入.md)订阅；仅 ONLINE 或会话 READY 时不采集。

ONLINE → 资源 READY/FREE → 会话 READY → 官方 SDK 接入后的 ACTIVE → 实际业务验证，是依次不同的判断。cleanup=COMPLETE 也仅说明相应清理已经确认，不能替代业务成功。

## 停止、撤销与续期

在 Node 终端 Ctrl+C 正常停止后，查询最终显示 OFFLINE、capabilities_stale=true。Hub 重启后 Node 网络恢复会重新认证与上报，旧会话不会复活。

撤销指南中创建的实际许可 ID：

```bash
uv run --locked --no-sync runbridge-node revoke grant_example --config .runbridge/node.json
```

撤销或到期后旧访问文件返回 401；节点身份与控制连接保持独立。续期是签发新的许可并交付新文件，不修改旧文件里的 expires_at 或凭据值。新许可不能接管旧许可创建的会话。

网络/代理问题见[跨机器部署](../deployment/跨机器部署与中文字体.md)，其他错误见[排障](../deployment/Playwright运行与排障.md)。
