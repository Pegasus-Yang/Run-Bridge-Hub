# RunBridge Hub 部署与运行

[文档导航](../README.md) · [配置与参数查询](../reference/部署配置与凭据.md) · [运行与排障](运行与排障.md)

本文带 Hub 部署者从安装开始，完成服务启动，再把 Node 登记所需的资料交给设备所有者。适用于 **Hub 0.5.1**，命令使用 macOS／Linux 的 Bash 或 Zsh。Node 安装由另一台设备上的所有者按 Node 项目手册完成。

## 先看操作顺序

按第 1～7 节依次操作。首次部署完成的标志是：另一台设备能够访问 Hub，并且 Node 所有者已收到**实际 Hub 地址和真实的登记文件**。第 8 节供后续维护使用。

| 读到的名称 | 是什么 |
| --- | --- |
| Hub | 常驻运行的服务端，负责接收节点、检查许可和转发连接 |
| Node | 运行在浏览器设备上的另一个程序，主动连接 Hub |
| Hub 基址 | 客户端连接服务的地址，如 `http://192.168.50.10:8787`；包含协议、主机和端口 |
| 登记令牌 | 允许新 Node 登记的一段随机字符串，保存在 `enrollment.token` 中 |
| wheel／`.whl` | Python 程序的安装包文件，使用 uv 安装，不需要自己解压 |
| MCP | 供 Agent 调用浏览器工具的可选入口；只使用 HTTP／官方 SDK 时可以不开启 |

文中的 `192.168.50.10` 是演示地址。请先确定服务器的真实 IP 或域名：云服务器可从管理控制台取得；局域网机器可从系统网络设置取得。Linux 也可运行 `ip -brief address show up`，查看实际网卡上的地址。`127.0.0.1` 指当前机器自己，`0.0.0.0` 表示监听所有网卡，二者都不能当作远程设备的服务器地址。

## 1. 取得安装材料

向本次发布负责人取得下面的材料。本项目手册没有提供公共 PyPI 安装入口；不要根据包名猜测下载地址。

| 材料 | 本版文件名／要求 | 从哪里来 |
| --- | --- | --- |
| Hub 安装包 | `runbridge_hub-0.5.1-py3-none-any.whl` | 发布负责人交付 |
| Hub 文档包 | 包含本手册以及 `doc/reference/examples/` | 发布负责人交付；wheel 本身不包含这些操作手册和示例 |
| 依赖约束，可选 | `deploy-constraints.txt` | 发布负责人随同这一版安装包交付；没有时跳过 |
| 服务器地址 | Node 和调用方实际可达的 IP／域名和端口 | 服务器或网络管理员提供，部署者确认 |

后文假定安装包先保存在服务器当前账号的 `~/Downloads/`。没有图形桌面的服务器可由文件传输工具上传到该目录；目录不存在时先用 `mkdir -p ~/Downloads` 创建。若实际收到的文件在其他目录，把复制命令中的源路径改成那个位置。

`enrollment.token` 不需要向发布负责人索取：**它由你在第 4 节运行 Hub 命令现场生成**，安装包中没有预置的登记秘密。

## 2. 准备全局 uv 和部署目录

在 **Hub 服务器的终端**运行：

```bash
uv --version
```

已安装 Homebrew／uv 但新 SSH 终端提示找不到命令时，先加载该终端的 Homebrew 环境，不要重复安装。标准 Linux Homebrew 路径可运行：

```bash
eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"
uv --version
```

Apple Silicon macOS 可执行 `eval "$(/opt/homebrew/bin/brew shellenv)"`，Intel macOS 可执行 `eval "$(/usr/local/bin/brew shellenv)"`；安装在其他位置时以实际路径为准。按系统选择一种，不要把三种都执行。这个设置只影响当前终端。非交互脚本也可直接使用全局 uv 的绝对路径，例如 `/home/linuxbrew/.linuxbrew/bin/uv`。

能显示版本号即可继续，不需要重复安装。找不到命令时，已使用 Homebrew 的机器可运行 `brew install uv`；未使用 Homebrew 的 macOS／Linux 可按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)执行：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装后重新打开终端，再执行 `uv --version`。全局 uv 是管理 Python 环境的工具，不要在每个项目里再安装一套 uv。

创建 Hub 自己的部署目录：

```bash
mkdir -p ~/runbridge-hub
cd ~/runbridge-hub
pwd
```

`~` 表示当前账号的主目录。`pwd` 会显示部署目录的实际绝对路径，请记住它；以后重新打开终端，都先执行 `cd ~/runbridge-hub`。后文 `.runbridge/...` 和 `.venv/...` 都相对于这个目录。

## 3. 安装 Hub 程序

复制安装包并检查文件是否就位：

```bash
cd ~/runbridge-hub
cp -n ~/Downloads/runbridge_hub-0.5.1-py3-none-any.whl ./
ls -l runbridge_hub-0.5.1-py3-none-any.whl
```

`cp -n` 表示已有同名文件时不覆盖；看到 `No such file` 时，先核对下载位置与文件名，再继续。

首次安装时创建独立 Python 环境：

```bash
uv venv --python 3.14 .venv
.venv/bin/python --version
```

uv 会查找或下载标准 CPython 3.14.x，并把该部署使用的 Python 放在 `.venv/`。已部署过且环境有效时，跳过创建命令。后续命令已明确使用这个环境，不需要另外“激活环境”，也不要求存在单独的 `pip` 命令。

**根据用途只选一种安装命令。**不确定用途时，先与调用方确认是否需要 MCP。

只使用 HTTP／官方 SDK：

```bash
uv pip install --python .venv/bin/python ./runbridge_hub-0.5.1-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

还要让 Agent 使用 MCP 浏览器工具：

```bash
uv pip install --python .venv/bin/python './runbridge_hub-0.5.1-py3-none-any.whl[mcp]' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

`[mcp]` 表示同时安装可选客户端依赖，不是另一个文件名。命令周围的单引号要保留，防止 shell 解释方括号。Hub 不需要本机浏览器、Node.js 或 npm；实际浏览器在 Node 设备上。

若收到 `deploy-constraints.txt`，也把它复制到部署目录，并在所选安装命令最后添加 `--constraint ./deploy-constraints.txt`。它限制依赖版本，不是启动配置，不要自己凭空创建一份。

检查安装：

```bash
.venv/bin/runbridge-hub --help
uv pip check --python .venv/bin/python
```

第一条应列出 `generate-token` 和 `serve`；第二条应报告依赖兼容。出现错误时先解决安装问题，不要继续启动。

## 4. 生成登记文件：enrollment.token

仍在 `~/runbridge-hub`：

```bash
umask 077
mkdir -p .runbridge
chmod 700 .runbridge
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
```

成功时输出：

```text
登记凭据已保存：.runbridge/enrollment.token
```

这条命令随机生成真实令牌，写入 `~/runbridge-hub/.runbridge/enrollment.token`。令牌由程序生成，不来自账号密码、浏览器、Hub 地址或发布包，也不需要你事先编写。

文件为 **UTF-8 纯文本，正文只有一行令牌，末尾可以有换行**。例如下面是格式示意，**演示值不能用于实际部署**：

```text
EXAMPLE_ONLY_ENROLLMENT_TOKEN_DO_NOT_USE_00000000000000000000000
```

真实生成器写入 64 个字符和末尾换行。不要把它改成 JSON，不要添加引号、`Bearer ` 或 `token=`。文件扩展名是 `.token`，不要保存成 `enrollment.token.txt`。

用下面的命令确认文件存在，无需输出秘密：

```bash
ls -l .runbridge/enrollment.token
```

在 macOS／Linux 上文件权限应为 `-rw-------`，即只有当前用户可读写。`.runbridge` 以点开头，是隐藏目录；使用图形文件传输工具时需要开启显示隐藏文件。

**再次部署或重启时复用原文件，跳过生成。**生成命令拒绝覆盖已有文件。Hub 启动和后续交付 Node 使用的必须是同一份内容；两端分别随机生成会导致登记失败。

## 5. 启动 Hub

把当前终端称为**终端 A**。下面两种启动方式只选一种，选择与你安装的依赖对应的方式。

基础 Hub：

```bash
cd ~/runbridge-hub
.venv/bin/runbridge-hub serve --host 0.0.0.0 --port 8787 --db-path .runbridge/hub.sqlite3 --enrollment-token-file .runbridge/enrollment.token
```

启用 MCP 的 Hub；把允许的 Host 改为真实地址：

```bash
cd ~/runbridge-hub
.venv/bin/runbridge-hub serve --host 0.0.0.0 --port 8787 --db-path .runbridge/hub.sqlite3 --enrollment-token-file .runbridge/enrollment.token --enable-mcp --mcp-native-url http://127.0.0.1:8787 --mcp-allowed-host 192.168.50.10:8787
```

| 参数 | 这一步的含义 |
| --- | --- |
| `--host 0.0.0.0` | 接收本机所有网卡的连接；客户端仍填写真实 IP／域名 |
| `--port 8787` | 服务监听端口，须允许目标网络访问 |
| `--db-path` | Hub 自行创建 SQLite 数据库；不要手写该文件，也不要用空文件替代 |
| `--enrollment-token-file` | 读取第 4 节生成的纯文本文件 |
| `--enable-mcp` | 显式启用 `/mcp`；仅安装 `[mcp]` 不会自动开启 |
| `--mcp-native-url` | Hub 内部回连自己的地址，保留本机回环根地址，不加 `/mcp` |
| `--mcp-allowed-host` | MCP 请求到达 Hub 时使用的主机名和端口；使用 HTTPS 代理域名时例如 `hub.example.com` |

启动后应看到服务已运行的日志，**终端不会回到输入提示符，这是正常的**。保持终端 A 打开。下面的检查在另一个终端进行，不要再运行第二个 Hub。要切换启动方式，先在终端 A 按 Ctrl+C 正常停止，再执行另一条命令。

启动后目录大致如下：

```text
~/runbridge-hub/
├── runbridge_hub-0.5.1-py3-none-any.whl
├── .venv/                         # uv 创建的 Python 环境
└── .runbridge/
    ├── enrollment.token           # 第 4 节生成的登记秘密
    └── hub.sqlite3                # Hub 自动创建的持久数据
```

数据库运行时可能还有 `-wal`／`-shm` 文件，属于 SQLite 正常行为。完整参数的默认值和限制见[配置参考](../reference/部署配置与凭据.md)，首次启动不需要添加该表的所有参数。

## 6. 检查本机和远程访问

打开 **Hub 服务器的终端 B**：

```bash
cd ~/runbridge-hub
curl --fail http://127.0.0.1:8787/health
```

应返回：

```json
{"status":"ok","protocol_version":1}
```

然后请位于 Node 网络的接收者执行同一项健康检查，地址改为本服务的真实地址，例如 `http://192.168.50.10:8787/health`。这一步的操作写在 Node 部署手册的开头。

如果本机通过、远程不通，检查服务器防火墙、云安全组、虚拟机网络或反向代理是否开放了所选端口。远程访问未通过时先解决网络，Node 无法靠修改登记令牌绕过网络故障。

`/health` 不需要登记令牌。它只确认服务可达，不能证明浏览器已经接入。

## 7. 把登记资料交给 Node 所有者

**交付的是第 4 节生成的真实文件，不是本手册的演示字符串。**在 Hub 的部署目录运行 `pwd` 后，定位该目录下的 `.runbridge/enrollment.token`。例如 Linux 账号为 `hub-admin` 时，完整路径可能是 `/home/hub-admin/runbridge-hub/.runbridge/enrollment.token`；以你的实际目录为准。

通过双方认可的私密文件传输渠道，把这一个文件原样交给 Node 所有者。接收方按 Node 手册先保存到自己的 `~/Downloads/enrollment.token`，再放入 Node 私有目录。文件传输不会更改 Hub 上的原文件。

同时交给对方以下说明；可以复制此模板后填写。这是给人看的交接信息，Hub 不读取这段文字：

```text
Hub 地址：http://192.168.50.10:8787
健康检查：http://192.168.50.10:8787/health
登记附件：enrollment.token（真实附件，与 Hub 正在读取的文件内容相同）
适配版本：RunBridge Node 0.5.0
MCP：已启用；入口为 http://192.168.50.10:8787/mcp
Node 安装包：由本次发布负责人另行交付 runbridge_node-0.5.0-py3-none-any.whl
后续操作：按 RunBridge Node 项目《部署与运行》接收文件、登记和准备浏览器
```

没有启用 MCP 时，把相应一行改成“未启用”，不要交付一个尚未开放的入口。启用与否不影响普通 Node 登记。

接收方可能收到以下两种材料：

| 对方收到什么 | 应如何说明 |
| --- | --- |
| 文件附件 `enrollment.token` | 保留正文和文件名，按 Node 手册复制到自己的私有目录 |
| 只能传递令牌原文 | 提供完整的单行真实值，明确它是登记令牌；Node 手册有保存为文件的步骤 |

Node 自己的 `node.json`、浏览器配置和调用方 `access.json` 是后续生成的其他文件，不由 Hub 部署者提前编造。登记令牌允许新节点接入，交给经过确认的 Node 所有者；普通接口调用方使用的是 Node 所有者另行签发的访问许可。

做到这里，Hub 首次部署和交接完成。请对方回报实际节点 ID 和上线结果，再按 [Hub 接入检查](../user-guide/快速开始.md)继续。Hub 服务器无需安装或运行 Node。

## 8. 后续运行、网络与维护

### 让服务长期运行

本教程的终端 A 是前台运行：关闭它或按 Ctrl+C 会停止服务。需要开机启动或无人值守时，由部署环境的进程管理器管理上面的启动命令，并固定：

- 工作目录为第 2 节的实际部署目录。
- CLI 为该目录内 `.venv/bin/runbridge-hub` 的绝对路径。
- 保留日志；使用正常停止／SIGTERM 流程。
- 只运行一个 Hub 进程和一个 ASGI Worker。当前活动连接属于该进程，不能直接增加 Worker 共享路由。

### HTTPS、代理和 MCP 允许列表

生产入口的 HTTPS／WSS 由反向代理或部署设施终止；Hub CLI 没有证书参数。代理应转发 Authorization、User-Agent、`x-playwright-*` 和 WebSocket Upgrade，连接超时需覆盖心跳和会话租期。

MCP 默认允许回环 Host。外部 MCP 请求的 Host 通过 `--mcp-allowed-host` 追加；网页客户端若发送 Origin，还需用 `--mcp-allowed-origin https://agent.example.com` 允许真实来源。无 Origin 的服务端客户端不必设置这一项。不要使用单独的 `*` 放行全部来源。

代理路径前缀需一致映射到 Hub 原路由；MCP 内部原生地址仍使用无前缀根地址。Hub 没有通用 HTTP CORS 配置；调用方网页的跨域或同源代理由其平台处理。

### 停止、备份和升级

先让调用方结束活动会话，再正常停止 Hub。重启会中断旧会话；Node 重连后重新上报，调用方需要新会话，原 SDK 对象不会恢复。

备份时正常停止后复制 `hub.sqlite3`，或使用 SQLite 一致性备份；运行中的 WAL 模式不能只随意复制主数据库文件。把原登记文件一并妥善保存，不要把数据库或登记秘密放入公开文档或 Git。

Hub 0.5.1 使用 SQLite schema 3，启动会迁移 v1／v2；回退需使用升级前的一致性备份。升级时在原 `.venv` 安装新 Hub wheel，保留原数据和登记文件；MCP 部署继续安装对应 extra。完成后重新验证本机健康、远程访问和已有节点上报。

源码安装、构建和同机 Hub／Node 联调属于[开发文档](../development/本地开发与联调.md)。
