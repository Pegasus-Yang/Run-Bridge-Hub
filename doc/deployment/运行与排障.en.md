# Hub operations, troubleshooting, and upgrades

[简体中文](运行与排障.md) · English

Applies to **Hub 0.9.2 / Node 0.8.1**. Hub allocates anonymous exclusive leases on whole Nodes and has no user-account system. Device identity, Hub claim credentials, lease tokens, and dashboard tokens have separate roles.

| Symptom | Check and action |
| --- | --- |
| `HUB_ACCESS_NOT_CONFIGURED` | Configure independent `hub_token_file` or `RUNBRIDGE_HUB_TOKEN`; enrollment is not a fallback |
| `PUBLIC_URL_REQUIRED` | Set the actual client-reachable `public_url`, including a proxy prefix when needed, without `/mcp` |
| `INVALID_HUB_TOKEN` | Use the pool/claim credential, not enrollment, dashboard, identity, or lease tokens |
| `NODE_LEASE_BUSY` | Node is held, releasing, or quarantined; await the original release |
| `NODE_OFFLINE` / `NODE_NOT_READY` | Control connection, heartbeats, actual tool probe, and READY/FREE resource |
| Execution or renewal 401 | Original lease ended, expired, or idled out; query its original ID with its original token |
| `LEASE_TOO_LONG` / `INVALID_REQUEST` | Positive integer lease duration within the configured maximum; browser sessions separately allow 1–3600 seconds |
| Duplicate claim lacks `access_token` | Secrets are delivered once; retain the original file or wait for idle reclaim |
| `RELEASING` / `QUARANTINED` | Cleanup pending / unknown; both prevent execution and a new claim |
| Session CLOSED but Node HELD | Release the Node separately with `DELETE /v1/grants/{grant_id}` |
| Database already in use | Stop the original process; do not delete `.lock` to bypass the process lock |
| MCP 404 / 421 / 403 | Enable flag/extra; nonempty Host list; Origin and ownership respectively |
| `RESULT_UNKNOWN` / `RESULT_EXPIRED` | Query the original request and verify actual business state before another action |
| Frames stale or stopped | Visual state, original lease validity, and page directory; observation does not reset idle time |
| Invalid dashboard token | Use the separate read-only token; it cannot claim or execute |

## Upgrade from 0.9.0 or 0.9.1 to 0.9.2

This patch changes the default MCP Host rule. Schema 5, Node 0.8.1, and plugin 0.15.0 contracts remain compatible. Stop new work, let current leases return, stop Hub, install the 0.9.2 wheel in the original `.venv`, then start with the original `hub.yaml`. No new identity, credential, access file, or database migration is required for this path.

Omitted `mcp_allowed_hosts` or `[]` allows all Hosts. A nonempty list permits only listed addresses. To retain restrictions with local access, explicitly include required `localhost`, `127.0.0.1`, or `[::1]` host/port entries. Token authentication and Origin validation remain in effect.

## Upgrade from 0.8.x or earlier to 0.9.2

This changes grant behavior: old grants cannot continue executing. Execution protocol 2, tool API 1, visual protocol 1, Hub YAML format 1, Node YAML format 2, and device identity format are unchanged.

1. Stop new work, close sessions, and confirm actual `cleanup=COMPLETE`. Stop Hub and related Nodes. Back up YAML, SQLite and side files, enrollment/dashboard tokens, and Node identities.
2. Review unresolved cleanup using the next section. Migration refuses such records without changing the old schema; keep original UNKNOWN evidence.
3. Install the new Hub package in its original `.venv`, upgrade Node to 0.8.1 using its guide, and retain stable identities and enrollment credentials.

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_hub-0.9.2-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'
.venv/bin/runbridge-hub generate-token --output .runbridge/hub.token
```

4. Add `hub_token_file` and `public_url`. Configure `grant_max_lease_seconds` (default 86400) and `grant_idle_timeout_seconds` (default 600) if needed; see [annotated YAML](../reference/examples/Hub启动配置.en.yaml). Enrollment, claim, and dashboard secrets must differ.
5. Start Hub, then Node. Migration to schema 5 adds a unique occupancy constraint and invalidates all old grants, while preserving devices, sessions, and command history. It saves `.pre-lease-<time>.bak` beside the database; retain your complete pre-upgrade backup as well.
6. Check health, dashboard, pool ONLINE/READY/FREE and UNCLAIMED. Claim through Hub and verify a real action, session cleanup, and Node release. Old `access.json` is invalid; editing its expiry does not renew it.

Rollback requires stopped services, the pre-upgrade database, and matching old package/configuration. Do not open schema 5 using an older package. Historical instructions remain in Git and the [release record (Chinese)](../project/版本发布记录.md).

## Offline review of unknown cleanup

A maintainer with Hub host file access performs this procedure. A shared `hub_token` has no force-takeover operation.

Stop the target Hub and related Nodes. Check the original session and Node `state-node_ID` activity records against PID creation times, dedicated short directories, and ownership markers. In managed mode, handle only that scope's worker/browser/profile. In borrowed mode, disconnect RunBridge while preserving original Chrome and login state.

Confirm no original operation continues. Archive verified Node activity records outside the state directory, keeping evidence. Save UTF-8 JSON, using actual IDs, time, and findings:

```json
{"node_id":"node_example","grant_id":"grant_example","checked_at":"2026-10-23T14:00:00+00:00","details":"Describe stopped instances, original sessions, and verified processes/directories; omit tokens"}
```

The evidence time must be at or after lease creation and no later than the server's current time. Save as `cleanup-evidence.json`, mode `600`, then run from the Hub deployment directory:

```bash
.venv/bin/runbridge-hub confirm-cleanup --db-path .runbridge/hub.sqlite3 --grant-id grant_example --evidence-file cleanup-evidence.json --confirm-node-stopped
```

The process lock rejects online maintenance. The command backs up the database and records evidence for exactly that grant. Schema 5 accepts QUARANTINED grants; older schemas can record evidence for grants blocking migration. Repeating identical evidence is idempotent; existing evidence cannot be replaced.

This does not replay commands or rewrite a session's UNKNOWN cleanup. Schema 5 releases occupancy while retaining original cleanup and adding `resolution`. Old databases still require normal migration, invalidating old grants. After restart, check evidence and original lease state and let Node probe readiness before allowing claims. Keep quarantine when trustworthy evidence is unavailable.

## Shutdown and policy changes

Finish tasks, release Nodes, stop normally, and back up before configuration changes. Lease expiry, activity time, and idle policy persist across restart; restart does not reset clocks. Unknown cleanup on interrupted sessions remains quarantined.

A new maximum affects later claims/renewals, without shortening existing expiry. New idle configuration applies to new leases; renewal does not reset idle time. Check the target environment's installed metadata and actual behavior to confirm an upgrade.
