## 3. 存储与接入

| 来源 | 支持的结论 |
| --- | --- |
| [SQLite 适用场景](https://www.sqlite.org/whentouse.html) | 低管理写入场景、单写者与多服务器边界 |
| [SQLite WAL](https://www.sqlite.org/wal.html) | 读写并行改善，同主机和网络文件系统限制 |
| [Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/) | at-most-once，不能自动获得可靠执行恢复 |
| [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html) | Bearer 持码许可、TLS 与凭据保护 |

“首期不需要 Redis”“管理与网关同进程”和“100 用户、10 并发执行（按每用户 1 个在线客户端估算）”是结合当前范围、已由用户确认的设计与压测规划，不是这些组件官方对本项目的容量保证。当前仅验证 R0/R1 管理 API 与控制通道，尚无容量或性能测量；参考硬件、流量假设和验收方式见[最小实现与验证计划](../design/最小实现与验证计划.md)。

## 5. 本次完成和未完成

完成：研究范围重组、三部分职责与合同、Python/Pydantic 官方支持核对、12 个包分发元数据、执行运行时元数据、拆分/存储取舍、首期方案定稿、容量规划与验证标准、历史文件按字节归档。

当前新增完成：R0/R1 基础依赖解析/锁定/安装、项目包构建、服务器与客户端控制通道、登记认证、心跳、能力/许可查询与重启恢复验收。证据见[运行核验记录](R0与R1运行核验记录.json)。

未完成：执行会话与原生协议代理、浏览器或真机操作、完整原生 API 覆盖、执行恢复、性能测试、客户端打包、依赖许可审计。

本地标准 Python 3.14.7 仅作解释器存在证据。原研究未以解释器存在宣称候选库已运行；当前两项目各自 .venv 已通过基础依赖和控制通道实测，未改变其他项目的虚拟环境。
