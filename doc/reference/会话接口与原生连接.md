# RunBridge 会话接口与原生连接

[文档导航](../README.md) · [当前架构](../architecture/Playwright执行与会话管理.md) · [统一调用指南](../user-guide/调用方对接与使用.md) · [对外入口](对外接口总览.md)

本文件描述 0.4.0 的实际接口。HTTP/JSON 与控制消息继续使用合同版本 1；受管理 Playwright 和已有 Chrome CDP 使用各自原生协议。

## 调用方 API

所有接口使用调用方 `Authorization: Bearer <access_token>`；节点身份凭据不能代替它。会话 GET/DELETE 和原生入口还要求与创建会话的 grant_id 相同。

| 方法/路径 | 请求/返回 |
| --- | --- |
| POST `/v1/nodes/{node_id}/sessions` | 申请浏览器，等待就绪；201 SessionView |
| GET `/v1/sessions/{session_id}` | 200 SessionQueryView；基础会话字段与临时 visual |
| DELETE `/v1/sessions/{session_id}` | 幂等释放，200 SessionView；不是空 204 |
| WS `/v1/sessions/{session_id}/playwright` | 官方 Chromium SDK 原生入口 |
| WS `/v1/sessions/{session_id}/cdp` | 已有 Chrome，官方 SDK connect_over_cdp 入口 |

```json
{"resource_id":"chromium","client_version":"1.63.0","lease_seconds":300}
```

`resource_id` 是节点资源 ID，`client_version` 是调用方实际 SDK 分发版本，必须是三段数字；`lease_seconds` 默认 300、范围 1–3600。准备请求最长等待 30 秒，调用方 HTTP 超时应大于该值；CLI 使用 40 秒。不接受远程启动参数。

| SessionView 字段 | 含义 |
| --- | --- |
| protocol_version / session_id | 控制合同版本 1、管理会话 ID |
| node_id / resource_id / grant_id | 节点、独占资源位和创建许可 |
| connection_generation | 本次节点连接代次 |
| backend / runtime_version | playwright 与 npm Playwright 版本；或 chrome-cdp 与实际 Chrome 版本 |
| client_version | 创建时的调用方 SDK 版本；兼容旧会话时可空 |
| native_protocol | playwright 或 cdp；决定 SDK 连接方式和入口 |
| authorization_scope | 已有 Chrome 必须为 BROWSER_INSTANCE；受管理模式为空 |
| state / cleanup | 会话生命周期、PENDING/COMPLETE/UNKNOWN |
| execution_outcome | NOT_STARTED/NOT_TRACKED/OUTCOME_UNKNOWN |
| created_at / updated_at / expires_at | 带时区时间，期限不晚于许可期限 |
| close_reason / error_code | 可空的公开技术原因 |
| native_path | READY/ACTIVE 时的相对 WS 路径，无秘密；结束后为空 |

HTTP(S) Hub 基址换成 WS(S) 并保留部署路径前缀，再拼接 `native_path`。对接码放在 SDK `connect` 或 `connect_over_cdp` 的 Authorization 头，不能放入 URL。受管理模式的 Hub 转交 `User-Agent` 与 `x-playwright-*` 原生头，消费调用方 Bearer，不交给本机服务；Chrome 模式不把任何调用方头交给本机浏览器。原生入口拒绝查询参数、错误浏览器类型及协议不匹配。

受管理模式要求 SDK 与 npm 服务主、次版本相同。CDP 会话的 Chrome 版本不与 SDK 比较，SDK 最低 1.60，实际握手须与创建时声明的 SDK 主、次版本相同；已验收 1.63.0，不意味着其他版本都已验证。Chrome SDK 接入时使用 `no_defaults=True`，该参数由调用方选择。

## CLI

```bash
uv run --locked --no-sync runbridge-node session create --access-file .runbridge/access.json --resource-id chromium --client-version 1.63.0 --lease-seconds 300
uv run --locked --no-sync runbridge-node session get session_example --access-file .runbridge/access.json
uv run --locked --no-sync runbridge-node session close session_example --access-file .runbridge/access.json
```

这些命令在 Node 源码根目录运行；wheel 部署使用 .venv/bin/runbridge-node 替代 uv 前缀。session_example 换为实际会话 ID。

创建和释放返回基础 SessionView，查询返回带 visual 的 SessionQueryView JSON，诊断在 stderr。`inspect <node-id> --access-file ...` 继续查询节点与能力。CLI 不自动重放创建、关闭或浏览器动作；HTTP 失联后先确认状态，不能凭超时断言动作未执行。

节点/会话查询在 0.4.0 默认附带画面数据流入口与状态，详见[浏览器画面流接口](浏览器画面流接口.md)。控制消息和会话持久化结构保持不变，旧严格查询模型须同步升级；未安装画面扩展不影响原生执行。

## Node 本地配置

`run --playwright-config <文件>` 是节点所有者选择的本地启用入口。示例见[配置文件](examples/Playwright节点配置.json)。路径相对执行命令的当前工作目录；建议始终在 Node 项目根目录运行。

| 字段 | 默认/行为 |
| --- | --- |
| runtime_directory | 必填；prepare-playwright 准备的独立目录 |
| node_executable | node；也可指定 Node.js 的绝对路径 |
| resource_id | chromium；每个 Node 当前一个受管理资源位 |
| launch_options | 对象，字段名/参数采用 Node.js Chromium launchServer API |

允许启动字段：`args`、`artifactsDir`、`channel`、`chromiumSandbox`、`downloadsPath`、`env`、`executablePath`、`headless`、`ignoreDefaultArgs`、`proxy`、`slowMo`、`timeout`、`tracesDir`。类型与值由官方运行时校验，不把它们换成简化的 click/goto 接口。未列出的字段明确拒绝；`host`、`port`、`wsPath`、信号管理和函数型 logger 不由该 JSON 配置提供。

工具 timeout 使用官方毫秒单位，默认 20000；外层 Node 准备等待最多 30 秒，即使把工具 timeout 调大或设为 0，也不能取消该外层限制。启动路径/环境和输出目录仅由所有者本地配置，不删除用户指定的目录；默认浏览器临时数据由官方服务在关闭时回收。[launchServer](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-server)

已有 Chrome 选择 `run --chrome-config <文件>`，与受管理配置互斥，示例见[Chrome 本地配置](examples/Chrome节点配置.json)。字段 `resource_id` 默认 chrome；`authorization_scope` 必填且只能是 BROWSER_INSTANCE；`cdp_endpoint` 必填，为固定浏览器 ID 的本机回环 `ws://.../devtools/browser/...`，不接受 HTTP 自动发现或页面级端点。Chrome 已由所有者运行，Node 不需要 npm/Node.js，不启动或关闭用户浏览器。完整步骤见[Chrome 指南](../user-guide/Chrome复用快速开始.md)。

资源上报 `backend=chrome-cdp`、`kind=BORROWED_CHROME_CDP` 和 `authorization_scope=BROWSER_INSTANCE`。范围覆盖端点可见的整个实例，不提供页面/域名隔离；本机端点不写入能力或会话视图。会话准备和占用沿用现有控制消息；`session_prepared.runtime_version` 为实际 Chrome 版本。

## Node 出站隧道与控制消息

Node 使用自己的身份认证 `/v1/nodes/{node_id}/sessions/{session_id}/tunnel`，头 `x-runbridge-generation` 指定当前代次。只有匹配节点、当前代次、PREPARING 会话且未已有隧道时才接受；调用方许可不能建立它。

| 方向 | type | 主要字段 |
| --- | --- | --- |
| Hub → Node | session_open | connection_generation、session_id、resource_id |
| Node → Hub | session_prepared | connection_generation、session_id、runtime_version 或 error_code |
| Hub → Node | session_connect | connection_generation、session_id、headers |
| Hub → Node | session_stop | connection_generation、session_id、reason |
| Node → Hub | session_closed | connection_generation、session_id、cleanup、可空 error_code |
| Hub → Node | session_ack | connection_generation、session_id |

这些消息与 R1 心跳/能力确认共用控制连接，发送串行，执行任务异步；执行帧只走独立隧道。接入 SDK 前，隧道管理端交出接收权，再传递 SDK 头与连接命令，避免两个任务争读同一连接。

## 公开错误

| 状态/错误码 | 情况 |
| --- | --- |
| 401 INVALID_ACCESS_TOKEN | 缺失、错误、撤销或到期的调用许可 |
| 403 NODE_OUTSIDE_GRANT / RESOURCE_OUTSIDE_GRANT | 节点或资源超出范围 |
| 403 SESSION_OUTSIDE_GRANT | 会话属于另一个许可 |
| 404 RESOURCE_NOT_FOUND / SESSION_NOT_FOUND | 不存在或不是当前支持的资源 |
| 409 NODE_OFFLINE / RESOURCE_NOT_READY / RESOURCE_BUSY | 节点、就绪或独占冲突 |
| 409 BACKEND_UNAVAILABLE / BACKEND_VERSION_UNKNOWN | 服务不可用或版本无法比较 |
| 409 SESSION_NOT_CONNECTABLE / SESSION_EXPIRED | 不能接入或已到期 |
| 428 PLAYWRIGHT_VERSION_MISMATCH | SDK/服务主、次版本不匹配 |
| 428 CDP_CLIENT_VERSION_UNSUPPORTED | Chrome 模式的 SDK 低于 1.60 |
| 409 RESOURCE_NOT_AUTHORIZED | Chrome 资源未声明实例授权 |
| 409 NATIVE_PROTOCOL_MISMATCH | 会话与访问入口协议不符 |
| 409 CHROME_CONNECT_FAILED / CHROME_CONNECTION_LOST | Chrome 不可达、版本变化或本机连接丢失 |
| 400 BROWSER_TYPE_MISMATCH / UNSUPPORTED_NATIVE_QUERY | 非 Chromium 或带不支持的查询参数 |
| 431 NATIVE_HEADERS_TOO_LARGE | 原生工具头合计超过 32 KiB |
| 504 SESSION_PREPARE_FAILED | 准备等待超时/连接失败 |
| 409 PLAYWRIGHT_START_FAILED / NODE_RESOURCE_UNAVAILABLE | Node 再检查或启动失败 |

原生 WS 在接受前使用 HTTP 拒绝状态；控制连接错误仍用 R1 错误消息和关闭码。执行帧超限/失联会关闭连接并记录技术状态，SDK 方法调用错误沿原生协议返回。释放后要检查 cleanup；关闭码、零退出码和 CLOSED 本身不代替业务测试结果。

借用模式还返回 CDP 原生 `-32000 / RUNBRIDGE_BORROWED_BROWSER_COMMAND_FORBIDDEN`，拒绝 Browser.close、Browser.crash 和 Target.sendMessageToTarget，不改变其他支持方法的参数。`cleanup=COMPLETE` 仅确认本次连接释放；Chrome 与原页面保留，详情见[授权与清理](../architecture/Chrome复用与授权清理.md)。
