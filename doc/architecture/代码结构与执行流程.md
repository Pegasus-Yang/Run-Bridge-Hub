# Hub 代码结构与执行流程

适用于 0.6.0。部署者从[部署手册](../deployment/部署与运行.md)开始，本文用于维护源码和理解职责；不包含 Node 的安装步骤。

## 模块与状态归属

源码均在 `src/runbridge_hub/`：

| 模块 | 当前职责 |
| --- | --- |
| `app.py`、`settings.py`、`cli.py` | 组装单进程应用、依赖生命周期、CLI 与启动配置 |
| `api.py`、`service.py`、`security.py` | HTTP 管理/执行路由、登记、许可签发/撤销、节点查询和令牌哈希鉴权 |
| `gateway.py`、`protocol.py` | `/v2` 节点控制 WS、连接代次、心跳与能力快照 |
| `sessions.py` | 工具会话分配、资源预留、创建去重、租期和关闭确认 |
| `commands.py`、`tool_contract.py` | 执行 WS 与指令服务、方法输入/输出模型、去重、队列、关联和状态查询 |
| `mcp_server.py`、`browser.py`、`browser_tools.py` | Bearer MCP 入口、27 个工具的参数转换与结果包装，共用会话/指令服务 |
| `visual.py`、`visual_api.py`、`visual_protocol.py`、`visual_wire.py` | Node 画面上传、页面目录与选择确认、PNG 分发和新鲜度 |
| `store.py` | SQLite schema 4 与旧数据迁移；节点、许可、会话、启动请求和指令元数据 |
| `native.py`、`body_limit.py` | 旧原生入口返回 410；请求体大小控制 |

`browser.py` 是 MCP 的项目方法适配层，不持有 Playwright Browser。Hub 包不安装 Playwright，也没有采集浏览器或回连自身 SDK 入口的进程。

## 一次调用如何完成

1. HTTP 或 MCP 入口解析访问令牌，确认节点、资源和会话归属。会话创建先预留资源，再通过当前代次的控制连接下发 `session_open`。
2. Node 建立独立执行 WS，返回真实工具版本和对象目录；Hub 确认 `session_ready` 后，Node 再用控制消息确认准备完成。
3. CommandService 校验已登记的方法和参数，按许可/会话/请求 ID 去重。队列中的动作下发前重新核对许可、租期和剩余预算。
4. Node 返回结构化结果或事件。Hub 校验输出合同、更新目录镜像和状态，将 JSON/PNG 交给调用方；不会执行传来的 Python 语句。
5. 释放、到期、撤销或失联进入关闭流程。只有 Node 确认实际清理 `COMPLETE` 后资源才恢复可用；`UNKNOWN` 保留隔离。

完整信封、33 项方法和状态限制见[工具协议](../reference/工具调用协议.md)。时序见[会话管理](Playwright执行与会话管理.md)。

## 哪些数据会保存

SQLite 保存身份/许可令牌的哈希和执行元数据；会话记录也包含对象目录镜像，例如页面 URL、引用和最近弹窗摘要。完整动作参数、上传和图片不落库。真实工具对象、活连接、队列和完整结果缓存属于当前进程；数据库中的旧引用不能在重启后继续使用，未确认动作标记未知，不重放。调用方需要保存自己的访问文件、请求 ID、业务断言和必要证据，不能依赖 Hub 充当测试账号或业务数据仓库。

新增工具时维护两端的版本化方法模型、能力声明和 Node 适配器。已有的鉴权、会话、队列与结果服务复用；当前只实现 `playwright`，没有其他工具运行时。
