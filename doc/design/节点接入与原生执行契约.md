# RunBridge 节点接入与原生执行契约

[文档导航](../README.md) · [节点服务范围与架构](节点服务范围与架构.md)

## 1. 最小公开合同

RunBridge Hub 与 RunBridge Node 共同提供访问许可、查询、资源使用和执行接入。合同只有本服务的节点、资源、访问许可与会话概念，不依赖调用方的业务数据。

| 能力 | 最小合同 |
| --- | --- |
| 节点访问 | 节点所有者生成对接凭据；服务器验证其节点/资源范围 |
| 查询 | 当前连接、工具版本、资源准备/占用、支持协议和限制 |
| 资源使用 | 申请、占用确认、原生端点或执行入口、释放 |
| 原生执行 | 尽量保留对应工具的参数、响应、事件和错误 |
| 输出 | 原生传输或可授权获取的文件引用 |
| 失败 | 区分认证、离线、占用、版本、能力限制、原生错误与连接中断 |

R1 的节点与能力查询、许可管理和控制连接已实现，精确字段见[R1 接口与控制协议](../reference/R1接口与控制协议.md)。受管理 Chromium 的执行会话与原生接入现已实现，精确合同见[会话接口](../reference/会话接口与原生连接.md)。R4 Chrome CDP 路线见[复用实现](../architecture/Chrome复用与授权清理.md)；HTTP、扩展和 Appium 内容仍属于设计。

## 2. 对接码与节点身份

建议首期使用足够长的安全随机访问凭据，绑定一个节点和所选资源；不必先做 OAuth 或完整账户系统。若提供易输入的短配对码，只用于短时一次性兑换，不能作为长期公开调用的唯一秘密。

Bearer 形式的凭据表示持有者拥有相应访问许可，不自动提供具体用户身份。服务地址/TLS 身份确认与服务器检查凭据分别处理。[RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html)

节点客户端另有自己的节点身份凭据，用于登记和重连。调用方的对接码不能用于接管客户端身份或覆盖现有节点登记。

服务器保存验证信息、范围和撤销状态；客户端保存其节点身份和配置。创建访问码时只向所有者展示秘密，查询与普通日志不回显原值。撤销许可后，不再允许新连接；已关联该许可的执行连接按约定关闭或停止。

首期支持单个节点所有者管理访问许可。多个调用方若共享同一码，其许可也共享；需要单独撤销时再生成不同许可，不因此引入额外业务账户模型。

## 3. 查询 API 和 CLI

```text
GET /v1/nodes/{node_id}
GET /v1/nodes/{node_id}/capabilities
GET /v1/sessions/{session_id}  # 已实现

runbridge-node inspect <node-id> --output json
```

真实节点和资源查询都需要对应许可。`runbridge-node` CLI 已提供 Hub HTTP API 的查询入口，使用同一 JSON 数据模型，诊断写 stderr；只做客户端工具，不成为另一套权威状态源。查询命令已通过真实 CLI 验收；执行会话 create/get/close 命令已实现，见当前会话参考。

| 查询内容 | 要求 |
| --- | --- |
| 节点 | 稳定 ID、在线/停用、连接代次、观察时间 |
| 后端 | 名称、实际版本、驱动/插件版本、协议模式 |
| 资源 | 授权可见的浏览器/设备标识、准备状态、占用 |
| 能力 | 原生协议覆盖或明确子集、限制与文档版本 |
| 会话 | 归属、当前技术状态、到期及错误/关闭原因 |

静态安装信息与动态可运行状态分开。没有实际探测结果时返回未知或待准备，不能根据安装目录存在宣称设备就绪。查询快照附观察时间，申请资源时重新确认。

CLI 凭据通过受控配置或凭据输入取得，不要求将秘密放进命令行参数、输出或工具描述。

## 4. 资源和会话

节点服务决定资源可否共享。首期手机和借用浏览器会话采用独占；受管理浏览器按实例占用。资源占用在服务器串行确认，客户端对真实资源再检查。

会话可以通过管理接口准备，也可结合原生协议的创建动作处理。选定一种明确方式：不要先替 Appium 创建原生 session，再让官方 SDK 重复创建一个。节点管理会话标识与原生 session/target 标识如果不同，映射由网关维护并在接口中说明。

调用方可传可选关联标识帮助排查，但其含义不参与节点的执行决策。首期无需保存通用业务任务或离线操作队列。

会话准备失败应释放本次占用，返回驱动原始原因。客户端重连后的新连接代次用于拒绝旧连接迟到的控制消息；数据库中的旧会话状态必须结合真实资源协调。

## 5. Playwright 执行面

受管理浏览器优先使用官方原生远程连接：节点运行 Node.js Playwright 浏览器服务，网关路由获授权的 WebSocket，调用方使用对应版本 SDK `connect()`。管理层负责启动配置、访问许可和资源归属，执行层保留对象、事件与方法参数。[Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype)、[Python 接入](https://playwright.dev/python/docs/api/class-browsertype)

不得逐 API 复制后声称全部能力原样保留。Browser、Context、Page、Locator、回调、事件、上传/下载和关闭行为都需要原型确认。将 native 载荷重新放入默认 Pydantic 模型可能丢参数，详见[技术栈可行性](Python3.14技术栈可行性.md)。

已有浏览器的 CDP/扩展模式单独声明。CDP 只适用 Chromium，兼容程度低于原生 Playwright 协议；扩展也不是完整浏览器级端点。允许查询返回部分支持，遇到不支持的能力明确拒绝，不能静默忽略参数。

原生端点的可访问能力可能较宽。授权应该对应实际浏览器实例/Profile 或已声明的页面范围；不能拿一个标签页选择 UI 就保证所有浏览器级方法都只作用于该页。

## 6. Appium 和 HTTP 执行面

Appium 保留原生 HTTP 方法、路径、capabilities、元素标识、响应与驱动扩展。代理层检查许可和目标设备；若请求参数与授权设备冲突，应明确拒绝，不静默改写为另一设备。[WebDriver Protocol](https://appium.io/docs/en/latest/reference/api/webdriver/)、[Appium Protocol](https://appium.io/docs/en/latest/reference/api/appium/)

Appium 本地服务不直接公开到互联网。受保护网关处理调用认证和对应会话路由；服务端未启用的扩展能力须如实声明，调用方不能自行改变主机的安全开关。[Appium 安全说明](https://appium.io/docs/en/latest/guides/security/)

HTTP 请求能力在节点发出请求，使用本机 DNS、代理、CA 和许可范围内的凭据配置。保留请求/响应的通用语义；大响应和文件说明输出位置。不为了 HTTP 能力自动读取整个浏览器凭据库。

## 7. 运行与错误语义

| 情况 | 服务承诺 |
| --- | --- |
| 参数或身份错误 | 本服务明确拒绝；错误原因不冒充驱动错误 |
| 资源被占用 | 返回忙碌/冲突，不让两个会话同时控制独占资源 |
| 原生方法错误 | 保留原生状态和错误内容 |
| 连接超时/中断 | 返回连接或执行结果未知；不自动重放有副作用操作 |
| 撤销、到期或停止 | 不接受新执行，尽力关闭连接/驱动会话，报告清理结果 |
| 服务器重启 | 原连接无效，资源重新报告与协调，不能靠记录复活对象 |

节点服务只报告技术事实，不推断操作是否满足调用者的业务目标。纯原生代理首期不提供每个动作的持久去重账本，也不承诺任意动作 exactly-once。

文件和事件尽量沿用原生行为。额外输出以授权的资源引用获取，注明哪一端持有文件、大小与保留时间；不预绑定某个调用者的数据库或对象存储。

## 8. 原生能力覆盖的验收

需要用官方 SDK 验证代表性对象链、定位参数、事件、文件、会话生命周期和原生错误；Appium 验证 capabilities/actions/已启用扩展。只有查询接口和 WebSocket 能连通，不能认定原生协议完整可用。

对高权限方法，按节点所有者和执行工具的许可处理并公布限制。二次封装由调用方选择，节点服务不因某一种调用方式方便而缩减底层公开能力。
