# Browser visual stream contract

[简体中文](浏览器画面流接口.md) · English · [Guide](../user-guide/浏览器画面流接入.en.md) · [Documentation](../README.en.md)

## Sources and versions

Node **0.8.2** managed mode captures the same Python worker Page approximately every 300 ms, independently of the action queue. `target_id` equals action `page_id`. Borrowed uses optional Browscreen and maps internal CDP targets to session Page references. Hub distributes frames; it holds no browser/capture connection.

HTTP- and MCP-created sessions can stream according to actual capabilities. A first command makes a session ACTIVE so uploads can be accepted; MCP start activates it with a read-only state operation. Visual protocol **1** is independent of execution protocol **2**.

Upload `hello.capture_backend` is `python-playwright` or `browscreen`. The former reports actual `runtime_version` and null `browscreen_version`; the latter reports its actual supported Browscreen version. Screenshot actions are limited to 2 MiB. Visual wire allows 4 MiB PNG, with current managed capture additionally limited to 2 MiB. Capture failure must not be advertised as LIVE.

## Queries

| Query | Visual fields |
| --- | --- |
| `GET /v1/nodes/{node_id}` | `visual.supported` and this lease's `visual.streams` |
| `GET /v1/nodes/{node_id}/capabilities` | Same visual information |
| `GET /v2/sessions/{session_id}` | The session's `visual` |

Use access Bearer authentication. A session query also requires its creating grant. Node stream lists include only active sessions belonging to this lease. `supported` declares capability, not live frames; inspect `capabilities_stale` for offline historical snapshots.

An active session declaring the protocol can return a path while waiting for a first frame or target selection. Unsupported/undeclared backend, offline Node, inactive/ended session leave no usable entry. No current active streams means `streams=[]`.

Illustrative session view:

```json
{
  "visual": {
    "supported": true,
    "state": "LIVE",
    "visual_protocol_version": 1,
    "transport": "websocket",
    "content_type": "image/png",
    "stream_path": "/v1/sessions/session_example/visual/stream",
    "target_id": "page_example",
    "targets": [{"target_id": "page_example", "label": "页面 1"}],
    "stream_id": "stream_example",
    "last_frame_id": 42,
    "capture_started_at": "2026-10-12T12:00:00Z",
    "frame_age_ms": 80,
    "reason_code": null,
    "selection": null
  }
}
```

Node-level stream entries additionally include `session_id` and `resource_id`. Queries contain no PNG, token, local listener, or CDP address. Visual fields are generated from current memory, not persistent records. Target labels currently use Chinese numbered labels.

## Read-only subscription

Connect to returned `stream_path`, currently `WS /v1/sessions/{session_id}/visual/stream`, with the valid creating lease. Convert the access-file HTTP(S) base to WS(S), preserve any deployment prefix, and append that returned path. Do not infer a new path from execution API version.

Clients supporting headers send `Authorization: Bearer <access_token>` during handshake. Browser clients without custom headers send this first message within five seconds:

```json
{"type":"auth","access_token":"REPLACE_WITH_PRIVATE_ACCESS_TOKEN"}
```

No target directory, state, or frames are sent before authentication. Query parameters are rejected. An invalid supplied header does not fall back to first-message authentication. Unauthorized/noncreator/unsubscribable sessions are rejected; after WebSocket acceptance, first-message rejection closes with 1008.

Subscription starts with text state, then a fresh cached frame if available, and subsequent updates:

```json
{"type":"state","visual":{"supported":true,"state":"WAITING","stream_path":"/v1/sessions/session_example/visual/stream"}}
```

Other VisualView fields are omitted above. Later state messages include targets, selection progress, errors, and freshness. After authentication, sending other application messages closes the read-only subscription. Multiple consumers share one source without taking the execution caller slot.

Binary layout:

```text
4-byte big-endian unsigned JSON length + UTF-8 JSON metadata + PNG bytes
```

Metadata: `visual_protocol_version`, `connection_generation`, `session_id`, `resource_id`, `stream_id`, `target_id`, `frame_id`, `capture_started_at`, `content_type`. Header limit: 4096 bytes; PNG limit: 4 MiB; content type: image/png. Remove the length/header before image decoding; the whole binary message is not raw PNG.

Frame IDs strictly increase within a stream. A new capture instance/target uses a new stream ID and may restart at 1. Ignore in-flight data from old targets/streams; intermediate frames may be dropped. No historical replay is provided. Session end, revocation, or expiry stops frames and closes subscriptions.

## Target selection

`PUT /v1/sessions/{session_id}/visual/target` uses the same access credential:

```json
{"target_id":"page_example"}
```

Choose from current `targets`. Labels do not expose real titles, URLs, or debug endpoints. A 202 response includes request_id, target_id, state, error_code; accepted selection is PENDING. Query/stream `selection` tracks progress. The first valid new frame confirms APPLIED; failure reports FAILED and a reason. Selection neither activates/operates a page nor changes instance authorization.

## States and errors

| State | Meaning |
| --- | --- |
| UNAVAILABLE | Missing declaration, unsupported backend, or unavailable Node |
| WAITING | Session activation/upload/page/first frame pending |
| WAITING_TARGET | Multiple pages need selection or selected page closed |
| LIVE | A fresh frame has actually arrived |
| STALE | More than five seconds without a new frame; remove old image |
| ERROR | Capture, upload, or selection failed |
| STOPPED | Session ended/closing; no entry |

| Error/condition | Behavior |
| --- | --- |
| INVALID_ACCESS_TOKEN / SESSION_OUTSIDE_GRANT | 401 / 403 |
| SESSION_NOT_ACTIVE / ended session | 409 before activation / 410 after end |
| UNSUPPORTED_BACKEND / EXTENSION_NOT_ADVERTISED | Reason and empty entry; ordinary execution remains |
| VISUAL_UPLOAD_NOT_READY / TARGET_SELECTION_PENDING | 409 |
| VISUAL_TARGET_NOT_FOUND | 404 |
| TARGET_SELECTION_TIMEOUT | No new target frame after 10 seconds; discard late confirmation |
| FRAME_STALE / TARGET_CLOSED | Clear the old image and update state |
| FRAME_TOO_LARGE / CAPTURE_FAILED / BROWSER_WAIT_TIMEOUT | Capture reports state; viewport is not automatically adjusted |
| STALE_SESSION / INVALID_GENERATION | Reject mismatched upload identity/session/generation |
| INVALID_VISUAL_MESSAGE | Close upload with 1008; this visual error does not itself change execution |

## Internal Node upload

`GET /v1/nodes/{node_id}/visual/support` uses Node identity and returns visual protocol version and header/PNG limits.

Node uploads at `WS /v1/nodes/{node_id}/sessions/{session_id}/visual/upload`, using Node Bearer and `x-runbridge-generation`, for the current ACTIVE session. Within five seconds, send `hello` with protocol 1, backend, and actual runtime/Browscreen version, followed by targets/state text and binary frames. Capture can declare WAITING, WAITING_TARGET, or ERROR; Hub declares LIVE only after receiving a frame.

Accepted stable Browscreen range is `>=0.3.1,<0.4.0`, excluding prereleases under Python distribution-version rules. Thus 0.3.1/0.3.2/0.3.10 satisfy the range; 0.3.0/0.4.0/0.3.2rc1 do not. Invalid versions close visual upload with INVALID_VISUAL_MESSAGE while execution continues. Recorded live acceptance is on 0.3.1; accepted version range is not live-test evidence for every later release.

```json
{
  "type": "hello",
  "visual_protocol_version": 1,
  "capture_backend": "browscreen",
  "runtime_version": null,
  "browscreen_version": "0.3.1"
}
```

Managed hello instead uses `capture_backend=python-playwright`, actual runtime version, and null Browscreen version. Hub sends `select_target` through this channel. It accepts no arbitrary CDP, mouse, keyboard, or navigation commands. Control and execution use protocol 2, not historical SDK tunnel messages.

Strict clients must use expanded NodeQueryView/SessionQueryView models for added fields. New query models allow missing visual data when talking to older Hub. Creation/close responses remain basic SessionView. Implementation details are in the [capture architecture (Chinese)](../architecture/浏览器画面采集与分发.md).
