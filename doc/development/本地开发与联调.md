# Hub 本地开发与联调

[文档导航](../README.md) · [用户部署指南](../deployment/部署与运行.md)

本文面向维护 Hub 的开发者。源码安装、构建、测试及同一电脑同时启动 Hub／Node 都属于开发调试。用户发布包部署使用独立服务器和远程节点，按部署指南操作。

## 1. 准备 Hub 源码环境

在 Hub 源码根目录：

```bash
uv sync --locked --extra mcp --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv run --locked --no-sync runbridge-hub --help
```

使用项目根目录 .venv 和 uv.lock。MCP 开发需要 extra；只研究基础服务时可不选择它。依赖同步使用约定镜像，服务运行使用 --no-sync 保留已准备的依赖。

## 2. 在开发机同时启动 Hub 和 Node

前提：本机有相邻的 runbridge-hub、runbridge-node 两个源码目录，各自有独立 .venv。这里的 127.0.0.1 仅用于这个同机开发场景。

终端 A，在 Hub 根目录首次生成调试登记文件并启动：

```bash
uv run --locked --no-sync runbridge-hub generate-token --output .runbridge/dev-enrollment.token
uv run --locked --no-sync runbridge-hub serve --host 127.0.0.1 --port 8787 --db-path .runbridge/dev-hub.sqlite3 --enrollment-token-file .runbridge/dev-enrollment.token --enable-mcp
```

已有文件时跳过生成，避免覆盖正常部署的数据。终端 B，在 Node 根目录：

```bash
uv sync --locked --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv run --locked --no-sync runbridge-node register --hub-url http://127.0.0.1:8787 --enrollment-token-file ../runbridge-hub/.runbridge/dev-enrollment.token --config .runbridge/dev-node.json --name dev-node
uv run --locked --no-sync runbridge-node prepare-playwright --runtime-dir .runbridge/playwright
cp -n doc/reference/examples/Playwright节点配置.json .runbridge/dev-playwright.json
uv run --locked --no-sync runbridge-node run --config .runbridge/dev-node.json --playwright-config .runbridge/dev-playwright.json
```

Node 设备需已准备 Node.js／npm 和浏览器库。另一个 Node 终端：

```bash
uv run --locked --no-sync runbridge-node grant --config .runbridge/dev-node.json --resource-id chromium --expires-in 3600 --output .runbridge/dev-access.json
uv run --locked --no-sync runbridge-node inspect node_example --access-file .runbridge/dev-access.json
```

替换真实节点 ID。调用方样例按 Hub 用户指南复制到独立目录，或使用 Node 开发区的联调脚本。此开发流程不要用于替代远程部署配置。

## 3. 构建并交付 Hub 包

在 Hub 根目录：

```bash
uv build -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv export --locked --no-dev --extra mcp --no-emit-project --no-hashes --format requirements-txt --output-file deploy-constraints.txt
```

当前 wheel 为 dist/runbridge_hub-0.5.1-py3-none-any.whl；基础服务约束导出可省略 extra。交付当前项目的 wheel、对应依赖约束和文档包，不要求用户克隆源码或自己构建。

## 4. 回归与真实浏览器验证

普通回归：

```bash
uv run --locked --no-sync pytest -q
```

真实 MCP 联调需准备相邻 Node 的环境和运行时，再显式启用：

```bash
RUNBRIDGE_RUN_BROWSER_TESTS=1 uv run --locked --no-sync pytest -q tests/test_mcp_live.py
```

测试支持 RUNBRIDGE_NODE_PROJECT、RUNBRIDGE_PLAYWRIGHT_RUNTIME 和 RUNBRIDGE_MCP_EVIDENCE_FILE 指定目录和脱敏证据。临时 Hub、Node、网页和浏览器由夹具拥有并回收；真实测试不代替部署目标的公网 TLS／容量验收。

当前机器专属配置、脚本、日志和证据集中放在 Git 忽略的 local/，入口 local/README.md。维护时保留身份和非本次所有的进程。
