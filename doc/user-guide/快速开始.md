# Hub 快速开始

简体中文 · [English](快速开始.en.md)

从 GitHub 源码直接体验，请先按[项目首页](../../README.md#快速开始)安装。本文说明已有 wheel 的独立目录部署，后续配置、验证和交付流程相同。

目标是在 Hub 机器上完成“安装 → 保存启动配置 → 运行 → 检查 → 交付登记材料”。Node 接入后，再验证一次浏览器访问、页面读取和截图。适用于 **0.9.3**；本文不包含 Node 的部署步骤。

## 开始前

- 已具备 Python **3.14.x**、全局 uv 和可供 Node 访问的网络。基础工具准备参考 [Python](https://www.python.org/downloads/)及 [uv](https://docs.astral.sh/uv/getting-started/installation/)官网。
- 已从发布负责人取得 `runbridge_hub-0.9.3-py3-none-any.whl`，保存到 `~/Downloads/`。wheel 是发布包，不是 Git 源码；源码构建在[开发手册](../development/本地开发与联调.md)中。
- 以下命令使用 macOS/Linux 路径，在新的 `~/runbridge-hub` 目录操作。已有部署继续使用原数据库和令牌，不要用快速体验覆盖它们。

## 安装并生成登记文件

```bash
mkdir -p ~/runbridge-hub
cd ~/runbridge-hub
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python ~/Downloads/runbridge_hub-0.9.3-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
.venv/bin/runbridge-hub generate-token --output .runbridge/hub.token
```

成功提示“凭据文件已保存”。生成的 `enrollment.token` 是 UTF-8 单行随机文本，通常为 64 字符，不含 JSON、引号或 `Bearer `。**这就是要交给 Node 所有者的登记附件**，不用再手工创建另一个文件。目录权限为 `700`、文件为 `600`，生成器拒绝覆盖已有文件。

## 保存配置并启动

在部署目录创建 `hub.yaml`，写入：

```yaml
host: 0.0.0.0  # 允许其他设备的 Node 连接；仅供本机访问时可省略。
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787  # 改为 Node 和调用方实际可达的 Hub 基址。
```

端口默认 `8787`，数据库默认 `.runbridge/hub.sqlite3`，其余参数保持默认。YAML 中相对路径以 **hub.yaml 所在目录**为基准；不用填写默认端口、默认数据库或 MCP Host。

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

前台出现 Uvicorn 启动日志后保留终端。启动失败时先看错误，不能只凭窗口未退出就认为可用。完整注释见 [Hub启动配置.yaml](../reference/examples/Hub启动配置.yaml)，每个参数的场景见[参数详解](../reference/参数详解.md)。

节点总览默认开启。点击启动日志中带口令的 `Dashboard URL` 可直接进入，刷新无需重复填写；页面每 5 秒更新连接、资源占用、能力和实测 RTT。尚未登记 Node 时列表为空是正常状态；Node 上线后自动显示真实数据。日志的回环地址用于 Hub 本机，远程查看时换成实际 Hub 主机名。独立口令、手动登录及关闭方式见[节点总览](节点总览.md)。

## 确认 Hub 已可用并交付材料

另开终端，在 Hub 本机检查：

```bash
curl --fail http://127.0.0.1:8787/health
```

应返回：

```json
{"status":"ok","protocol_version":2}
```

这表示 Hub 服务可用，尚不代表远程浏览器已就绪。健康接口不返回安装版本；需要确认时运行 `.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'`，应为 `0.9.3`。

把以下内容私密交给 Node 所有者：

| 材料 | 填写方式 |
| --- | --- |
| Hub 基址 | 如 `http://192.168.50.10:8787`，换成从 Node 可达的实际地址或可解析主机名 |
| 登记附件 | 上一步真实生成的 `.runbridge/enrollment.token` 文件 |
| 版本与手册 | Hub 0.9.3，兼容 Node 0.8.2；Node 发布包及 Node 项目的部署手册由发布负责人提供 |
| MCP 信息（如启用） | 实际 `/mcp` 地址，供后续调用方使用 |

`0.0.0.0` 只用于监听，不能作为交付地址；Node 设备上的 `127.0.0.1` 指 Node 自己。基址不要带 `/health`、`/v2` 或 `/mcp`。请 Node 所有者从其机器访问同一基址的 `/health`，再按 Node 手册上线。

## 启用 MCP（按需）

普通 HTTP 调用可以跳过本节。需要 Agent/MCP 时，先停止本次 Hub，在同一部署环境补充 extra：

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_hub-0.9.3-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

在原 `hub.yaml` 增加一行 `mcp_enabled: true`，再用原命令启动。**默认不限制 MCP 的 Host，本机和远程客户端均无需配置 Host 列表。**

只有需要限制入口地址时，才填写允许列表，例如：

```yaml
mcp_enabled: true
mcp_allowed_hosts:
  - "hub.example:8787"  # 对应 http://hub.example:8787/mcp；替换为实际可解析名称。
```

省略该列表或设为 `[]` 时允许所有 Host；列表非空时只允许所列地址，不额外加入本机地址。列表填写 MCP URL 的 Host，不填写 Node IP 或调用方 IP；主机名需要已有 DNS 解析。普通 MCP 客户端通常不发送 Origin，无需填写 `mcp_allowed_origins`。

MCP 地址的 HTTP 可达不代表鉴权通过；真正调用要使用 从Hub领取产生的访问令牌，见 [MCP 接入](MCP浏览器接入.md)。

## 验证一次完整调用（Node 接入后）

先按[调用教程](调用方对接与使用.md#1-从-hub-领取-node-使用权)使用Hub申请凭据领取Node并保存真实 `access.json`，确认资源 `chromium` 为 managed 且 READY/FREE。将访问文件保存为 Hub 部署目录下的 `.runbridge/access.json`，并将文档包中的[执行会话调用.py](../reference/examples/执行会话调用.py)保存到部署目录。脚本只使用 Python 标准库。

```bash
cd ~/runbridge-hub
chmod 600 .runbridge/access.json
rb_check_url=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/access.json").read_text())["hub_url"].rstrip("/") + "/health")')
.venv/bin/python 执行会话调用.py --access-file .runbridge/access.json --url "$rb_check_url"
```

命令从访问文件取得真实 Hub 基址，并让 Node 浏览器打开其 `/health` 页面，不依赖外部网站。示例使用默认资源 `chromium`，自动创建会话、导航、读取标题、保存 `page.png` 并释放会话。项目只接受 HTTP/HTTPS 导航，不使用 `data:` 或本机文件页面。

成功时输出的 `url` 是实际 Hub 健康页、`cleanup` 为 `COMPLETE`，部署目录生成 `page.png`。打开图片应能看到 `{"status":"ok","protocol_version":2}`。健康页是 JSON，`title` 为空字符串是正常现象。这里同时验证了访问鉴权、Hub 到 Node 的指令传递、实际浏览器执行、结果返回和清理。资源 ID 不同则增加 `--resource-id 实际资源ID`；borrowed 操作另见[调用方教程](调用方对接与使用.md)。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `uv`、Python 或 `.venv/bin/runbridge-hub` 不存在 | 核对基础环境要求、当前目录及本次 wheel 安装结果；不要调用另一目录的虚拟环境 |
| 令牌文件已存在 | 已部署时继续使用原文件；全新体验选择另一个独立目录，不删除原令牌 |
| YAML 配置失败或文件找不到 | 使用空格缩进；路径相对 YAML 目录；不展开 `~`、`$HOME`；字段名查[参数详解](../reference/参数详解.md) |
| 提示不能混用启动参数 | 使用 `--settings` 时把端口、监听地址等统一写入 YAML，不在命令后追加 |
| 端口被占用 | 检查是否已有自己启动的 Hub；需要独立实例时在 YAML 设置另一 `port`，并同步交付基址 |
| 本机 health 成功，Node 设备失败 | 确认 YAML 有 `host: 0.0.0.0`、交付实际地址，并检查网络、防火墙与代理 |
| 登记返回 401 | Node 必须使用 Hub 当前读取的同一份真实登记文件；重新生成不同令牌不会匹配 |
| MCP 返回 404 / 421 | 404 检查 extra 和 `mcp_enabled`；421 检查已配置的非空 Host 列表，省略或 `[]` 不限制 Host |
| MCP 返回 401 / 403 | 401 检查访问文件是否过期或撤销；403 还需检查资源范围，有 Origin 的请求需匹配允许列表 |
| 调用失败但 health 正常 | 请 Node 所有者确认 ONLINE、非 stale、资源 READY/FREE；health 不检查浏览器 |
| 动作超时或结果未知 | 保留会话 ID、请求 ID，查询原请求并核对业务结果，避免重新提交造成重复动作 |
| 总览 404 / 口令无效 | 确认安装的是 Hub 0.9.3、未关闭 Web；使用本次启动日志中的 Dashboard URL 或独立只读口令，不能使用登记令牌或 access.json |

正常停止使用原终端 Ctrl+C；重启使用同一 YAML、数据库和登记文件。长期运行与备份见[部署手册](../deployment/部署与运行.md)，更多错误与升级说明见[运行与排障](../deployment/运行与排障.md)。

测试完成后还需使用原访问文件运行node_lease.py release，确认Node租约RELEASED；关闭会话不会自动交还Node。Hub部署者另向调用方交付hub.token与public_url，登记附件仅供Node使用。
