# 对外接口总览

[文档导航](../README.md) · [调用方指南](../user-guide/调用方对接与使用.md) · [会话参考](会话接口与原生连接.md) · [画面参考](浏览器画面流接口.md)

本文件对应 Hub 0.5.1 / Node 0.5.0。Hub 提供 RunBridge 管理接口、官方浏览器执行协议入口、独立画面协议入口和可选 MCP 工具入口；同一个服务端地址不表示这些入口都属于 Playwright 协议。

## 调用方使用的接口

| 方法与路径 | 合同/返回 | 用途 |
| --- | --- | --- |
| GET /health | RunBridge JSON，无需凭据 | 检查 Hub 健康 |
| /mcp（以 POST 为主） | MCP Streamable HTTP，需 `mcp` extra 与 `--enable-mcp` | 访问许可授权的 26 个工具，见 [工具合同](../user-guide/MCP浏览器接入.md) |
| GET /v1/nodes/{node_id} | NodeQueryView | 在线状态、能力、资源和 visual |
| GET /v1/nodes/{node_id}/capabilities | 与节点查询相同 | 能力查询别名 |
| POST /v1/nodes/{node_id}/sessions | 201 SessionView | 申请一个独占资源位，等待准备完成 |
| GET /v1/sessions/{session_id} | SessionQueryView | 状态、执行入口及临时画面信息 |
| DELETE /v1/sessions/{session_id} | 200 SessionView | 幂等释放，并检查实际 cleanup |
| WS /v1/sessions/{session_id}/playwright | 官方 Playwright 原生协议 | 使用 chromium.connect() 操作受管理 Chromium |
| WS /v1/sessions/{session_id}/cdp | Chromium CDP | 使用 chromium.connect_over_cdp() 复用已有 Chrome |
| WS /v1/sessions/{session_id}/visual/stream | RunBridge visual v1 | 只读订阅状态和 PNG |
| PUT /v1/sessions/{session_id}/visual/target | 202 VisualSelection | 请求选择采集页，后续等待实际结果 |

除 /health 外，这些调用方入口需要有效的访问许可。会话、执行和画面还要求与创建会话的 grant_id 相同。Authorization 请求头为 Bearer 访问令牌；浏览器原生 WebSocket 无法自定义请求头时，画面订阅可在连接后的首条消息认证。原生执行入口没有首消息认证替代方式，应使用官方 SDK 的 headers 参数。

## 官方协议的范围

受管理模式由 Node 调用公开 chromium.launchServer() 启动服务，Hub 转发原生文本/二进制消息；原生调用方直接使用官方 Browser/Context/Page/Locator。MCP 工具层在 Hub 内调用同一 SDK，通过原生入口访问 Node，不增加 Node 自定义 click/goto 协议。SDK 与服务的主、次版本必须匹配。[官方 connect](https://playwright.dev/python/docs/api/class-browsertype#browser-type-connect)

已有 Chrome 模式转发本机固定实例的 CDP，官方 SDK 使用 connect_over_cdp()。这条路径与 Playwright 原生连接的能力覆盖不同，尤其高级功能需要分别验证。[官方 CDP 接口](https://playwright.dev/python/docs/api/class-browsertype#browser-type-connect-over-cdp)

Hub 仍做授权、租期、版本和 Chromium 类型校验。两个原生入口当前都检查官方 Playwright SDK 的 User-Agent 与声明版本，普通 WebSocket 工具只提交 Bearer 不能替代 SDK 接入。借用模式还拒绝 Browser.close、Browser.crash、Target.sendMessageToTarget，保护所有者浏览器；SDK browser.close() 释放的是连接。不能把它称为不受限制的通用浏览器代理。

## 查询如何发现执行和画面入口

| 查询字段 | 如何使用 |
| --- | --- |
| node.connection_status、capabilities_stale | 确认节点在线，避免使用离线历史能力 |
| capabilities.resources | 使用实际 resource_id、readiness、occupancy 和 backend |
| session.native_protocol / native_path | 按返回值选择官方连接方式，并构造 WS/WSS 地址 |
| node.visual.supported / streams | 是否声明支持画面，以及当前许可创建的活动流 |
| session.visual.state / stream_path | 当前画面状态与单个会话的订阅路径 |
| session.visual.targets / selection | 页面 ID、选择请求与实际进度 |

查询返回入口与状态，不把 PNG 内嵌进 JSON。ACTIVE 会话即使等待首帧或选择目标，也可有 stream_path；LIVE 由 Hub 收到新鲜帧确认。结束或不可用时路径为空。PNG 通过独立 WebSocket 传输，官方 SDK 不会自动订阅它。

HTTP(S) 的 Hub 基址转换为 WS(S)，保留既有路径前缀，再拼接查询返回的路径。例如基址 https://gateway.example/runbridge 与 native_path=/v1/sessions/session_example/cdp 组合为 wss://gateway.example/runbridge/v1/sessions/session_example/cdp。反向代理需把这个前缀映射到 Hub 原有路由。

## 所有者及 Node 内部入口

| 路径 | 凭据 | 调用者 |
| --- | --- | --- |
| POST /v1/nodes/register | 登记凭据 | Node 首次登记 |
| POST/GET /v1/nodes/{node_id}/grants | Node 身份 | 所有者签发/查询许可 |
| DELETE /v1/nodes/{node_id}/grants/{grant_id} | Node 身份 | 所有者撤销许可 |
| WS /v1/nodes/{node_id}/control | Node 身份 | Node 控制连接、心跳和报告 |
| WS /v1/nodes/{node_id}/sessions/{session_id}/tunnel | Node 身份及当前代次 | Node 出站执行隧道 |
| GET /v1/nodes/{node_id}/visual/support | Node 身份 | Node 画面合同探测 |
| WS /v1/nodes/{node_id}/sessions/{session_id}/visual/upload | Node 身份及当前代次 | Node 上传画面 |

普通调用方不建立 control、tunnel 或 upload，也不需要 Node 身份文件。Hub 没有浏览器展示页面、固定帧率视频播放入口或外部鼠标输入接口。

FastAPI 默认还提供 /docs、/redoc 和 /openapi.json，便于查看 HTTP 接口；WebSocket 合同按本项目参考文档读取。这些是接口文档入口，不是浏览器画面展示页。

字段、限制与错误码分别见[R1 参考](R1接口与控制协议.md)、[会话参考](会话接口与原生连接.md)、[画面参考](浏览器画面流接口.md)。
