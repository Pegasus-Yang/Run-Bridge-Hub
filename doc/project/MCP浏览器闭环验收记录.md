# MCP 浏览器闭环验收记录

[文档导航](../README.md) · [MCP 接入](../user-guide/MCP浏览器接入.md) · [当前时序](../architecture/MCP授权与浏览器生命周期.md) · [脱敏运行证据](../reference/MCP浏览器运行核验记录.json)

验收日期：2026-10-13。实现基于 Hub/Node 0.4.0 工作树，本记录不表示已经发布新的发行版本。测试环境为 macOS 26.6.2 arm64、Python 3.14.7、MCP SDK 2.3.0、Playwright 1.63.0。Hub、Node、网页服务和 MCP 客户端是独立进程/服务；网络使用本机 HTTP/WebSocket。

## 1. 本次交付

- Hub 可选 `mcp` extra 与 `/mcp` 入口，默认关闭；CLI 支持内部原生地址及 Host/Origin 允许列表。
- 每次 MCP HTTP 请求使用 `access_token` 认证，复用 grant 的节点、资源、到期、撤销与会话归属规则。
- 12 个工具覆盖节点查询、启动、会话列表/状态、导航、快照、填写、点击、等待、读取、截图和释放。
- Hub 的 Playwright SDK 经现有原生隧道操作 Node 自建 Chromium；Node 运行代码、数据库合同和控制协议保持原有实现。
- 同会话操作串行，取得锁后复核授权；停止和撤销可以中断正在等待及排队的工具。
- 启动失败/取消请求清理；写动作超时标记 `OUTCOME_UNKNOWN`，不自动重放；清理状态来自 Node 实际报告。

## 3. 业务结果与清理证据

测试网页的 HTTP 服务独立记录收到的提交。两种协议模式各提交一次，服务端收到的用户名与页面显示的“已保存”结果一致；测试也确认网页请求没有携带 RunBridge Authorization。不是仅用点击成功判定业务通过。

截图为真实 Chromium 生成的 1280×720 PNG，中文标签与结果可读：

![真实 MCP 表单填写并提交后的页面](../reference/MCP浏览器页面验证.png)

正常结束同时检查：

1. `browser_stop` 返回 `CLOSED` 与 `cleanup=COMPLETE`。
2. 本次拥有的浏览器 PID 已退出。
3. 本次 `browser-*` 专用临时目录已经删除。
4. Node 仍 `ONLINE`，资源恢复 `READY/FREE`，可申请下一次会话。

测试全部使用临时数据库、节点身份、grant 和网页。没有连接用户既有浏览器、读取已有登录或修改用户服务配置。进程日志检查没有发现测试凭据，也没有未处理异常。

## 4. 验收中修正的问题

首次联调发现，MCP 关闭回调同时调用 SDK `browser.close()` 与关闭原生隧道时，偶发把正常释放报告为 `NATIVE_CONNECTION_LOST`。现改为先由现有会话服务关闭路由并触发 Node 清理，收到报告或清理超时后再回收 SDK 句柄。保留真实错误与 UNKNOWN 语义，没有通过忽略 Node 错误让测试通过。

原生回归另发现 Node 的旧测试仍从 `Playwright快速开始.md` 提取已移走的内嵌 Python 代码。该指南已经指向独立 `执行会话调用.py`；测试现执行这个实际文档入口，并继续检查页面标题、截图与 COMPLETE。Node 运行代码没有因此改变。
