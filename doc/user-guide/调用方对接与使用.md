# Hub 调用方：完成第一次浏览器连接

[文档导航](../README.md) · [公开接口参考](../reference/对外接口总览.md) · [示例文件说明](../reference/examples/README.md)

本文带脚本、平台或服务的接入者完成一次“读取许可 → 查询资源 → 连接浏览器 → 截图 → 释放”的操作。Hub 和 Node 已由各自部署者运行；你在自己的电脑或服务机器上准备调用环境，不需要启动两端程序。

使用 MCP 工具的 Agent 用户可直接读 [MCP 浏览器接入](MCP浏览器接入.md)。本页使用官方 Python Playwright SDK，适配 Hub 0.5.1。

## 1. 从 Node 所有者取得访问资料

开始前拿齐：

| 材料 | 来源和用途 |
| --- | --- |
| 真实 `access.json` | Node 所有者运行 `grant` 自动生成并私下交给你；不能使用文档的演示令牌 |
| 资源 ID | Node 所有者另外告知，通常为 `chromium` 或 `chrome`；JSON 文件中没有此字段 |
| 浏览器模式 | 受管理 Chromium，或已有 Chrome，决定下面选择哪条执行命令 |
| 已打开页面的精确 URL，仅已有 Chrome | 由 Node 所有者告知；示例根据它查找已有页面 |
| Hub 文档及示例包 | 发布负责人提供，本项目 `doc/reference/examples/` 中的脚本；wheel 内不包含示例 |

访问 JSON 的完整格式如下，仅用于认识字段：

```json
{
  "hub_url": "http://192.168.50.10:8787",
  "node_id": "node_11111111111111111111111111111111",
  "grant_id": "grant_22222222222222222222222222222222",
  "access_token": "EXAMPLE_ONLY_ACCESS_TOKEN_DO_NOT_USE_00000000000000000000000000000",
  "expires_at": "2030-01-01T01:00:00Z"
}
```

`hub_url` 是远程 Hub 基址；`node_id` 指定许可所属设备；`grant_id` 用于所有者撤销许可；`access_token` 是实际接口凭据；`expires_at` 是到期时间。实际文件中的值由签发过程生成。不要手工替换 ID、修改期限，或往其中加入资源列表。

把收到的真实文件先保存为 `~/Downloads/access.json`。如果对方只给了登记文本 `enrollment.token` 或设备身份 `node.json`，请其重新提供**调用方访问文件**，它们不能互相替代。

本教程约定：将 Hub 文档包解压后，含 `README.md`、`doc/` 的那层目录命名为 `runbridge-hub-docs`，放在 `~/Downloads/`。这样下面的复制命令可以直接使用。文档包可以来自发布者提供的项目资料，无需安装 Hub 源码依赖。

## 2. 建立自己的调用目录

先运行 `uv --version`。没有 uv 时按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)安装，已装则复用。

在**调用方设备终端**执行：

```bash
mkdir -p ~/runbridge-client
cd ~/runbridge-client
umask 077
mkdir -p .runbridge examples artifacts
chmod 700 .runbridge
uv venv --python 3.14 --no-python-downloads .venv
uv pip install --python .venv/bin/python 'playwright==1.63.0' 'httpx>=0.28,<1' 'websockets>=15,<18' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

已有有效 `.venv` 时跳过环境创建。这里只安装客户端 SDK，浏览器在远程 Node 上，不需要在调用方执行 `playwright install`。

复制收到的访问文件和示例：

```bash
cp -n ~/Downloads/access.json .runbridge/access.json
chmod 600 .runbridge/access.json
cp -n ~/Downloads/runbridge-hub-docs/doc/reference/examples/执行会话调用.py examples/
cp -n ~/Downloads/runbridge-hub-docs/doc/reference/examples/画面流订阅.py examples/
cp -n ~/Downloads/runbridge-hub-docs/doc/reference/examples/画面查看示例.html examples/
.venv/bin/python -m json.tool .runbridge/access.json > /dev/null
.venv/bin/python examples/执行会话调用.py --help
```

`cp -n` 不覆盖已有文件。若文档包在其他目录，修改复制命令中的源路径；若文件不存在，先找到文档包中的同名文件，不要新建一个空脚本。JSON 检查不输出令牌；格式错误时向提供方核对原文件。

现在目录应包含：

```text
~/runbridge-client/
├── .venv/                         # 本调用方的 SDK 环境
├── .runbridge/access.json         # 私有调用凭据
├── examples/
│   ├── 执行会话调用.py
│   ├── 画面流订阅.py
│   └── 画面查看示例.html
└── artifacts/                     # 截图和画面输出
```

后续每个新终端先执行 `cd ~/runbridge-client`。

## 3. 查询实际节点和资源

下面的整段命令直接读取访问文件，查询对应节点；无需你手抄 URL、Node ID 或令牌：

```bash
.venv/bin/python - <<'PYCODE'
import json
from pathlib import Path

import httpx

access = json.loads(Path(".runbridge/access.json").read_text(encoding="utf-8"))
response = httpx.get(
    url=f"{access['hub_url'].rstrip('/')}/v1/nodes/{access['node_id']}",
    headers={"Authorization": f"Bearer {access['access_token']}"},
    timeout=15,
)
response.raise_for_status()
print(json.dumps(response.json(), ensure_ascii=False, indent=2))
PYCODE
```

核对返回值：

| 位置 | 应看到什么 |
| --- | --- |
| `connection_status` | `ONLINE` |
| `capabilities_stale` | `false` |
| `capabilities.resources` | 找到所有者告知的资源 ID，不根据浏览器名称猜 ID |
| 该资源的 `readiness`／`occupancy` | `READY`／`FREE` |

这些字段说明当前可申请资源，尚未执行网页。返回 401 时先确认许可未过期或撤销；OFFLINE／UNAVAILABLE 时联系 Node 所有者，不能用重建本地 access.json 修复远程状态。

## 4. 跑一次连接、截图和释放

按收到的浏览器模式，只选择一条命令。示例会自行申请会话，不需要预先手工创建一个 READY 会话。

### 受管理 Chromium

资源 ID 若为默认 `chromium`：

```bash
.venv/bin/python examples/执行会话调用.py --access-file .runbridge/access.json --resource-id chromium --screenshot artifacts/managed.png
```

脚本在远端新建浏览器，打开内置 data 页面，因此这次连接检查不依赖业务网站或外网。成功会按顺序输出类似以下三行；这里只展示关键字段，实际会话 ID 每次不同，第二行还包含 visual 画面信息：

```jsonl
{"session_id":"session_example","state":"READY","native_protocol":"playwright"}
{"session_id":"session_example","state":"ACTIVE","title":"RunBridge"}
{"session_id":"session_example","state":"CLOSED","cleanup":"COMPLETE"}
```

这些是分行日志，不是一整个 JSON 文件。`artifacts/managed.png` 应能在调用方设备打开，内容为示例页面。需要测试业务网站时加 `--url 'https://你的实际业务地址/'`，该地址必须从 Node 浏览器网络可达。

### 已有 Chrome

把下面 URL 替换为 Node 所有者交付的**已打开页面的精确 URL**：

```bash
.venv/bin/python examples/执行会话调用.py --access-file .runbridge/access.json --resource-id chrome --page-url 'https://your-test-system.example/account' --screenshot artifacts/chrome.png
```

脚本使用授权实例的已有 contexts/pages，不导航原页面。零个或多个页面匹配都会报错并释放会话；由所有者确认页面仍在并提供唯一目标，而不是随意改调试端点。

第一行协议应为 `cdp`，第二行是该页面实际标题，最后同样检查 CLOSED／COMPLETE。截图是读取原页面的结果，不代表其业务流程通过。

### 参数都从哪里来

| 参数 | 来源和含义 |
| --- | --- |
| `--access-file` | 第 2 节保存的真实访问 JSON |
| `--resource-id` | 所有者交付的资源 ID，须与许可范围一致 |
| `--screenshot` | 调用方本机输出路径，不是 Node 机器的目录 |
| `--page-url` | 仅已有 Chrome 使用，由所有者确认的已有页面 URL |
| `--url` | 受管理浏览器要打开的地址；不设置时使用内置示例页 |
| `--lease-seconds` | 会话租期，默认 300 秒，范围 1～3600，不超过许可期限 |
| `--hold-seconds` | 默认 0，示例结束就释放；设置为 60 可在租期内保持连接供另一终端看画面 |

看到 ACTIVE 说明原生连接已建立，看到 PNG 说明截图保存成功，cleanup=COMPLETE 说明相应资源清理已确认。三者分别核对，业务结果还需你自己的断言。

## 5. 接入自己的业务动作

打开复制到 `examples/执行会话调用.py` 的文件，定位注释“实际业务动作与断言放在这里”。该处已经取得 `page`，可增加官方 Page／Locator 操作，例如：

```python
from playwright.async_api import expect

await page.get_by_role(role="textbox", name="内容").fill(value="测试内容")
await page.get_by_role(role="button", name="提交").click()
await expect(page.locator(selector="#result")).to_have_text(expected="测试内容")
```

这是插入现有异步函数的片段，不能单独粘贴到 shell 运行。定位和断言必须按真实网页修改，保留脚本已有的 finally 释放流程。已有 Chrome 的动作会改变原页面，断开连接不会回滚业务操作。

自己实现客户端时，创建会话的 HTTP 等待时间要大于 Node 的 30 秒准备等待，现有脚本使用 40 秒；SDK 连接使用返回的 `native_protocol/native_path`，不连接 Node 本机调试端点。精确 HTTP 请求和状态合同见[会话接口](../reference/会话接口与原生连接.md)。

## 6. 后续查询、画面与常见中断

运行日志中的 `session_id` 是本次会话的标识，不是 `node_id` 或 `grant_id`。要查询或释放该会话，必须使用**创建它的同一份访问许可**；HTTP 请求路径和例子见会话参考。原生连接已结束时，不能靠重新使用旧 ID 恢复 SDK 对象。

需要持续看画面时，先阅读[画面流接入](浏览器画面流接入.md)。它说明两个终端的操作顺序：执行脚本加 `--hold-seconds 60`，记录 ACTIVE 会话 ID，第二终端订阅。普通 SDK 受管理会话没有独立画面流；已有 Chrome 需要所有者启用采集。

调用失败时，先看错误发生在哪一层：

| 现象 | 下一步 |
| --- | --- |
| 文件不存在或 JSON 格式错 | 回到第 1～2 节，核对文件来源和保存路径 |
| 401／INVALID_ACCESS_TOKEN | 让所有者确认到期、撤销和文件是否正确 |
| 没有对应资源／资源未就绪 | 让所有者核对资源 ID、许可范围和实际浏览器 |
| RESOURCE_BUSY | 等待原任务结束，确认其 cleanup，勿重复抢占 |
| Chrome 页面没有唯一匹配 | 由所有者确认当前已打开页面的精确 URL |
| 网络断线／动作超时 | 先确认网页业务效果和会话清理，不自动重放提交 |
| cleanup 为 PENDING／UNKNOWN | 继续查询并由所有者核查，不当作已回收 |

完整故障说明见[运行与排障](../deployment/运行与排障.md)。
