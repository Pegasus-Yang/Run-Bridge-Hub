# 浏览器画面流接入

[文档导航](../README.md) · [Chrome 准备](Chrome复用快速开始.md) · [调用方使用](调用方对接与使用.md) · [接口合同](../reference/浏览器画面流接口.md)
## 受管理 MCP 页面的持续画面（0.5.0）

Hub 安装 `mcp` extra，Node 使用 0.5.0 和官方 Playwright 1.63.0 后，启动探测会用专用页面验证 CDP PNG，并声明 `host.managed_visual=cdp-png`。探测失败不虚报画面能力。MCP `browser_start` 创建的页面由 Hub 的同一 Playwright 连接持有；Hub 对该 Page 建立 CDPSession，约 300 毫秒采集一次，独立于页面操作锁。无需 Node 的 Browscreen `visual` 扩展。

调用方查询该会话的 `visual.stream_path`，沿用下面的状态与 PNG 二进制合同订阅。`target_id` 是 MCP 的 `page_id`；通过 `browser_tabs` 明确选页同时切换采集，新页面首帧到达前撤下旧图。关闭选中页后等待明确选择，不猜测其他页面。临时错误撤图但不改变业务断言；结束、撤销或超租期停止采集。

普通 REST 创建的任意 SDK 会话仍不提供这条独立流，因为 Hub 并不拥有调用方页面。已授权 Chrome 继续使用下文 Node/Browscreen 上传路线。MCP 画面从 Hub 内部来源发布，不能由 Node 上传接口冒充。


已有的可选画面扩展在授权 Chrome 执行会话期间采集 PNG，Node 上传到 Hub，调用方订阅并展示。Hub 不提供画面页面；安装扩展也不会在节点仅在线时采集。

## 1. 前置条件与安装位置

先完成 Chrome 模式：Hub 运行、Node 已登记、所有者固定本机浏览器级 CDP 入口、Chrome 资源 READY/FREE、调用方持有该资源许可。

只在 Node 源码根目录安装扩展，正常停止原 Node 后使用同一配置重新启动：

```bash
uv sync --locked --extra visual --python 3.14 -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv run --locked --no-sync runbridge-node run --config .runbridge/node.json --chrome-config .runbridge/chrome.json
```

wheel 安装用带 [visual] 的包路径，见[安装文档](../deployment/安装与运行.md)。Hub 和调用方不安装 Browscreen；订阅者只需 WebSocket 和相应解码工具。扩展接受 `browscreen>=0.3.1,<0.4.0` 的正式版本，上传握手声明实际安装版本；缺失、超出范围、预发布或导入失败时保持基础执行，真实画面支持按节点上报判断。源码锁文件当前仍解析为 0.3.1，更新扩展和两端版本的顺序见[安装文档](../deployment/安装与运行.md)。

## 2. 查询能力声明

```bash
uv run --locked --no-sync runbridge-node inspect node_example --access-file .runbridge/chrome-access.json
```

预期 visual.supported=true，但 streams=[] 完全正常，因为还没有 ACTIVE 会话。supported 是声明，不表示 LIVE；同时检查 ONLINE、capabilities_stale=false 和资源就绪。普通 REST/SDK 创建的受管理会话返回 UNSUPPORTED_BACKEND；Hub MCP 持有的受管理页面另有同页画面流，见本文开头。

## 3. 终端 A：保持一个原生执行会话

在准备好的 Node 源码环境执行，独立调用方使用自己的 .venv 与复制的示例：

```bash
uv run --locked --no-sync python doc/reference/examples/执行会话调用.py --access-file .runbridge/chrome-access.json --resource-id chrome --page-url 'https://your-test-system.example/account' --hold-seconds 60
```

URL 必须是授权实例内唯一匹配的已有页面；替换为实际值。脚本输出 READY 后连接官方 SDK，再输出 ACTIVE 与 session_id，并保持 60 秒。需要较长演示时间可调整保持值和租期，但不能超出访问许可有效期。

画面订阅不能自行激活执行会话。只运行 session create 会得到 READY，没有采集；如果执行脚本省略保持参数，会立即释放，随后订阅失败属于预期。

## 4. 终端 B：查询并保存实际帧

复制终端 A 输出的实际 session_id，替换下文 session_example：

```bash
uv run --locked --no-sync runbridge-node session get session_example --access-file .runbridge/chrome-access.json
uv run --locked --no-sync python doc/reference/examples/画面流订阅.py --access-file .runbridge/chrome-access.json --session-id session_example --frame-count 3 --output-dir .runbridge/visual-frames
```

查询的 visual 包含 state、stream_path、targets、target_id、stream_id、last_frame_id、frame_age_ms 和选择进度。执行示例与订阅者使用同一访问文件。

只有一个页时自动采集。订阅者先收到 state 文本，再收到带元数据的二进制 PNG；保存 frame-001.png 等有限数量图片后退出，不关闭原生执行。成功应同时核对画面 target、递增 frame_id 与实际解码的图片，而不是只看 WS 已连接。

PNG 在订阅者本机；图片完整解码可用自己的浏览器或图片库。示例的纯 Python 拆包验证长度、协议、PNG 签名和会话归属，不以签名校验替代完整图片解码。

## 5. 多页时明确选择采集目标

多页会进入 WAITING_TARGET，不自动跳到某个标签页。列出目标：

```bash
uv run --locked --no-sync python doc/reference/examples/画面流订阅.py --access-file .runbridge/chrome-access.json --session-id session_example --list-targets
```

targets 给出“页面 1”等标签与 target_id，不返回真实 URL/标题。刚启动观察连接时列表可能暂空，稍后重新查询。复制已返回的 target_id，然后：

```bash
uv run --locked --no-sync python doc/reference/examples/画面流订阅.py --access-file .runbridge/chrome-access.json --session-id session_example --target-id target_example --frame-count 3
```

该示例发送 PUT /v1/sessions/{session_id}/visual/target，请求体为 {"target_id":"target_example"}。202 与 PENDING 只表示受理；收到有效首帧后才确认 APPLIED/LIVE，10 秒内未确认会返回失败状态。单个会话同时只受理一个待完成选择。

采集页关闭后撤下旧图，重新从当前 targets 中选择；不自动改截其他页。选择只决定画面来源，不激活页面、不执行业务动作，也不缩小整个实例授权。正式调用方切换目标时跟踪 request_id/target_id，忽略旧选择的在途帧。

## 6. 调用方浏览器展示

将[画面查看示例.html](../reference/examples/画面查看示例.html)部署到自己的调用方页面，或在调用方本机通过回环 HTTP 打开。它是独立客户端示例，不部署到 Hub，也不包含私有凭据。在已准备环境的源码根目录开另一个终端：

```bash
uv run --locked --no-sync python -m http.server 8000 --bind 127.0.0.1 --directory doc/reference/examples
```

独立调用项目使用 .venv/bin/python，并把 --directory 换成仅包含公开示例文件的目录。浏览器访问 http://127.0.0.1:8000/画面查看示例.html；不要将访问文件或 Node 身份放进这个静态目录。演示结束可 Ctrl+C 停止此临时页面服务。

不要用 data URL 加载此页后直接连接局域网 Hub。本次 Chromium 153 实测该来源会触发 ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS；改为回环 HTTP 来源后连接和绘制通过。其他部署来源还需按实际浏览器的本地网络权限处理，不通过关闭浏览器检查解决。[Chrome 本地网络访问说明](https://developer.chrome.com/blog/local-network-access)

操作步骤：

1. 让终端 A 的执行连接继续保持 ACTIVE。
2. 用同一许可查询会话，取得 visual.stream_path；将 Hub 的 http/https 转为 ws/wss，保留路径前缀并拼接该路径。
3. 在示例页填写完整 WS/WSS 地址和该许可的访问令牌，点击“连接画面”。令牌来自自己的私有访问配置，不写在静态页面或 URL。
4. 多页时先在终端 B 选择目标，等待 LIVE；Canvas 显示最新 PNG。
5. 点击“断开订阅”只结束查看；关闭页面会清理订阅。执行端结束后，页面清空旧图并显示关闭状态。

浏览器 WebSocket 不能指定 Authorization 头，示例在打开连接后立即发送 {"type":"auth","access_token":"..."}，必须在 5 秒内完成。认证前 Hub 不发送页面目录、状态或图片。

正式平台应由自己的登录/授权流程获取许可，后台调用查询接口，再将获授权的入口交给前端。Hub 没有提供跨域 HTTP CORS 配置；跨域 fetch 查询需要平台的同源代理或自行设计的跨域配置。此 HTML 只使用 WS 首消息认证，没有跨域 fetch 查询依赖。HTTPS 页面使用 WSS，避免浏览器混合内容限制。

## 7. 二进制合同与展示生命周期

```text
4 字节大端无符号 JSON 长度 + UTF-8 JSON 元数据 + PNG 字节
```

元数据包含 session_id、connection_generation、stream_id、target_id、frame_id 等。单 JSON 最多 4096 字节，PNG 最多 4 MiB；不能把整个二进制消息直接当 PNG 解码。官方 Playwright SDK 不处理这个独立封包。

展示者保持最新帧，不无限排队；选择变化时丢弃旧来源，STALE/ERROR/WAITING_TARGET/STOPPED 时及时清空旧图。HTML 示例只保留一个待绘制消息，并在异步解码后再次核对当前来源。订阅重连要重新认证、查询当前状态；结束的会话不能恢复旧流。

## 8. 常见状态与处理

| state / reason | 含义与处理 |
| --- | --- |
| UNAVAILABLE | 没有扩展、后端不支持、未 ACTIVE 或离线；先查原因和资源 |
| WAITING | 源正在准备或等待首帧；不要把入口存在视为成功 |
| WAITING_TARGET | 多页或目标关闭；从返回的 targets 选择 |
| LIVE | Hub 收到新鲜有效帧；再验证实际图片 |
| STALE / FRAME_STALE | 5 秒没有新鲜帧，撤下旧图并查采集/网络 |
| ERROR / FRAME_TOO_LARGE | PNG 超过 4 MiB；本期不自动缩放或转码 |
| STOPPED | 会话结束，入口撤下；下一次需新会话 |
| 401 / 403 | 许可到期、撤销或不是创建该会话的许可 |

采集错误不会单独改变业务执行结果，浏览器本身失联则按执行中断处理。默认采样间隔 300 毫秒，实际更新取决于浏览器、网络和解码；不是固定帧率视频，不含音频、录制和鼠标输入。

退出执行示例后确认 cleanup=COMPLETE、节点 streams=[]、无活动采集；Chrome 及登录保留。强杀后的 UNKNOWN 仍需要独立核查，不能根据画面消失改写清理结论。中文方框按[字体说明](../deployment/跨机器部署与中文字体.md)补齐 Node 字库；业务 UTF-8 正确不自动等于字体渲染正确。
