# Subscribe to browser frames

[简体中文](浏览器画面流接入.md) · English

Create a tool session using a real claimed access file, run its first command to make it ACTIVE, then query `GET /v2/sessions/{id}`. `visual.supported` declares observation support; use the returned `stream_path`, rather than guessing a Node/browser address.

Managed frames come from the same Python Page on Node; `target_id` equals the action `page_id`. Borrowed uses its optional capture extension, mapped to session Page references. Both use visual protocol 1; clients need no browser SDK.

Copy [画面流订阅.py](../reference/examples/画面流订阅.py) and the actual access file into a client directory with a prepared `.venv`. Install both of the script's dependencies in that environment:

```bash
uv pip install --python .venv/bin/python 'httpx>=0.28,<1' 'websockets>=15,<18' -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python 画面流订阅.py --access-file access.json --session-id session_example --frame-count 3
```

Replace `session_example` with the real session created and kept ACTIVE by the original caller. The script saves a limited number of frames under `.runbridge/visual-frames` by default; it neither creates nor closes browser sessions. Alternatively use the [HTML viewer](../reference/examples/画面查看示例.html) with the actual base URL and permit. Browser WebSockets without custom headers authenticate with the first `auth` message. Keep tokens out of query strings. Shared script/viewer messages can be Chinese.

Handle state messages before displaying images. Show only LIVE, fresh frames. Choose targets from `visual.targets` using the target endpoint; do not assume the first of multiple pages. Clear old images on staleness, session end, revocation, or disconnection.

See the [visual contract](../reference/浏览器画面流接口.en.md) for framing, limits, and selection confirmation. Streaming is observation, not mouse/keyboard control; actions still use HTTP / MCP and verify actual business results.
