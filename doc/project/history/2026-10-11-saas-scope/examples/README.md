# 协议示例说明

[研究首页](../README.md) · [架构设计](../doc/design/平台与执行节点架构.md)

本目录三个 JSON 是设计示例，未被真实客户端执行，也不是已实现的接口规范。`DESIGN_EXAMPLE_NOT_EXECUTED` 明确标记证据等级，所有节点/会话/业务 ID 均为虚构示例，不包含真实秘密。

这些示例保留早期平台统一注册与工具 RPC 的消息格式。最新[独立节点服务契约](../doc/design/独立节点服务与对外契约.md)不要求节点理解平台 `tenant_id`、`run_id` 或测试结论，也不要求采用这里的简化工具集合；不要将历史示例当作当前独立节点的必选协议。

| 文件 | 说明 |
| --- | --- |
| [节点能力示例](节点能力示例.json) | 节点登记时已有浏览器候选，但尚待用户授权；手机也待调试授权 |
| [执行命令示例](执行命令示例.json) | 后续用户授权、重新探测并取得租约后，在原有浏览器页面点击提交 |
| [执行结果示例](执行结果示例.json) | 动作已执行，但业务结果缺少验证，平台不能认定通过 |

节点能力示例和执行命令示例处于不同阶段。不能拿能力示例中的 `NEEDS_USER_APPROVAL` 状态直接执行命令；运行前必须获得当前授权、匹配资源和有效租约。

`tenant_id` 只表示记录归属，服务端必须从认证上下文验证；不能信任请求自报的租户。`authorization_scope_id` 指已保存的授权，不能由 Agent 临时生成来扩大范围。元素引用绑定观测版本，租约代次绑定当前资源所有者。

命令超时、重复投递和断线恢复的建议见架构设计。命令去重记录不能为任意 UI 业务写入提供 exactly-once 保证，结果未知需要进一步协调。
