# Hub 部署后的交接与接入检查

[文档导航](../README.md) · [首次部署 Hub](../deployment/部署与运行.md) · [调用方操作](调用方对接与使用.md)

本页供 Hub 部署者在服务启动后跟进交接，不替代首次部署教程。如果还没有安装程序、生成登记文件或开启监听，请先完整执行[部署与运行](../deployment/部署与运行.md)。

## 1. 先确认服务还在运行

Hub 服务终端应保持运行。另开一个 Hub 终端检查：

```bash
curl --fail http://127.0.0.1:8787/health
```

实际端口不为 8787 时改用自己的端口。预期 `{"status":"ok","protocol_version":1}`；然后请 Node 所有者从其设备检查实际服务器地址。只检查回环地址不能证明远程可达。

## 2. 确认对方真的收到登记资料

按[部署交接步骤](../deployment/部署与运行.md#7-把登记资料交给-node-所有者)核对：

| 资料 | 双方要确认什么 |
| --- | --- |
| Hub 基址 | Node 所有者收到的是实际可达地址，不是 `0.0.0.0` 或 Hub 的回环地址 |
| `enrollment.token` | 交付的是本服务正在读取的真实单行文件，不是手册示例、JSON 或访问许可 |
| 文件接收位置 | 对方按 Node 手册先保存到自己的下载目录，再放入 Node 私有目录；这不是在 Hub 上新建第二份秘密 |
| MCP，若需要 | Hub 已启用，且实际 MCP 入口已说明；登记文本不能当作其认证凭据 |

Node 所有者接下来按 **Node 项目《部署与运行》**完成登记和一种浏览器准备。Hub 服务器到此无需安装或启动 Node。

## 3. 向 Node 所有者索取上线结果

请对方回报实际值：

| 项目 | 数据来自哪里 | 应达到的状态 |
| --- | --- | --- |
| 节点 ID | `register` 成功响应或设备自己的身份文件 | 实际 `node_...`，不是演示 ID |
| 浏览器模式与资源 ID | 对方浏览器配置 | 受管理 `chromium` 或已有 Chrome `chrome`，也可以是自定义值 |
| 查询结果 | 对方使用访问许可执行状态查询 | ONLINE、报告未过期，所需资源 READY／FREE |
| 给谁交付访问许可 | 对方本次签发并保存的 `access.json` | 交给确认的接口调用方，附上资源 ID 和期限 |

Node 设备的身份秘密和本机调试地址留在其设备上。Hub 部署者不需要收集它们，也不需要修改数据库来“补登记”。

## 4. 由调用方完成第一次浏览器连接

取得自己使用的访问 JSON 后，调用方按[调用方操作](调用方对接与使用.md)在独立目录完成：

1. 用文件里的 Hub 地址、Node ID 和访问令牌查询节点。
2. 按所有者交付的资源 ID 连接浏览器。
3. 保存实际截图或完成业务断言。
4. 结束后确认本次会话 cleanup=COMPLETE。

Agent 用户改按 [MCP 接入](MCP浏览器接入.md)。已有 Chrome 持续画面则按[画面流指南](浏览器画面流接入.md)核对新鲜 PNG。

健康正常、节点 ONLINE、连接 ACTIVE、截图内容正确、清理完成分别说明不同结果。部署交接完成后，浏览器业务成功仍由调用方的真实断言确认。

## 5. 卡在哪一步就找对应的提供者

| 卡住的位置 | 下一步 |
| --- | --- |
| 远程 health 不通 | Hub 部署者排查监听、网络和代理 |
| 找不到登记文件／格式不明 | 回到 Hub 部署第 4、7 节确认生成结果和交付文件 |
| Node 登记认证失败 | 双方核对是不是同一真实登记文本；不要各自重新随机生成 |
| ONLINE 但浏览器不可用 | Node 所有者按自己的模式指南检查本机浏览器 |
| 调用返回 401 | Node 所有者核对该调用许可是否到期或撤销 |
| MCP 404／Host 拒绝 | Hub 部署者核对可选功能和允许列表 |

服务端细节见[运行与排障](../deployment/运行与排障.md)。
