# Hub configuration and credentials

[简体中文](部署配置与凭据.md) · English

Applies to **Hub 0.9.3**. See [deployment](../deployment/部署与运行.en.md), [parameters](参数详解.en.md), and [annotated YAML](examples/Hub启动配置.en.yaml).

The deployer writes `hub.yaml`; `serve --settings` reads it. Store token paths and policy rather than secret values. The database is created initially and retained afterward. Hub uses one process/worker and does not connect to a browser itself; `--mcp-native-url` is removed. HTTP and execution WebSocket messages are limited to 16 MiB, control messages to 64 KiB, and MCP request bodies to 8 MiB.

## Files, formats, and owners

| File | Producer | Contents / source | Holder |
| --- | --- | --- | --- |
| `enrollment.token` | Hub `generate-token` | Random single-line text, 32–256 characters, without quotes or Bearer | Hub deployer; privately handed to Node maintainers |
| `hub.token` | Separate `generate-token` call | Independent single-line claim credential, 32–256 characters | Hub deployer and authorized clients, not the Node process |
| `hub-auth.json` / `.yaml` | Client | Only `hub_url` and `hub_token`, using actual `public_url` and original claim token | Client / DSH host, mode 600 |
| `web.token` or configured file | Automatic Hub generation or separate generator call | Independent read-only single-line token, 32–256 characters | Hub deployer and monitoring users |
| `hub.sqlite3` | Hub startup/migration | SQLite schema 5; identity/permit tokens stored as hashes | Hub deployer |
| `node.json` | Initial Node startup | `config_version=1`, `hub_url`, `node_id`, `name`, `node_token` | Node owner, not clients |
| `access.json` / `.yaml` | Client after Hub claim | Returned `access_config`: `hub_url`, `node_id`, `grant_id`, `access_token`, `expires_at` | This lease holder |

An access file has exactly those five fields. Hub issues timezone-aware ISO 8601 expiry rather than permanent leases. The resource ID is provided separately. Enrollment and device tokens cannot replace the client access token.

The dashboard is enabled by default. Startup prints its token and complete token-bearing URL. Read-only authentication cannot execute or allocate leases. See [dashboard](../user-guide/节点总览.en.md) for precedence and disable options.

Private text/JSON files use UTF-8, directory mode 700 and file mode 600. Token generation refuses overwrite. Stop Hub before taking a consistent database backup; copying a writing SQLite file is insufficient.

The database-side `.lock` provides process exclusion. Its existence alone does not prove a process is alive; do not remove it to bypass locking. Offline review evidence is stored in `grant_resolutions`, while original session UNKNOWN remains. See [operations](../deployment/运行与排障.en.md) and [leases](Node使用权租约接口.en.md).
