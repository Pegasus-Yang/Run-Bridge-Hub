# RunBridge Node 与执行工具接入

[文档导航](../README.md) · [节点接入与原生执行契约](节点接入与原生执行契约.md)

R0/R1 和受管理 Chromium 原生执行已实现。R4 Chrome CDP 路线见[复用实现](../architecture/Chrome复用与授权清理.md)；HTTP、扩展和设备路线仍为设计；当前代码、能力与限制见[执行架构](../architecture/Playwright执行与会话管理.md)。

## 1. RunBridge Node 的职责

RunBridge Node 是 Python 节点客户端，保存本机身份和配置，主动连接 RunBridge Hub 网关，探测获授权资源，管理执行子进程并回传状态。用户通过本地 CLI 或停止入口撤销本次连接/控制。

使用 asyncio 处理连接、心跳、异步子进程和状态；避免在网络主循环同步执行耗时探测、ADB 或大文件读取。执行工具可作为子进程或已有服务，不要求全部重新写成 Python。

客户端只安装实际启用能力所需的工具。仅提供 HTTP 的节点不必安装 Playwright/Appium；只提供 Android 的节点不必安装 iOS 工具链。

## 2. 首期能力矩阵

| 能力 | 本机基础 | 首期建议 |
| --- | --- | --- |
| HTTP 请求 | HTTP 库、客户网络和 CA/代理 | 先验证一个仅本机可达服务 |
| 受管理 Chromium | 配套 Node.js Playwright、浏览器 | 原生协议的第一条完整验证路径 |
| 已有 Chrome/Edge | 已授权的 CDP/扩展桥接 | 单独验证并声明覆盖范围，不能用新浏览器代替 |
| Android | Appium、UiAutomator2、ADB、已授权设备 | 验证一台 USB 真机及明确资源占用 |
| iOS 常规路径 | Mac、Xcode、XCUITest/WDA、签名准备 | 后续独立验收 |
| iOS 非 Mac 路径 | 官方受限真机方案与前置 WDA | 专项验证，不作为任意 Windows/Linux 节点的默认能力 |

“实际工具版本”和“最近准备结果”由节点报告；数据库中的安装快照不能代替现时检查。

## 3. Playwright 浏览器服务

Python 客户端管理运行时启动、退出与网关接入。原生端点由对应版本的 Node.js Playwright 提供，调用方通过官方 SDK 使用其 API。两端主次版本必须匹配，本次候选 1.63.0/1.63.0 仅确认发布存在。[Python BrowserType](https://playwright.dev/python/docs/api/class-browsertype)

启动参数作用于节点环境，例如可执行文件路径、浏览器 channel 和本机输出目录。外部调用者路径不能直接作为本机有效路径；适配层保留参数含义并说明位置，无法支持时明确返回限制。

受管理浏览器由本次会话创建，结束时回收自己的实例/目录。借用浏览器来自用户，结束默认解除控制；关闭、清数据和改变 Profile 必须具有对应许可。

## 4. 已有浏览器复用

传统端口方式在 Chrome 136+ 对默认数据目录有限制；不能只发现 Chrome 进程就接管默认 Profile。[Chrome 调试端口变更](https://developer.chrome.com/blog/remote-debugging-port)

官方 Playwright 扩展可连接已登录页面，默认选择页面并确认连接；可以作为桥接验证参考。Chrome debugger API 的域和企业策略仍有限制。[固定扩展说明](https://github.com/microsoft/playwright/blob/d9f2fd3e2232ace8e317a84eda6cb86e25bcf49c/packages/extension/README.md)、[debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger)

R4 已选定本机固定 CDP 浏览器端点，明确授权端点可见的整个实例；单页面扩展授权保留后续路线。不承诺完全后台或所有浏览器级能力。连接正常、页面可交互、业务登录仍有效是不同事实。

后台、失焦、最小化、冻结/丢弃分别验证。多窗口同 Profile 仍共享登录和存储，不能仅靠不同网关连接制造账号隔离。

## 5. HTTP 能力

DNS、网络请求、代理和证书验证在节点完成。认证材料可由本地配置引用，不默认向调用者返回原值；响应内容与输出按授权范围提供。

HTTPX 支持 CA 和客户端证书，可作为执行候选；原研究只检查其公开资料与元数据；当前 R1 已在 Python 3.14 下安装 HTTPX 并验证管理请求，节点侧业务 HTTP 执行仍待 R2。[HTTPX SSL](https://www.python-httpx.org/advanced/ssl/)

错误证书、超时和写请求结果未知分开报告；不用“自动关闭证书校验”解决所有内网访问问题，也不在重连后自动重发写请求。

## 6. Android：ADB 与 Appium 分工

ADB 负责设备连接、调试授权、安装、文件和必要诊断；Appium UiAutomator2 提供 UI 元素、会话与动作。两者可以配合使用，不是简单二选一。[UiAutomator2](https://github.com/appium/appium-uiautomator2-driver)

用户需开启 USB 调试并确认电脑 RSA 密钥；未授权、离线、拔线都要能识别。[Android ADB](https://developer.android.com/tools/adb)

当前 UiAutomator2 5+ 对应 Appium 3，6+ Android 下限为 API 26。按真实设备选择兼容版本，不将一个版本的准备成功推及全部 Android。

首期一台设备只允许一个交互会话。复用 App 登录状态时，不擅自清数据、重装或卸载；`noReset` 配置不保证所有业务会话永不过期。

FLAG_SECURE 保护内容可能不能截图；无法观测时明确返回能力限制，不将空白截图当成有效业务证据。[Android 安全窗口](https://developer.android.com/security/fraud-prevention/activities)

## 7. iOS：独立准备与验证

常规路径是 Mac + Xcode + XCUITest/WDA。真机涉及设备信任、Developer Mode、签名和 provisioning；当前 XCUITest 10+ 对应 Appium 3。[系统要求](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/system-requirements/)、[设备准备](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/)

新版官方文档已有 Windows/Linux 受限路径：仅真机、iOS/tvOS 18+、RemoteXPC、明确设备、预装或外部 WDA；常规 xcodebuild 启动不适用。不能说 iOS 一律只能在 Mac 执行，也不能宣传任意非 Mac 主机即插即用。[非 Mac 主机](https://appium.github.io/appium-xcuitest-driver/latest/guides/non-macos-hosts/)

签名资产和设备准备是外部工具条件，Python 3.14 和 Pydantic 不会消除这些条件。iOS 能力按路线单独声明和验收。

## 8. 本机清理、重连和分发

客户端维护自己创建与借用的资源记录。失联时停止接受新会话；到期/停止时尽力解除控制或回收自建进程，并回报清理状态。客户端崩溃后依据真实进程和资源重新探测，不只恢复配置中的“运行中”标志。

输出与临时文件按会话隔离，提供有限生命周期的获取方式。避免误删除用户既有浏览器 Profile、下载目录或手机数据。

首期按 uv 管理 Python 环境运行客户端，不将单文件可执行程序、安装向导或 GUI 作为最低要求。后续如需打包分发，另行核验打包器对 Python 3.14、外部 Node.js/ADB 工具及目标系统的支持；本次没有打包验证。
