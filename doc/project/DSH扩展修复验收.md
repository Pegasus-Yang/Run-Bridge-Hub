## 修复范围与分工

| 问题 | 当前实现与验证 |
| --- | --- |
| F1 · 失败启动无法恢复身份 | 会话首次分配与请求关联在 SQLite 同一事务中提交；准备失败、连接失败、取消和重启均可按原 request_id 查询。区分确定未分配与无记录，失败请求不自动重放 |
| F2 · 永久 Task 与凭据上下文 | 在途 Task 完成后移出内存，不继承 MCP 请求 ContextVar；终态仅保存无凭据元数据。每有效许可最多 1024 个请求、Hub 最多 64 个在途请求；失效许可记录可回收，授权阻止旧请求重放 |
| F3 · 4 MiB 上传被 HTTP 413 拒绝 | HTTP 请求上限为 8 MiB，解码后的所有文件仍合计最多 4 MiB。单文件、多文件、+1 字节、非法 base64 和空列表均验证；超限在文件输入操作前拒绝 |
| F4 · 当前文档矛盾 | 两端统一为 Hub 0.5.1 / Node 0.5.0 和 26 个 MCP 工具，区分 MCP 同页画面、普通 REST/SDK 会话及 Chrome/Browscreen 路线；历史验收和依赖版本范围保留原貌 |

- 正常 browser_stop 为 **CLOSED / COMPLETE**，error_code 为空；资源为 FREE，自建主浏览器进程退出，实际短临时目录消失。

## 实机验证发现的关闭竞态

首轮真实测试发现 0.5.0 的同页采集与原生关闭竞争：正常释放出现 INTERRUPTED / COMPLETE 和 NATIVE_CONNECTION_LOST。仅有 cleanup=COMPLETE 不能证明正常生命周期正确，因此没有放宽断言或把首次失败记为通过。

Hub 现在先调度 Node 停止意图，让 MCP 句柄失效与停止通知并发，再关闭原生连接；采集在已关闭或失效会话上不再发送 detach RPC，CDP 随 Node 自建浏览器清理。活动会话换页仍显式 detach。对应发送顺序、换页和失效路由的回归已补齐，最终 8 项实机验收全部通过。

## 升级与保留边界

Hub 首次运行会将 SQLite v1/v2 自动迁移到 v3，保留身份、许可与会话，新增无凭据 mcp_requests。升级前一致性备份；旧程序不能直接读取 v3，回退须恢复备份，不能通过删除请求记录来重放未知创建。

固定 DOM 采集仍仅覆盖主页面，256 KiB 限额在结果传回 Hub 后检查；CDPSession 初始化失败仍需显式重新选择目标。这些已知边界已写入两端指南，不新增 iframe 采集、浏览器侧限额或自动重连。

MCP 2.3.0 对部分带注解/可选参数中的 JSON 数组或对象字符串会预解析；本次页面摘要采用普通文本前缀，随后按固定采集结果解析并严格比对文件元数据。这个既有 SDK 行为没有在本轮扩展修复。公网 TLS/代理、Windows、容量压力与任意 Playwright 方法仍不由本次验收推及。
