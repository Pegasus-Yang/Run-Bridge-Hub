# 0.6.0 日常环境升级与功能验收

核验日期：2026-10-19（Asia/Shanghai）。本记录针对原有的 macOS Hub、Ubuntu ARM64 Node 日常部署；与此前[独立目录发布验收](Python工具执行验收记录.md)分开。

## 升级结果

两套 Hub 和 managed/borrowed 两套 Node 均为 0.6.0。先备份停止状态下的数据库、身份、配置和 Chrome Profile，再安装升级、迁移启动配置。原 Node ID 和身份文件哈希不变；两库升至 schema 4，通过完整性检查，原节点、许可及历史会话均保留。旧会话仍带旧协议标记。

Hub 安装环境已移除 Playwright。运行职责为鉴权、路由、租期、状态与画面分发；工具操作在 Node 的 Python worker。最终 Node wheel 的全部 Python 文件与源码、两套虚拟机安装内容一致。

## 发现并修正

直接启动测试 Chrome 的旧脚本缺少本地存储参数，可能触发系统钥匙链访问；项目未实现 Keychain 账号存储。当前 managed 启动显式保留 `--use-mock-keychain`、`--password-store=basic`，过滤自定义冲突值；直接启动的专用测试浏览器也保留同样参数，不要求批准系统钥匙链请求。

已有 Chrome 的后台页点击会卡在元素稳定性等待。borrowed 鼠标、键盘与表单输入现在先激活明确指定的 Page；只读查询与画面订阅不切换前台。重复 URL 的旧页面需要额外内容确认或由所有者准备可区分的测试 URL。

技术与用户文档已同步上述行为、实际健康响应、结果取值层次、模块职责、控制/执行合同和当前依赖边界；旧研究保留日期与历史提示。基础工具安装仍交由官网管理，Hub 与 Node 的用户部署步骤分别维护。

机器地址、运行命令、备份校验、测试数据、凭据、JUnit、截图和原始证据保存于不提交的 `local/`。公开结果只证明上述环境和场景，不增加其他工具、完整官方 SDK、容量或全部系统的兼容承诺。
