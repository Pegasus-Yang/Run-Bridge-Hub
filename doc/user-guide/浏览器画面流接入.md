# Hub 画面流：保持会话、保存 PNG 和打开查看页

[文档导航](../README.md) · [调用方准备](调用方对接与使用.md) · [画面接口参考](../reference/浏览器画面流接口.md)

本页从调用方已经拿到访问许可、完成 SDK 连接检查开始，带你在第二个终端接收持续画面。画面采集由 Node 所有者或 Hub 提供；调用方不安装采集器，也不修改远程浏览器配置。

## 1. 确认你的会话确实有画面能力

| 场景 | 本页前提 |
| --- | --- |
| 已有 Chrome | 所有者已安装 Node 的 visual 扩展，并告知资源 ID、已有页面 URL |
| 受管理 MCP 页面 | 继续使用原 MCP 会话和 Page，拿到它的 session_id；不另建 SDK 连接 |
| 普通 SDK 受管理会话 | 当前无独立画面流，本页不适用；可用 SDK 截图 |

以下可执行流程以**已有 Chrome**为例。先按[调用方准备](调用方对接与使用.md)建立 `~/runbridge-client`，其中应有 `.venv`、私有 `.runbridge/access.json` 和 `examples/` 中的执行、订阅脚本及 HTML。这些文件从 Hub 文档包复制，不能只创建同名空文件。

三个 ID 要分清：节点 ID 来自访问文件；资源 ID 由所有者交付；**会话 ID 是本次运行执行脚本后返回的 `session_id`**，不是前两者。

## 2. 先准备查看入口查询脚本

在调用方目录创建下面的小脚本。它只查询同一许可可见的会话，并输出完整画面地址，不显示访问令牌：

```bash
cd ~/runbridge-client
cat > visual_info.py <<'PYCODE'
import argparse
import json
from pathlib import Path
from urllib.parse import urlsplit, urlunsplit

import httpx

parser = argparse.ArgumentParser()
parser.add_argument("--session-id", required=True)
args = parser.parse_args()
access = json.loads(Path(".runbridge/access.json").read_text(encoding="utf-8"))
hub = access["hub_url"].rstrip("/")
response = httpx.get(
    url=f"{hub}/v1/sessions/{args.session_id}",
    headers={"Authorization": f"Bearer {access['access_token']}"},
    timeout=15,
)
response.raise_for_status()
visual = response.json().get("visual") or {}
if not visual.get("stream_path"):
    raise RuntimeError("本次会话尚未 ACTIVE 或没有画面入口")
address = urlsplit(hub)
stream_url = urlunsplit((
    "wss" if address.scheme == "https" else "ws",
    address.netloc, address.path + visual["stream_path"], "", "",
))
print(json.dumps({"stream_url": stream_url, "state": visual["state"], "targets": visual["targets"]}, ensure_ascii=False, indent=2))
PYCODE
```

这个文件是本地查询示例，不是 Hub／Node 启动配置。先保存它，再开始活动会话，可以减少在租期内临时准备文件的时间。

## 3. 终端 A：建立并保持活动会话

在调用方终端 A，替换所有者提供的资源 ID 和已有页 URL：

```bash
cd ~/runbridge-client
.venv/bin/python examples/执行会话调用.py --access-file .runbridge/access.json --resource-id chrome --page-url 'https://your-test-system.example/account' --hold-seconds 180
```

等到输出 `state=ACTIVE` 后，记录同一行的真实 `session_id`。脚本会在默认 300 秒租期内保持连接 180 秒，然后释放。

**保留终端 A 运行**，立即在终端 B 操作下一节。只拿到第一行 READY 不够；直接运行不带保持参数的示例会很快释放，之后再订阅就来不及了。若时间耗尽，待原会话释放后重新运行，使用新的会话 ID。

MCP 路线则保持原 MCP 会话和页面，使用 `browser_start`／`browser_status` 返回的会话 ID，不运行上面的 SDK 创建命令。

## 4. 终端 B：先接收并保存一张 PNG

打开调用方终端 B。把 `session_example` 换成终端 A 返回的实际 ID：

```bash
cd ~/runbridge-client
.venv/bin/python examples/画面流订阅.py --access-file .runbridge/access.json --session-id session_example --frame-count 1 --output-dir artifacts/visual-frames
```

必须使用创建会话的同一访问文件，不能换成同节点另一份许可。

脚本先输出画面状态，接着打印保存文件、`frame_id` 和 PNG 字节数。首次检查只等一张，成功会生成：

```text
artifacts/visual-frames/frame-001.png
```

打开图片确认是授权页面的当前内容。WebSocket 连上或文件有 PNG 签名都不足以替代内容核验。脚本保存指定帧数后退出，只停止订阅，终端 A 的业务连接仍继续。

**首张图是空白页或导航前的画面时，还不能判定成功。**采集可能早于页面导航完成，首次订阅也可能先收到缓存的初始帧。保持原会话和页面，先确认目标内容已经加载：已有 Chrome 可请所有者查看目标页，MCP 可用 `browser_wait_for` 等待预期元素出现，并用 `browser_screenshot` 核对页面。稍候后重新订阅一次，把输出目录改为新目录以保留前一次证据：

```bash
.venv/bin/python examples/画面流订阅.py --access-file .runbridge/access.json --session-id session_example --frame-count 1 --output-dir artifacts/visual-frames-retry
```

打开新目录的 `frame-001.png`，确认包含本次页面的预期文字或状态，再算内容检查通过。若仍是空白或旧图，按第 5 节核对目标并联系所有者排查；不要把一次工具截图成功当作持续画面已经正确，也不要重放保存、支付等写操作来刷新画面。

需要检查多帧时，再把 `--frame-count` 改为 `3`，使用确实持续变化的页面，核对递增帧号和实际内容。部分采集路线只在画面更新时发帧，静态页面不保证凑足三张；默认等待 20 秒后可能退出为失败，但已保存的 PNG 仍保留。不要为了增加帧数重放提交或其他业务写操作。

如果只有 WAITING_TARGET，执行下一节明确选页；ERROR／STALE 时按状态原因排查，不把旧图作为当前画面。

## 5. 多页面时明确选择目标

继续在终端 B，用同一个真实会话 ID 列出目标：

```bash
.venv/bin/python examples/画面流订阅.py --access-file .runbridge/access.json --session-id session_example --list-targets
```

读取 `targets` 中返回的真实 `target_id`，替换 `target_example` 后再订阅：

```bash
.venv/bin/python examples/画面流订阅.py --access-file .runbridge/access.json --session-id session_example --target-id target_example --frame-count 1 --output-dir artifacts/visual-frames
```

这些目标 ID 来自查询，不是页面 URL 或浏览器调试 ID。已有 Chrome 不公开真实 URL／标题；不要根据列表顺序猜目标。选择响应 PENDING 只是受理，之后看 APPLIED／LIVE。同一会话同时只接受一个在途选择。

选页只切换采集来源，不激活页面，也不缩小原实例授权。MCP 的目标是其 page_id，通过 `browser_tabs` 明确选页并同步采集，不另接 SDK。

## 6. 在调用方浏览器打开查看页

在一个可用调用方终端运行：

```bash
cd ~/runbridge-client
.venv/bin/python -m http.server 8000 --bind 127.0.0.1 --directory examples
```

这是只展示公开示例的本地静态服务，不是部署 Hub／Node。保留服务终端，在调用方本机浏览器打开 `http://127.0.0.1:8000/画面查看示例.html`。私有访问文件在 `.runbridge/`，不在被提供服务的 `examples/` 下。

在另一个终端查询本次活动会话的完整入口：

```bash
cd ~/runbridge-client
.venv/bin/python visual_info.py --session-id session_example
```

在页面按以下来源填写：

| 页面字段 | 填入什么 |
| --- | --- |
| 完整 WS/WSS 画面地址 | 上述查询输出的 `stream_url`，不是 Hub 的 HTTP 健康地址 |
| 创建会话的访问令牌 | 用本地文本编辑器打开 `.runbridge/access.json`，复制 `access_token` 的原值，不带 JSON 引号或 Bearer 前缀 |

点击“连接画面”。页面会在连接后发送认证首消息，等待 LIVE 后绘制 PNG。浏览器 WebSocket 不能设置 Authorization 请求头，因此页面使用首消息认证；不要把令牌拼进 URL 或写进公开 HTML。

查看过程中保持终端 A 的原业务会话 ACTIVE。如果准备页面时 180 秒已过，先新建并保持一个会话，再用其**新 ID**重新查入口。点击“断开订阅”只停止查看，业务结束仍由原执行方释放。

HTTPS 页面使用 WSS。Hub 没有通用 CORS 配置，本例通过 Python 查询 HTTP 元数据；自己的网页集成应处理同源代理／跨域和浏览器的局域网访问权限。

## 7. 状态和结束判断

| 状态／原因 | 应如何处理 |
| --- | --- |
| UNAVAILABLE／UNSUPPORTED_BACKEND | 确认使用了支持画面的路线和 ACTIVE 会话，联系所有者核对能力 |
| WAITING／WAITING_TARGET | 等首帧，或按第 5 节明确选择当前目标 |
| LIVE | 继续核对真实新帧内容 |
| STALE／ERROR | 撤下旧图并检查原因；5 秒没有有效新帧会过期。静态页也可能不产生新帧，不能据此单独判断业务失败或网络中断 |
| FRAME_TOO_LARGE | 原 PNG 超过 4 MiB，不会自动缩放 |
| STOPPED | 原会话已结束，下一任务申请新会话 |
| 401／403 | 检查到期、撤销，以及是否使用创建会话的同一许可 |

终端 A 完成后确认 cleanup；画面 LIVE 不判断网页业务通过。中文方框由浏览器所在设备的所有者检查字体，Hub 服务器安装字体不会改变远端渲染。

自己实现消费者时，二进制消息为“4 字节大端 JSON 长度 + UTF-8 JSON 元数据 + PNG”，不能整条直接当 PNG。JSON 最多 4096 字节、PNG 最多 4 MiB；页面应只保留最新待绘制帧，失效或目标变化时撤旧图。完整字段见[画面接口参考](../reference/浏览器画面流接口.md)。
