# 工具调用协议草案

状态：已采纳并按 0.6.0 实施的设计记录。原评审日期：2026-10-18。当前操作以文档导航中的使用手册与参考合同为准。本文保留原设计推演语境；最终字段与运行步骤见当前参考合同和部署手册。整体范围见[架构改造方案](工具指令执行架构改造方案.md)。

## 1. 一套信封，两类使用者

HTTP 使用者提交方法、目标和参数；MCP 将既有工具参数转换成同一种请求。Hub 补齐会话所绑定的工具、资源、协议版本和连接代次后，向 Node 下发指令。

外部调用方只提交业务调用字段，不需要填写 Node 内部进程、服务端口、连接代次或 SDK 版本。Node 只执行已注册工具的已声明动作，返回 JSON、对象引用或明确编码的二进制数据。

通信统一使用 UTF-8 JSON，不承载 Python 对象、pickle、可执行 Python 文本或 Playwright 私有协议帧。协议版本固定为 2，工具动作合同另有 `tool_api_version`，两者承担不同职责。

## 2. 接口与连接

### 2.1 对外 HTTP

所有接口沿用访问许可的 `Authorization: Bearer <access_token>`。Node 身份只用于 Node 主动连接，不交给调用方。

| 拟议接口 | 用途 |
| --- | --- |
| `GET /v2/nodes/{node_id}/tools` | 查看当前可用工具、合同版本、动作目录和资源，不把 installed 当作 READY |
| `POST /v2/nodes/{node_id}/sessions` | 选择 tool/resource_id，创建工具会话 |
| `GET /v2/sessions/{session_id}` | 会话、根对象、页面目录、当前请求与画面信息 |
| `DELETE /v2/sessions/{session_id}` | 幂等释放；返回已确认的清理状态或 PENDING/UNKNOWN |
| `POST /v2/sessions/{session_id}/commands` | 提交一次方法调用，并等待该请求的结果 |
| `GET /v2/sessions/{session_id}/commands/{request_id}` | 查询进行中、终态和可用结果，不重做操作 |

第一版不新增面向外部的任意事件订阅服务。页面和状态事件在 Node→Hub 内部同步，并反映到会话查询和已有画面接口中。以后需要对外订阅时，再定义客户端的订阅、断线和补偿合同。

### 2.2 Hub 与 Node

- 控制：Node 主动连接 `/v2/nodes/{node_id}/control`，传 welcome、heartbeat、capabilities、session_open、session_prepared、session_stop、session_closed 等项目消息。
- 执行：每会话由 Node 主动连接 `/v2/nodes/{node_id}/sessions/{session_id}/execution`，传 execute、command_ack、command_started、result、event。
- 画面：保留独立上传、目标选择和调用方订阅接口，继续使用现有画面格式；查询结果交付实际路径，执行协议升级不要求把 PNG 塞进控制连接。

控制消息上限仍为 64 KiB；执行消息上限为 16 MiB。WebSocket 一条文本消息对应一个 JSON 信封。第一版上传和截图采用有界 base64，超过限制明确拒绝，不悄悄截断。

Node 与其 Python worker 使用相同 JSON 内容。本地管道采用“4 字节无符号大端长度 + UTF-8 JSON”分帧，上限同为 16 MiB，不依赖默认只支持较短行的 readline。worker 标准输出只写协议，日志写标准错误；不开放另一个本机网络服务。

## 3. 会话和根对象

创建请求示例：

```json
{
  "request_id": "open_001",
  "tool": "playwright",
  "resource_id": "chromium",
  "lease_seconds": 300
}
```

| 字段 | 规则 |
| --- | --- |
| request_id | 创建请求标识，当前许可、Node 范围内唯一；同内容重复请求查询同一分配，不新建浏览器 |
| tool | 工具名，首版为 `playwright`；必须与资源目录绑定一致 |
| resource_id | 所选 Node 的真实资源编号，不通过浏览器地址推断 |
| lease_seconds | 默认 300 秒，范围 1～3600 秒，并受访问许可剩余有效期约束 |

受管理会话由 Node 的适配器执行 `async_playwright()`、`chromium.launch()`，创建默认 1280×720、zh-CN 的 context 和空白 page，以保留当前 MCP 启动行为。后续可以明确创建其他 context/page。

借用 Chrome 会话由 Node 连接已配置的本机 CDP，枚举原有 context/page，不创建新 context 来代替复用登录。只有一个页面时可返回默认页；多个页面时 `default_page_id` 为空，由调用方明确选择。

准备结果中的对象目录示意：

```json
{
  "session_id": "session_001",
  "state": "READY",
  "tool": "playwright",
  "tool_api_version": 1,
  "ownership": "managed",
  "root": {"type": "browser", "id": "browser_001"},
  "contexts": [{"type": "context", "id": "context_001"}],
  "pages": [{"type": "page", "id": "page_001", "context_id": "context_001", "url": "about:blank"}],
  "default_page_id": "page_001"
}
```

这些 ID 由 Node 分配，与真实 SDK 对象的映射只存在于 Node worker。它们不是 CDP targetId，不包含对象内存地址、文件路径或秘密。Hub 保存展示所需的目录镜像；收到引用时，Node 仍必须验证所属会话、代次、类型和生存期。

会话终止、对象关闭或 worker 重启后引用失效；不能把旧 ID 填到新会话继续用。未来工具可以返回其他 root 类型，无需创建 Browser、Context 或 Page。

## 4. 请求格式与参数

### 4.1 HTTP 调用体

填写输入框示例，假定 `page_001` 来自刚才的会话查询：

```json
{
  "request_id": "cmd_fill_001",
  "method": "locator.fill",
  "target": {
    "type": "page",
    "id": "page_001",
    "locator": [
      {"method": "get_by_role", "params": {"role": "textbox", "name": "用户名", "exact": true}}
    ]
  },
  "params": {"value": "demo", "timeout": 10000}
}
```

`session_id` 来自 URL；tool 和合同版本由已建立的会话决定，调用方不重复配置。`request_id` 是调用方生成的不透明标识，建议 UUID；长度沿用项目 Identifier 的 1～128 字符范围与字符限制。`method` 必须在当前工具动作目录中；未知方法、未知参数和错误目标类型在执行前拒绝。

### 4.2 Hub 下发给 Node 的执行信封

```json
{
  "protocol_version": 2,
  "type": "execute",
  "request_id": "cmd_fill_001",
  "session_id": "session_001",
  "connection_generation": 7,
  "tool": "playwright",
  "tool_api_version": 1,
  "method": "locator.fill",
  "target": {
    "type": "page",
    "id": "page_001",
    "locator": [
      {"method": "get_by_role", "params": {"role": "textbox", "name": "用户名", "exact": true}}
    ]
  },
  "params": {"value": "demo", "timeout": 10000},
  "remaining_ms": 9500
}
```

| 字段 | 生成者与意义 |
| --- | --- |
| protocol_version / type | 公共信封版本和消息类别 |
| request_id | 一次项目调用；返回、事件和查询均用它关联 |
| session_id | Hub 已授权且已占用资源的工具会话 |
| connection_generation | Hub 当前 Node 连接代次；旧连接的消息不能作用于新会话 |
| tool | 会话绑定的工具；Node 不能仅依据调用方字符串任意导入模块 |
| tool_api_version | 本工具动作声明版本；与底层 Playwright 包版本区分 |
| method / target / params | 经 Hub 公共校验后的方法、目标和参数；Node 再校验并执行 |
| remaining_ms | Hub 扣除已消耗时间后的预算，仅内部使用，不是第二个用户超时参数 |

签发给 Node 的指令不携带调用方 Bearer，不携带新的浏览器启动环境、可执行文件路径或秘密。资源的启动配置仍由 Node 所有者本地维护。

### 4.3 参数命名、超时与结果

采用 Python SDK 的 snake_case 参数名，例如 `wait_until`、`full_page`、`viewport_size`。`params` 仅接受动作目录声明的字段，不自动透传所有 SDK 参数。

动作的统一超时字段为 `params.timeout`，单位毫秒，默认 10000、范围 1～30000；MCP 既有 `timeout_ms` 仅作为外部适配名称，不同时要求两项。Hub 从接受请求开始计算预算，包含排队；Node 收到后按 remaining_ms 计时，并在出队后扣减本机排队耗时。两机不依赖墙上时钟同步，网络传输可能导致两端等待截止时间不同，Hub 等待到期并不表示远端已停止。支持原生 timeout 的 Playwright 方法注入剩余预算；没有该参数的方法由处理函数管理等待。

不能用 `timeout=0` 获取无限执行。会话创建的准备时间与普通动作区分，沿用 30 秒准备上限。网络断线或 HTTP 等待时间到达不会触发重放；如果操作还在进行，返回 202 与 request_id，再通过查询取得结果。

Playwright 官方指出直接取消正在执行的调用会导致未定义行为，因此采用库本身超时，外部等待与内部执行任务分离。外部等待到期时不能直接取消正在操作页面的协程并宣称停止；显式释放会话走专用关闭流程，受管理浏览器关闭、借用连接释放后再确认结果。

对于已进入浏览器调用的写操作，即使返回 TimeoutError，也不能推出副作用没有发生。结果要标记 OUTCOME_UNKNOWN，由调用方观察页面或业务数据后决定下一步。

### 4.4 Locator 表达

不跨机器保存 Locator 对象。请求携带根 Page 引用及最多 16 步的定位描述；Node 在本次执行时构造 Locator。

首版允许 `frame_locator`、`locator`、`get_by_role`、`get_by_label`、`get_by_text`、`get_by_test_id`。仅允许这些明确的构造步骤，不允许属性遍历或任意方法调用。iframe 的 selector 必须显式给出。

HTTP 参数默认值尽量遵循 Python SDK；MCP 为维持旧语义会明确填 `exact=true`。无论从哪种入口调用，交互动作均要求唯一匹配，不自动选第一个；0 个匹配由 Playwright 在预算内等待，已知多个匹配返回 AMBIGUOUS_TARGET。

拖拽的 `params.target` 也使用同样的目标描述，并校验两端都属于该会话；不允许用其他会话的 Page 作为目标。

## 5. 首版方法目录与调用范式

下列是需要覆盖的首版动作族。实施时每个动作要补齐可机器读取的参数类型、默认值、结果模型和错误模型，不以表中方法名作为自动反射许可。

| 方法或动作族 | 目标与输入要点 | 返回 |
| --- | --- | --- |
| `browser.contexts` / `browser.new_context` | browser；创建选项首版支持 viewport、locale 等已列明配置 | context 引用列表 / 新引用 |
| `context.pages` / `context.new_page` / `context.close` | context；关闭不能越过借用所有权规则 | page 引用列表 / 新引用 / completed |
| `page.goto` | page；url、wait_until，默认 domcontentloaded | 当前 url、title、http_status 摘要，不返回 SDK Response 对象 |
| `page.go_back` | page；wait_until | 当前 URL 摘要 |
| `page.title` / `page.url` / `page.frames` | page；属性通过同一种调用格式读取 | 字符串 / frame 元数据 |
| `page.close` | page | completed；关闭事件使引用失效 |
| `page.aria_snapshot` | page；固定读取配置 | snapshot、truncated，最多 20000 字符 |
| `page.screenshot` | page；full_page，默认 false；首版 PNG | binary 结果，最大 2 MiB；不接受 path |
| `page.set_viewport_size` | page；viewport_size.width/height | 实际 width/height |
| `page.keyboard.press` / `page.mouse.wheel` | page；key 或 delta_x/delta_y | completed 等明确 JSON |
| `locator.fill` / `locator.click` / `locator.press` / `locator.hover` | page + locator；value / button / key 等本动作声明参数 | completed；需要时附当前 URL |
| `locator.select_option` / `locator.set_checked` | page + locator；value 列表 / checked | 实际选中值 / 实际 checked |
| `locator.drag_to` | 源 Locator 与 params.target 定位描述 | completed |
| `locator.inner_text` / `locator.input_value` / `locator.wait_for` | page + locator；读取或状态等待 | 有界值 / completed |
| `locator.set_input_files` | page + locator；files，显式 name/mime_type/data | 上传文件名列表；最多 32 个、解码后合计 4 MiB |
| `runbridge.inspect_dom` / `runbridge.capture` | page；当前固定采集合同 | 原 MCP JSON；最大 256 KiB |
| `runbridge.wait_for` | page + locator；text/value 和期望值 | completed |
| `runbridge.tabs` / `runbridge.dialog_policy` / `runbridge.session_state` | session 或 page；明确操作或策略 | 页面目录、选页、策略或技术状态 |

整个浏览器的关闭使用 `DELETE /v2/sessions/{id}`。若文档提供 SDK 风格 `browser.close` 写法，它只是该释放操作的别名，由 Hub 进入同一管理流程，不能绕过会话清理协议。借用 Chrome 的会话释放只断开项目持有的连接；不把它翻译成关闭用户浏览器。

典型操作顺序：

1. 查询 Node 工具与资源，确认 READY/FREE。
2. 创建 `playwright` 会话，保存返回的 session_id 和 default_page_id；这些值从响应取得，不手填猜测。
3. 对该 page 提交 `page.goto`，检查结果状态及页面地址。
4. 用 Locator 描述提交 `locator.fill`、`locator.click`。
5. 通过读取或固定 DOM 采集检查实际业务结果；需要图像时调用 screenshot 或订阅已返回的画面入口。
6. 释放会话，检查 cleanup；UNKNOWN 不当成已清理。

这相当于把 `page.get_by_role(...).fill(...)` 的调用范式拆成结构化目标与方法参数，不要求用户获取或序列化真正的 SDK 对象。

## 6. 接收、结果和事件

### 6.1 执行确认

Node 校验并接收后发 `command_ack`，排队结束开始执行时发 `command_started`。二者均包含 protocol_version、request_id、session_id、connection_generation；确认收到或开始都不表示动作完成。

### 6.2 成功

```json
{
  "protocol_version": 2,
  "type": "result",
  "request_id": "cmd_fill_001",
  "session_id": "session_001",
  "connection_generation": 7,
  "status": "SUCCEEDED",
  "execution_outcome": "COMPLETED",
  "result": {"kind": "json", "value": {"completed": true}},
  "error": null
}
```

`COMPLETED` 只表示处理函数得到明确的技术完成结果，不证明业务目标正确。成功 HTTP 传输也不能替代 `status` 和业务读取。

### 6.3 错误与不确定结果

```json
{
  "protocol_version": 2,
  "type": "result",
  "request_id": "cmd_click_002",
  "session_id": "session_001",
  "connection_generation": 7,
  "status": "FAILED",
  "execution_outcome": "OUTCOME_UNKNOWN",
  "result": null,
  "error": {
    "code": "ACTION_TIMEOUT",
    "message": "点击等待超时，业务结果需要重新观察",
    "stage": "execute",
    "retryable": false
  }
}
```

`status` 的终态为 SUCCEEDED、FAILED、UNKNOWN。UNKNOWN 用于失联、进程异常等无法获得最终执行结果的情况；已收到超时异常可以是 FAILED，但其副作用仍为 OUTCOME_UNKNOWN。

`execution_outcome` 取 NOT_STARTED、COMPLETED、OUTCOME_UNKNOWN。执行前参数或定位拒绝为 NOT_STARTED；已进入可能写入的调用后无法确定副作用时为 OUTCOME_UNKNOWN。只读超时可报告明确读取失败，不推断写入。

错误字段包含稳定 code、简体中文公开说明、stage 和 retryable；不返回凭据、Node 路径、堆栈或本地环境变量。retryable 仅表示修正环境后可由调用方发起新请求，Hub 不据此自动重试。

| 错误族 | 示例 | 处理 |
| --- | --- | --- |
| 鉴权/授权 | UNAUTHORIZED、RESOURCE_OUTSIDE_GRANT | Hub 拒绝，NOT_STARTED |
| 合同不匹配 | PROTOCOL_UNSUPPORTED、TOOL_API_UNSUPPORTED、METHOD_UNSUPPORTED | 不回退到旧原生协议 |
| 参数/引用 | INVALID_PARAMS、OBJECT_NOT_FOUND、OBJECT_TYPE_MISMATCH、OBJECT_CLOSED | Node 执行前再次检查，NOT_STARTED |
| 定位 | AMBIGUOUS_TARGET、TARGET_NOT_FOUND | 不自动替换目标或点击第一个 |
| 请求关联 | REQUEST_ID_CONFLICT、RESULT_EXPIRED、REQUEST_LIMIT | 查询已有记录，不重新执行 |
| 执行/资源 | ACTION_TIMEOUT、RESOURCE_BUSY、SESSION_NOT_ACTIVE | 结合 stage 和 outcome 判断 |
| 连接/进程 | NODE_DISCONNECTED、WORKER_EXITED、RESULT_UNKNOWN | 不宣称已完成或已回滚 |

HTTP 网关在接收前拒绝时使用对应 4xx；接受后的命令结果使用统一结果体，调用方检查 status。仍在执行时用 202；已知终态用 200 返回结果体。MCP 将 FAILED/UNKNOWN 包装为 `isError`，保留稳定 code 与 outcome。

### 6.4 二进制

结果 `kind=binary`，包含 `mime_type`、`encoding=base64`、`size`、`data`。size 按解码后字节计算。截图上限 2 MiB；文件上传 files 中 data 也是 base64，沿用现有 name/mime_type/data 写法及 4 MiB 总量。

不接受调用方给出的 Node 本地上传或输出路径。大文件分片、持久化下载和 Trace 文件不是首版功能；后续如果确有需求，在通用结果中增加明确文件引用和传输合同，不能默默放宽 JSON 消息限制。

### 6.5 事件

Node 发出 `type=event`，包含 session_id、connection_generation、递增 event_seq、event 名称及 data。首批包括 page_created、page_closed、page_updated、dialog_observed、selection_changed；只传目录和技术状态，不把回调函数传回调用方。

事件源自实际持有对象的 worker。Hub 对对象目录按序应用；出现事件缺口时，将目录标为待刷新并查询 `runbridge.session_state`，不把旧目录当成当前事实。页面关闭会使旧引用失效，切页会清除旧画面。事件不代表业务断言已通过。

## 7. 请求唯一性、顺序和恢复

### 7.1 去重与记录

- 操作键为 `(grant_id, session_id, request_id)`；Hub 记录规范化 tool/method/target/params 的摘要和状态。
- 同 ID 同内容：返回已有状态或缓存结果；同 ID 不同内容：REQUEST_ID_CONFLICT。摘要不包括 Hub 内部的 remaining_ms。
- Hub 在下发前持久化 DISPATCHED，避免重启后误认为未执行。发送是否成功无法确认时保守标记 UNKNOWN，不能重新投递。
- Node 也按会话和 request_id 检查重复，不因执行连接的异常重复触发动作。
- 完整结果采用有界内存缓存，默认每会话最多 128 项且 Hub 全局最多 64 MiB；先淘汰已完成结果，不能丢弃在途关联。
- 请求 ID、摘要、状态和 outcome 作为元数据保留；单会话最多 10000 条，终止 24 小时后可清理。达到上限时拒绝尚未下发的新请求，不驱逐当前会话的去重记录来重新执行。
- 大图像和上传内容不落 SQLite。缓存结果已淘汰时返回 RESULT_EXPIRED，并附仍可查询的状态；不能把“没有缓存”当成“没有执行”。

Node 重连和 Hub 重启不恢复旧 SDK 对象，不重放旧命令。旧会话结束为 INTERRUPTED；未确认的操作标记 UNKNOWN，清理标记 UNKNOWN。重新建立会话需要调用方明确发起，旧对象编号不能继续用。

### 7.2 串行与停止

每会话最多执行 1 条普通动作，等待队列默认 16 条；满时在下发新动作前返回 RESOURCE_BUSY。不同 Node/资源位可并行，首版每个浏览器资源仍独占一个会话。

接收循环不直接等待 Playwright 操作完成；心跳、控制关闭、事件和画面独立运行。会话停止通过控制连接优先处理，不排在一个 30 秒等待动作之后。排队请求在出队时重新验证有效期和目标引用。

调用方 HTTP/MCP 断线时，Hub 不默认重发或取消已开始动作；仍可按 request_id 查询。租期、撤销和显式释放则进入关闭流程。停止不能撤销已经发生的点击或业务提交。

借用会话关闭时只断开连接并撤下项目句柄；已发生的页面操作仍然存在。受管理 worker 的退出也不能只根据 Python 进程已结束就推断 Chromium 已回收，需按 Node 清理方案确认。

## 8. 工具发现和 MCP 适配

Node 能力中声明工具名、底层运行时版本、tool_api_version、支持的方法集合，以及资源的 tool/mode/readiness/occupancy。运行时版本用于诊断；调用方无需安装同版本 Playwright。许可仍绑定 resource_id，工具变更需要新资源编号，不能将已授权资源静默改成另一个工具。

Hub 保存版本化方法声明，公开参数类型、默认值、目标类型、结果类型和可能副作用。Node 只上报支持的声明版本及方法摘要，避免将整个方法 schema 塞进 64 KiB 心跳消息。两端声明通过相同 JSON 契约样例验证，不在运行时加载远程 Python 模块。

HTTP 是统一方法接口；MCP 为适合 Agent 的明确工具包装。现有工具名和参数保留，新增加只读 `tool_request_status(session_id, request_id)`，用于查询任何工具的异步或结果未知请求。MCP 端不重新实现 Locator、浏览器读取或页面采集。

新增工具时，声明自己的 target、params、结果和资源模型，不改变公共信封。例如将来可增加另一个工具适配器；本方案不预先承诺该工具的动作、依赖或实际支持状态。

## 9. 合同验证

实现阶段至少保存这些可执行契约样例：创建会话、打开网页、填写、点击、读取、截图、上传、页面创建与关闭、弹窗策略、错误引用、错误动作、重复 ID、结果丢失、停止与清理。

同一组样例需要通过 Hub 和 Node 的模型与动作校验，并在接口测试中验证实际传输。工具参数不能只靠两边同名 Python 类而假定一致；新增字段、默认值或返回类型需要同步更新声明与样例。

业务验收使用真实页面计数、表单持久化、文件内容和实际画面，尤其验证断线后重试同一 ID 没有产生第二次写入。协议静态检查通过不等于新架构已经可用。
