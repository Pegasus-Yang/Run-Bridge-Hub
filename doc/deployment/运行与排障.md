# Hub 运行与排障

[文档导航](../README.md) · [部署与运行](部署与运行.md) · [配置参考](../reference/部署配置与凭据.md)

适用于 Hub 0.5.1。按服务健康 → 远程可达 → 授权 → 节点上报 → 会话／MCP → 画面定位。Node 本机浏览器和字体由 Node 所有者按其项目指南处理。

## 服务与网络

| 现象 | Hub 部署者检查 |
| --- | --- |
| 启动失败 | wheel／Python 版本、登记文件路径与长度、SQLite 目录权限、心跳超时大于间隔 |
| 本机健康通过，远程失败 | 监听网卡、实际访问地址、防火墙、路由与反向代理 |
| 重启后节点均消失 | 是否误用了另一部署目录或空 SQLite；保留原库，不重新登记掩盖问题 |
| WebSocket 失败 | Upgrade、Authorization、User-Agent、x-playwright-* 转发及代理超时 |
| 节点 OFFLINE／能力过期 | 确认控制连接日志与心跳，由所有者检查出站网络及重复身份连接 |

健康检查只证明 HTTP 入口，不证明 Node、浏览器或业务可用。CLI 使用单 Worker，不能用多 Worker 直接分担当前进程的连接路由。

## 登记、访问与 MCP

| 状态／错误 | 处理 |
| --- | --- |
| 登记认证失败 | 双方使用同一个纯文本登记令牌；核对文件与环境变量优先级 |
| 401 INVALID_ACCESS_TOKEN | 调用方提交访问许可，检查过期／撤销；登记令牌不能替代 |
| NODE／RESOURCE／SESSION_OUTSIDE_GRANT | 核对当前许可范围及会话归属，不能换另一个 token 接管 |
| MCP 404 | 确认安装对应 extra，并在启动时显式开启入口 |
| MCP 421／403 | 核对请求实际 Host／Origin 和允许列表，不能关闭检查绕过 |
| BROWSER_CONNECT_FAILED | 核对 Hub 内部可达根地址及原生路由，检查失败会话的清理 |
| PLAYWRIGHT_VERSION_MISMATCH | MCP SDK 和远程运行时主次版本匹配；交由双方分别检查自己的版本 |

Hub MCP 请求体上限 8 MiB；合法传输中上传文件解码后合计仍受 4 MiB 限制。工具错误读取 isError 和结构化错误，不以 HTTP 200 判断动作成功。

## 会话、恢复与画面

READY／ACTIVE、技术终态和 cleanup 各有含义。未知写操作先核对业务效果；不因超时重放。MCP 创建请求可按原 request_id 查询已分配身份，具体恢复规则见[MCP 指南](../user-guide/MCP浏览器接入.md)。

RESOURCE_BUSY 或 cleanup=PENDING／UNKNOWN 时保留占用证据，联系所有者核查本次资源。Hub 重启不恢复旧 SDK 对象和 MCP Page，不把旧会话改成可继续执行。

画面 WAITING_TARGET 需要调用方明确选页；STALE／ERROR 时撤下旧图。PNG 从独立二进制消息解包；原生连接正常不证明画面正常，画面状态也不证明业务通过。详细合同见[画面指南](../user-guide/浏览器画面流接入.md)。

## 维护与证据

按部署指南一致性备份 SQLite。0.5.1 schema 3 升级后，旧程序回退使用升级前备份。排障保留版本、工作目录、公开错误码、节点／会话标识及时间；日志和反馈中不回显令牌、网页私有数据或完整协议载荷。

源码构建、回归和同机调试见[开发与联调](../development/本地开发与联调.md)。历史验收只代表当次边界，不作为当前服务在线证据。
