## 需要修正的问题

### F1 · P1 · 启动失败后丢失请求到会话的关联

位置：`src/runbridge_hub/browser.py:103–132、173–189、249–255`；相关上游路径为 `sessions.py:124–139`。

`_open` 在申请会话后连接浏览器，连接失败会清理并删除 BrowserSession；请求查询只从活动条目或成功完成的 Task 中取得 session_id。失败 Task 不提供会话身份，因此即使会话已经分配并且清理仍为 UNKNOWN，`browser_sessions(request_id)` 也会返回空列表。SessionService 在 PREPARING 后失败的路径同样需要保留已经分配的身份。

独立探针调用真实 `_open`，只替换 Node/Playwright 连接和清理报告：结果为 `BROWSER_CONNECT_FAILED`，已分配会话为 `FAILED / UNKNOWN`，按 request_id 查询却得到 `{"sessions":[]}`。DSH 的 `runbridge.ts:419–435` 要求唯一查询结果才能恢复会话身份，这种情况会持续保留隔离，无法完成自动清理核对。

建议：在会话分配时建立请求与会话的关联；无论后续准备或连接是否成功，都能查询实际会话和清理状态。查询应区分仍在创建、确定未分配、已分配后失败和关联已失效，不将未知结果当作资源不存在，也不自动重放不确定的启动。

验证要求：覆盖分配后准备失败、SDK 连接失败、响应丢失、调用取消，以及 FAILED/UNKNOWN 和 FAILED/COMPLETE 的查询与恢复。

### F2 · P2 · 永久保留完成的 Task 及请求上下文

位置：`src/runbridge_hub/browser.py:55–56、69–82、173–189`。

两个请求缓存没有回收策略，保存成功及失败的 asyncio.Task。独立探针确认：成功请求返回后，即使会话已 CLOSED，缓存 Task 的 `get_context()` 仍持有 `REQUEST_TOKEN` 的 SecretStr。失败 Task 还会保留异常和 traceback。每次唯一请求都增加长期驻留记录，包括尚未分配资源的失败请求；这与无需长期保存访问凭据的设计意图不一致。

建议：运行中的 Task 与终态记录分离，完成后释放 Task、异常和请求上下文；终态仅保存无凭据的必要字段及会话关联。明确记录数量、保留时间或持久化策略，以及过期请求的重试语义。回收记录时不得让结果未知的同一请求重新分配浏览器。

验证要求：成功、失败、取消后不再长期持有 Bearer 上下文；记录回收和并发重复请求不破坏单次分配及异常恢复。

### F3 · P2 · 4 MiB 文件合同与 HTTP 请求上限不一致

位置：`src/runbridge_hub/browser_tools.py:202–211`、`src/runbridge_hub/mcp_server.py:190–191`。

工具、使用指南和 DSH 本机文件适配器均允许解码后合计 4 MiB，但当前 MCP SDK 的 Streamable HTTP 请求体默认上限也是 4 MiB，base64 编码和 JSON 会使合法文件在进入工具前被 HTTP 413 拒绝。

独立 ASGI HTTP 探针实际发送：原文件 `4,194,304` 字节，请求体 `5,592,794` 字节，响应 `413 Request body too large`。探针没有启动浏览器，也没有上传到远程页面。

建议：统一原文件、编码数据及 HTTP 请求体的上限；若保留 4 MiB 文件合同，传输上限应容纳合法编码及必要元数据，同时保留工具解码后的总量检查。

验证要求：通过实际 `/mcp` HTTP 入口检查恰好达到限制的单文件、多文件总量，以及超过限制的拒绝行为，不能只直接调用工具函数。

### F4 · P2 · 当前文档存在相互矛盾的能力说明

位置：两端 `doc/README.md:7、22`；Hub `doc/README.md:18`、`doc/reference/对外接口总览.md:5、12`、`doc/project/项目概况.md:11`，以及两端画面接入和架构文档。

虽然新增章节描述了 0.5.0 的 MCP 同页画面，但现有正文仍称当前版本为 0.4.0、工具数量为 12、受管理模式暂不支持画面。读者无法判断具体入口是否支持。

建议：统一当前文档为 0.5.0 和 26 个工具；明确区分 MCP 持有 Page 的受管理画面、普通 REST/SDK 会话、已授权 Chrome/Browscreen 画面。保留历史验收记录及其原版本，不用新能力改写历史事实。

## 已知边界与可选改进

- `ManagedCapture` 的截图循环能恢复瞬时截图错误，但 CDPSession 初始化失败会结束任务；目前需要显式重新选择目标才能重启。该行为应写明并补充回归；是否自动重建连接可另行决定。
- 固定 DOM 采集保持 DSH 原有主页面语义，当前没有 iframe 采集合同。交互工具接受 frame_selector，不表示可信采集也支持 iframe。
- 采集和 DOM 检查的 256 KiB 限制发生在结果传回 Hub 后，不能视为浏览器侧或原生传输的有界采集。若需要保护大页面场景，应在固定采集函数内限定文本、属性及累计结果，并明确失败或截断语义。
- 现有新增单元测试使用替身，未直接执行采集 JavaScript；真实业务操作和 PNG 验证沿用原 agent 的联调记录，本次没有重新进行远程浏览器验收。
