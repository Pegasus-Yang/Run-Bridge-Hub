# 节点总览

适用于 Hub **0.8.0**，兼容 Node **0.7.0**。页面、样式、脚本与图标均随 Hub wheel 安装；已有部署按[升级说明](../deployment/运行与排障.md#从-070-升级到-080)更新 Hub 即可使用。

Hub 在原有监听地址提供只读页面 **`/dashboard`**，默认开启。例如本机部署访问 `http://127.0.0.1:8787/dashboard`；远程访问换成 Hub 的实际地址。不增加端口、Node.js、前端构建步骤或浏览器运行依赖。

页面查询当前 Hub 的真实连接、Node 上报的能力与 Hub 资源预留，不提供分配、执行、断开或授权操作。

## 启动与口令

保留原来的启动方式：

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

启动成功后，日志直接输出当前只读口令和带口令的完整链接，例如（口令仅为格式示例）：

```text
Dashboard 只读口令：example-readonly-token-0123456789abcdef
Dashboard URL：http://127.0.0.1:8787/dashboard?token=example-readonly-token-0123456789abcdef
```

点击 `Dashboard URL` 自动进入节点总览，无需填写口令；链接保留 `token` 参数，支持刷新、收藏后再次访问。特殊字符由日志中的 URL 自动编码；手动拼接时也要对口令做 URL 编码。监听 `0.0.0.0` 或 `::` 时日志提供本机回环地址，远程访问将主机名替换为 Hub 的实际地址；端口使用实际绑定值，包括 `port: 0` 分配的临时端口。

未指定总览口令时，首次启动在**数据库所在目录**自动生成 `web.token`，权限 `600`，默认路径 `.runbridge/web.token`；重启继续使用同一文件。也可打开不带参数的 `/dashboard`，手动输入日志或文件中的单行口令，不加引号或 `Bearer `。

口令允许查看此 Hub 全部节点的主机、能力及连接信息。页面将口令保存在当前页面内存，通过 Bearer 请求总览接口，不使用 Cookie 或浏览器存储；带参数访问时口令也保留在链接中。点击“退出”或收到口令无效响应时清除链接里的口令参数并返回登录页。只读口令不能替代登记令牌、Node 身份令牌或执行访问许可。

需要预先配置时，在部署目录生成另一份独立文件：

```bash
.venv/bin/runbridge-hub generate-token --output .runbridge/dashboard.token
```

在 `hub.yaml` 指定路径，相对路径以 YAML 所在目录为准：

```yaml
enrollment_token_file: .runbridge/enrollment.token
web_token_file: .runbridge/dashboard.token
```

来源优先级：显式 `web_token_file` → `RUNBRIDGE_WEB_TOKEN` → 数据库同目录自动生成/复用的 `web.token`。显式文件缺失、为空或口令长度不在 32～256 字符时启动失败，不回退。只读口令不能与登记令牌相同。更换文件内容后重启 Hub，旧口令失效。

## 关闭 Web

在现有 YAML 增加：

```yaml
web_enabled: false
```

不使用 YAML 时可运行：

```bash
.venv/bin/runbridge-hub serve --enrollment-token-file .runbridge/enrollment.token --disable-web
```

关闭后 `/dashboard`、`/dashboard/assets/…`、`/dashboard/api/nodes` 均返回 404，不读取、生成或输出只读口令及访问链接，不影响节点、HTTP 或 MCP。`--settings` 仍不能混用其他启动参数。

## 查看连接、资源和能力

页面每 5 秒刷新一次，支持连接状态筛选，以及按名称、ID、主机名、系统和架构搜索。顶部统计始终表示全部节点，不随筛选变化。后台暂停轮询，回到页面立即更新。点节点名称或右侧箭头可看主机、版本、连接代次、心跳、资源就绪/占用、支持方法及后端安装/覆盖信息。

| 信息 | 真实判断依据 |
| --- | --- |
| 在线 | 当前控制连接有效、未超过心跳超时，且已收到本次连接的能力快照 |
| 准备中 | 当前连接有效，正在等待本次连接的能力上报；旧快照不代表当前能力 |
| 离线 | 没有当前连接或已超过心跳超时；保留登记信息与历史快照 |
| 可用资源 | Node 在线，资源 `READY`、`FREE`，且没有 Hub 预留 |
| 已占用资源 | 在线资源报告 `BUSY`，或 Hub 已预留，包括会话准备和未确认清理期间 |
| 部分占用 | 节点的部分资源被占用，其余已就绪且空闲的资源仍可用 |
| 未知 / 未就绪 | 不计为空闲；待探测、待授权、不可用及占用未知在详情分别展示 |
| 支持能力 | 只将 `coverage_status=SUPPORTED` 作为支持；安装了工具不等于可执行 |
| 最近心跳 | Hub 最近收到当前控制连接上报的时间，包含能力上报，与 RTT 分开 |

准备中或离线的资源占用按未知显示，不计入顶部实时资源统计；历史能力有标记。没有登记节点时显示空状态，不填充演示节点。

## 实测 RTT

**控制通道 RTT** 是 Hub 在当前 Node 控制 WebSocket 发送 Ping，到收到对应 Pong 的实测往返耗时，包含真实网络及对端调度时间。它不是心跳间隔、快照年龄、网页到 Hub 的 HTTP 耗时或浏览器动作时长。

标准 CLI 使用 `runbridge_hub.transport.ControlWebSocketProtocol`，连接后立即测一次，随后复用默认约 20 秒的保活周期。使用 WebSocket 标准控制帧，不修改 Node 应用合同，不为页面刷新创建浏览器会话。

- 未收到有效 Pong 时显示“待测量”。本机小延迟保留小数，不将未测量显示为 `0 ms`。
- 样本小于 60 秒时显示数值，超过后显示“已过期”。详情可看采样时间。
- 离线显示 `—`；重连使用新连接独立采样，不继承旧 RTT。
- 使用其他 ASGI 服务器或默认 WebSocket 实现自行加载 `create_app`，没有测量扩展时显示“未启用测量”。请用标准 CLI 验收 RTT。

“良好 / 一般 / 较高”为页面提示，阈值为 `<100 ms`、`100～<300 ms`、`≥300 ms`，不影响资源分配。原理参考 [websockets 延迟说明](https://websockets.readthedocs.io/en/stable/topics/keepalive.html)。

页面到 Hub 断网时，上次结果被显著标记为历史并自动重连；不继续显示 Hub 正常。口令失效则清除节点数据并返回登录。

## 接口和成功检查

`GET /dashboard/api/nodes` 使用独立总览 Bearer 口令。响应禁止缓存，包含查询时间、Hub 版本、刷新周期、在线/准备中/离线数量、在线资源统计及每个节点的连接、能力、资源和 `latency`。

`latency.status` 为 `PENDING`、`MEASURED`、`STALE`、`UNAVAILABLE` 或 `OFFLINE`；`rtt_ms`、`measured_at`、`sample_age_ms` 没有有效值时为 `null`。接口不提供身份/许可令牌、令牌哈希、会话参数、页面 URL 或执行内容。

运行验收分别确认：

1. 日志输出当前只读口令和带参数 URL；点击链接直接显示节点，刷新仍可访问。退出清除参数；错误口令提示重新输入。不带参数时手动登录仍可用。
2. 页面、样式与图标加载；无口令、错误口令、登记令牌、身份令牌及调用许可读取总览接口均为 401。
3. 真实 Node 上线并显示主机和能力；收到对应 Pong 后出现 RTT 数值与采样时间。
4. 正常申请资源后变占用，确认释放 `COMPLETE` 后恢复可用。
5. 停止 Node 后变离线，RTT 清空，能力标历史且资源不再可用。
6. 关闭 Web 后所有总览入口为 404，原 Hub 功能正常。

仅页面 HTTP 200、固定示例延迟或 Node 进程存在，不代表已完成真实数据验收。

资源在安装包的 `runbridge_hub/web/`，随 Hub 分发。图标来自 [Phosphor Icons](https://github.com/phosphor-icons/core) 2.1.1，附 MIT 许可证，运行时无需 CDN。
