# RunBridge Hub 项目概况

[项目首页](../../README.md) · [文档导航](../README.md) · [安装](../deployment/安装与运行.md)

## 当前定位与约定

节点管理与连接网关，负责登记、许可、资源/会话路由以及可选画面分发。

| 项目约定 | 值 |
| --- | --- |
| 当前包版本 | 0.4.0 |
| 整体名称 | RunBridge |
| 本项目/目录 | RunBridge Hub / runbridge-hub |
| Python 包/源码 | runbridge_hub / src/runbridge_hub |
| CLI | runbridge-hub |
| Python 环境 | 标准 3.14.x、各项目根 .venv、uv 管理 |

## 已实现的职责

| 部分 | 当前行为 |
| --- | --- |
| 节点管理 | 登记、身份认证、访问许可、能力/资源查询 |
| 会话管理 | 独占预约、租期、版本兼容、创建许可归属与清理协调 |
| 协议网关 | Node 控制连接、原生 Playwright/CDP 隧道、关闭与背压 |
| 画面分发 | 内存最新 PNG、独立只读消费者、查询中的临时 visual |
| 持久化 | SQLite v2 的节点、许可和会话元数据，不保存执行帧或 PNG |

Hub、Node 和调用方通过公开协议协作，部署和包导入独立。调用方直接使用官方 SDK 执行业务；节点查询、会话生命周期与画面使用 RunBridge 接口。[对外接口总览](../reference/对外接口总览.md)给出完整边界。

## 怎么安装和使用

按[首次连通](../user-guide/快速开始.md)启动 Hub、登记 Node、签发许可；再选择[已有 Chrome](../user-guide/Chrome复用快速开始.md)或[受管理 Chromium](../user-guide/Playwright快速开始.md)。调用脚本与平台按[对接指南](../user-guide/调用方对接与使用.md)申请、执行、断言与释放，需要持续 PNG 时再按[画面指南](../user-guide/浏览器画面流接入.md)订阅。

当前具体实现见[执行架构](../architecture/Playwright执行与会话管理.md)、[Chrome 授权与清理](../architecture/Chrome复用与授权清理.md)、[画面采集与分发](../architecture/浏览器画面采集与分发.md)。实际证据见[0.4.0 画面验收](浏览器画面流验收记录.md)和[虚拟机跨机器/中文字体](虚拟机Node跨机器验收记录.md)；历史 0.1.0–0.3.0 验收保留原日期。

## 计划与未验证边界

以下仍是后续工作：独立业务 HTTP 执行、Appium/ADB/设备资源、单标签页授权，以及生产 TLS/代理与容量验证。设计中出现这些路线不代表已开放对应入口。

100 在线用户/10 并发执行是原首期容量目标，没有完成专项压测，不能当作当前容量保证。当前浏览器资源以单 Node/单资源/单原生调用会话为界，多个画面消费者共享一个源。

外部 Agent 编排、模型调用、用例管理和业务报告不在本项目内实现。当前状态、截图、SDK 异常或 cleanup 也不自动给出业务 PASS；业务验证属于调用方。
