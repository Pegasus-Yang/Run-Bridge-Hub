# Hub quick start

[简体中文](快速开始.md) · English

For installation directly from GitHub source, start with the [project README](../../README.en.md#quick-start). This guide deploys an existing **Hub 0.9.3** wheel into a separate directory. Configuration, verification, and handoff are the same afterward. Run these steps on the **Hub machine**; deploy Node using its own guide.

## Before you start

- Prepare Python **3.14.x**, global [uv](https://docs.astral.sh/uv/getting-started/installation/), and a network endpoint reachable by Node. See [Python downloads](https://www.python.org/downloads/) for the base runtime.
- Obtain `runbridge_hub-0.9.3-py3-none-any.whl` and save it to `~/Downloads/`, or use the source-install route above.
- Commands use macOS / Linux paths and a new `~/runbridge-hub` directory. Preserve the database and credentials of an existing deployment.

## Install and generate credentials

```bash
mkdir -p ~/runbridge-hub
cd ~/runbridge-hub
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python ~/Downloads/runbridge_hub-0.9.3-py3-none-any.whl -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/runbridge-hub generate-token --output .runbridge/enrollment.token
.venv/bin/runbridge-hub generate-token --output .runbridge/hub.token
```

The generator saves UTF-8 single-line random text, normally 64 characters, with directory mode `700` and file mode `600`. It refuses to overwrite files. The original `enrollment.token` is the enrollment attachment for Node maintainers; `hub.token` is the separate client claim credential. Neither file contains JSON, quotes, `Bearer `, or `token=`.

## Save configuration and start

Create `hub.yaml` in the deployment directory:

```yaml
host: 0.0.0.0  # Allow Nodes on other devices to connect.
enrollment_token_file: .runbridge/enrollment.token
hub_token_file: .runbridge/hub.token
public_url: http://hub.example:8787  # Replace with the actual reachable Hub base URL.
```

Port defaults to `8787` and the database to `.runbridge/hub.sqlite3`. Relative paths resolve from the **YAML file's directory**. Default options need not be repeated.

```bash
.venv/bin/runbridge-hub serve --settings hub.yaml
```

Keep this terminal open after successful startup. Inspect any error before proceeding. See the [annotated YAML](../reference/examples/Hub启动配置.en.yaml) and [parameters](../reference/参数详解.en.md) for other settings.

Open the logged `Dashboard URL` to enter the [read-only dashboard](节点总览.en.md). The link includes its separate token and supports refresh. The page updates every five seconds. An empty list before Node enrollment is normal. For remote access, replace a logged loopback host with the actual Hub host.

## Check Hub and hand off enrollment material

In a second terminal on Hub:

```bash
curl --fail http://127.0.0.1:8787/health
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'
```

Expect `{"status":"ok","protocol_version":2}` and installed version `0.9.3`. Health confirms Hub availability; it does not check a remote browser and does not report the package version.

Privately give the Node maintainer the actual reachable base URL, the original enrollment file, paired versions **Hub 0.9.3 / Node 0.8.2**, and the Node deployment guide. If enabled, also identify the MCP endpoint for clients. Separately give authorized clients `hub.token` and the same base URL.

`0.0.0.0` is a bind address, not a handoff URL. On Node, `127.0.0.1` means Node itself. Base URLs do not end in `/health`, `/v1`, `/v2`, or `/mcp`. Ask the Node maintainer to check `/health` from its network before enrollment.

## Enable MCP when needed

Stop this Hub instance and install the extra in the same environment:

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_hub-0.9.3-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
```

Add `mcp_enabled: true` to the original YAML and restart with the same command. By default, local and remote MCP clients need no Host allowlist. Configure a nonempty list only to restrict entry hosts:

```yaml
mcp_enabled: true
mcp_allowed_hosts:
  - "hub.example:8787"
```

An omitted list or `[]` allows any Host; a nonempty list allows only its entries, without implicitly adding loopback addresses. Entries identify the MCP URL's host and port, not a client or Node IP. Normal clients without an Origin header need no `mcp_allowed_origins` setting.

HTTP reachability alone does not prove MCP authentication. Actual calls use the lease's `access_token`; see [MCP integration](MCP浏览器接入.en.md).

## Verify a complete call after Node connects

Follow the [client guide](调用方对接与使用.en.md#1-claim-node-through-hub) to claim Node. Confirm managed resource `chromium` is ready and free. Save the real access configuration as `.runbridge/access.json`. Copy [执行会话调用.py](../reference/examples/执行会话调用.py) and [node_lease.py](../reference/examples/node_lease.py) into the deployment directory. Both use the Python standard library.

```bash
cd ~/runbridge-hub
chmod 600 .runbridge/access.json
rb_check_url=$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path(".runbridge/access.json").read_text())["hub_url"].rstrip("/") + "/health")')
.venv/bin/python 执行会话调用.py --access-file .runbridge/access.json --url "$rb_check_url"
.venv/bin/python node_lease.py release --access-file .runbridge/access.json
```

The browser on Node opens Hub's actual health page, reads it, saves `page.png`, and closes the session. HTTP(S) navigation is supported; `data:` and local file pages are outside the interface. Expect the real health URL, `cleanup=COMPLETE`, a PNG showing the health JSON, and lease state `RELEASED`. An empty title is normal for the JSON page. Use `--resource-id` when the resource has another ID. Borrowed mode is explained in the client guide.

## Common problems

| Symptom | Check |
| --- | --- |
| Missing `uv`, Python, or CLI | Base tools, current directory, and installation into this `.venv` |
| Credential file already exists | Reuse an existing deployment's file; use a separate directory for a new trial |
| Invalid YAML or missing file | Space indentation, field spelling, and paths relative to YAML; `~` and `$HOME` are not expanded |
| Mixed startup options rejected | Put settings in YAML when using `--settings` |
| Port occupied | Check your existing instance or choose another `port` and update handoff URLs |
| Local health works, Node cannot connect | Bind address, actual network URL, firewall, and proxy |
| Enrollment 401 | The Node must use the same original token that Hub currently reads |
| MCP 404 / 421 | 404: extra and enable flag; 421: configured nonempty Host list |
| MCP 401 / 403 | Lease validity; also check Origin and resource/session ownership for 403 |
| Calls fail while health works | Node connection, fresh capabilities, and actual resource readiness |
| Timeout or unknown result | Retain session/request IDs, query the original action, and inspect the business result before retrying |
| Dashboard unavailable | Web enable flag, installed version, and the separate current read-only token |

Stop normally with Ctrl+C and restart with the same YAML, database, and credentials. See [deployment](../deployment/部署与运行.en.md) for backups and [operations](../deployment/运行与排障.en.md) for upgrades and cleanup review. Some CLI output and dashboard labels remain Chinese.
