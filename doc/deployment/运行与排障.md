# Hub 运行、排障与升级

适用于 Hub 0.9.1 / Node 0.8.1。Hub 统一分配整个 Node 的匿名独占使用权，不维护用户；设备身份、Hub 申请凭据、租约令牌和总览口令分别使用。

| 现象 | 检查与处理 |
| --- | --- |
| HUB_ACCESS_NOT_CONFIGURED | 配置独立 hub_token_file 或 RUNBRIDGE_HUB_TOKEN；不会复用登记凭据 |
| PUBLIC_URL_REQUIRED | 在 Hub YAML 配置调用方实际可达的 public_url；包含代理前缀，不以 /mcp 结尾 |
| INVALID_HUB_TOKEN | 只用于资源池及领取的 Hub 凭据不匹配；不要使用登记/总览/设备令牌 |
| NODE_LEASE_BUSY | Node 已领取、回收中或待核查；不能用新 request_id 抢占，等待原租约释放 |
| NODE_OFFLINE / NODE_NOT_READY | 设备控制连接、心跳、工具探测、实际 READY/FREE 能力 |
| 执行或续租 401 | 原租约已释放、到期或空闲回收；用原令牌查询原 grant_id，不能重新领取后重放原动作 |
| LEASE_TOO_LONG / INVALID_REQUEST | lease_seconds 必须为正整数且不超过当前上限；默认3600、上限默认86400，浏览器会话另限1～3600 |
| 同 request_id 重试没有 access_token | 设计如此：原秘密只交付一次；保留原文件或等待空闲回收，不从共享凭据恢复别人的令牌 |
| RELEASING / QUARANTINED | 正在清理 / 清理未知；旧令牌均不能执行，只有 RELEASED 后才解除使用权占用 |
| 会话已 CLOSED 但 Node 仍 HELD | 浏览器关闭与 Node 交还分别操作，整批结束还需 DELETE /v1/grants/{grant_id} |
| 数据库已被 Hub 或维护进程使用 | 同数据库只允许一个进程，先停止原实例；不要删除 .lock 文件来绕过进程锁 |
| MCP 404 / 421 / 403 | 检查启用状态、实际 HTTP Host/Origin 允许列表以及节点/会话归属 |
| RESULT_UNKNOWN / RESULT_EXPIRED | 查询原请求、核对业务最终状态，不自动重放点击、提交或上传 |
| 画面停止或过期 | 查 visual 状态、原租约有效期与页面目录；画面和状态轮询不刷新空闲 |
| 总览口令无效 | 使用独立只读口令；Hub 申请令牌不能登录总览，总览口令不能领取或执行 |

## 升级到 0.9.1

这是许可行为变更，不能沿用旧 grant 继续执行。执行协议2、工具API1、画面协议1、Hub YAML格式1、Node YAML格式2及设备身份格式保持不变。

1. 停止新任务，让调用方结束会话并检查实际 cleanup=COMPLETE。正常停止 Hub 和相关 Node，备份原 hub.yaml、SQLite及其侧文件、登记/总览口令和 Node 身份。不要在真实运行库试验升级。
2. 未确认清理的旧会话先按下节核查，不能删除原记录或把 UNKNOWN 改成 COMPLETE。迁移遇到这类记录会拒绝启动，schema保持旧版本。
3. 在原部署的 .venv 安装新包，Node 按其手册升级到0.8.1；保留设备长期身份与登记凭据。

```bash
uv pip install --python .venv/bin/python "$HOME/Downloads/runbridge_hub-0.9.1-py3-none-any.whl[mcp]" -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -c 'from importlib.metadata import version; print(version("runbridge-hub"))'
.venv/bin/runbridge-hub generate-token --output .runbridge/hub.token
```

4. 在 Hub YAML 增加 hub_token_file、public_url，以及按需要设置 grant_max_lease_seconds（默认86400）和 grant_idle_timeout_seconds（默认600）；完整格式见[注释配置](../reference/examples/Hub启动配置.yaml)。登记/申请/总览三个秘密必须不同。
5. 由操作者启动 Hub，再启动 Node。数据库升到schema5，新增每Node最多一份占用租约的唯一索引，全部旧grant失效；不会从多份旧许可中选择一个继续使用。设备身份、历史会话和命令保留。迁移自动在数据库旁保存 .pre-lease-时间.bak；它不能替代升级前完整备份。
6. 检查health、独立总览、资源池ONLINE/READY/FREE与UNCLAIMED。调用方用Hub认证重新领取，完成真实动作、关闭会话、释放Node，确认cleanup和RELEASED。原access.json不再有效，不能只改本地到期时间。

回滚须先停止新服务，再恢复升级前数据库和匹配旧包/配置；不能让旧包打开schema5。旧版升级说明在Git历史与[发布记录](../project/版本发布记录.md)保留，不作为0.9.1的操作步骤。

## 清理未知的离线核查

只有具备Hub主机文件权限的维护者可执行，普通hub_token没有强制交接接口。先停止目标Hub与相关Node；根据原会话、Node的state-node_ID活动记录、PID创建时间、专用短目录及marker核查原范围。managed只处理该范围拥有的worker/浏览器/Profile；borrowed断开项目连接，保留原Chrome及其登录。确认没有原任务继续执行，将核查过的Node活动记录归档到state目录之外（保留证据，不删除未经核查的记录），避免重启时对已移除目录重复判为UNKNOWN。再保存UTF-8 JSON证据，示例字段如下，时间和ID均需换成实际值：

```json
{"node_id":"node_example","grant_id":"grant_example","checked_at":"2026-10-23T14:00:00+00:00","details":"填写已停止的实例、原会话及进程/目录核查结果；不要写令牌"}
```

证据时间不得早于租约创建或晚于当前服务器时间。将文件保存为cleanup-evidence.json、权限600，在Hub部署目录执行：

```bash
.venv/bin/runbridge-hub confirm-cleanup --db-path .runbridge/hub.sqlite3 --grant-id grant_example --evidence-file cleanup-evidence.json --confirm-node-stopped
```

运行中的Hub会因进程锁被拒绝。命令自动备份数据库，按精确grant_id记录证据；schema5仅允许处理QUARANTINED，旧schema可记录阻塞迁移的原许可。相同证据重复提交幂等，不能覆盖已有证据。命令不重放执行、不改写原会话的UNKNOWN；schema5解除租约占用，状态保留原cleanup并额外返回resolution。旧库核查完成后仍需正常升级、旧grant全部失效。

重启后确认原租约状态与证据、Node重新探测就绪，再允许新领取。未取得可信核查证据时继续保持隔离。

## 停机与配置变更

先结束任务并释放Node，再正常停止服务和备份。租约到期、活动时间和空闲策略持久化，Hub重启不会重置时钟；原会话中断后清理未知会隔离。改租期上限只影响后续申请/续租，改空闲配置只影响新租约，续租不重置空闲。实例启动、安装或手册更新不代表远程部署已升级；以目标.venv安装元数据和实际业务验证为准。
