# Client integration and usage

[简体中文](调用方对接与使用.md) · English

Applies to **Hub 0.9.2 / Node 0.8.1**. Run on the **client machine** once remote Hub and Node are ready. The HTTP examples require only Python's standard library, without local Hub, Node, Playwright SDK, or browser installation.

## 1. Claim Node through Hub

Obtain an independent `hub_token` and actual base URL from the Hub deployer, and the target `node_id` from the pool or maintainer. Save private `hub-auth.json`:

```json
{"hub_url":"https://hub.example/runbridge","hub_token":"REPLACE_WITH_ACTUAL_HUB_CLAIM_TOKEN"}
```

Copy [node_lease.py](../reference/examples/node_lease.py) into your client directory and use your Python environment:

```bash
chmod 600 hub-auth.json
.venv/bin/python node_lease.py claim --hub-auth hub-auth.json --node-id node_example --output access.json --lease-seconds 3600
```

Replace `node_example`. Save the returned five-field `access_config`, not the entire response: `hub_url`, `node_id`, `grant_id`, `access_token`, `expires_at`. Node diagnostics and DSH also support YAML with those fields; these standard-library examples read JSON. Keep credential files outside Git.

A claim exclusively holds the entire Node. Defaults: 3600-second lease, maximum 86400, idle timeout 600; the last two are Hub settings. Execution and release use this claim's access token, not the shared Hub credential. A duplicate claim does not redeliver its secret. If the first response is lost, wait for reclaim rather than overriding occupancy.

Before claiming, Hub credentials can query `GET /v1/pool/nodes` and `GET /v1/pool/nodes/{node_id}/tools` without occupying devices. Plugins prepare and review plans first. See the [lease API](../reference/Node使用权租约接口.en.md).

## 2. Run a complete example

Prepare Python **3.14.x** and [uv](https://docs.astral.sh/uv/getting-started/installation/). Copy [执行会话调用.py](../reference/examples/执行会话调用.py) and the real access file into your working directory:

```bash
mkdir -p ~/runbridge-client
cd ~/runbridge-client
uv venv --python 3.14 .venv
# Save access.json and 执行会话调用.py in this directory first.
chmod 600 access.json
.venv/bin/python 执行会话调用.py --access-file access.json --resource-id chromium --url https://example.com --screenshot page.png
```

Use the advertised resource ID and a URL reachable from **Node's browser**. `127.0.0.1` means Node, not the client. Success returns actual URL/title, session ID, `cleanup: COMPLETE`, and a local PNG.

For borrowed Chrome, use its resource ID and `--page-url 'EXACT_EXISTING_PAGE_URL'`. The example selects that page and navigates it to `--url`. For read-only inspection without navigation, submit read operations directly. If multiple pages have the same URL, inspect their contents to select a unique reference or have the owner prepare distinguishable URLs. Do not assume the first page. Borrowed input brings the selected Page forward; read-only queries and streaming do not.

## 3. Call sequence and business checks

1. `GET /v1/nodes/{node_id}/capabilities`: check ONLINE, freshness, READY/FREE.
2. `GET /v2/nodes/{node_id}/tools`: read authorized method/input/output/default/resource declarations.
3. `POST /v2/nodes/{node_id}/sessions` with `{"resource_id":"chromium","tool":"playwright","request_id":"open_order_1","lease_seconds":300}`. Retain `session_id` and `objects`.
4. Use actual `objects.root`, `contexts`, `pages`, and `default_page_id` (possibly null). References are session-bound; never invent or reuse them across sessions.
5. `POST /v2/sessions/{session_id}/commands` submits an action.
6. Check `status` and `execution_outcome`, then read the actual page or business record.
7. `DELETE /v2/sessions/{session_id}` closes each case; verify `cleanup=COMPLETE`. Borrowed release preserves original Chrome.
8. Release Node separately after the complete task or batch.

Example targeting a Chinese-labeled form, using a real Page reference in place of `page_example`:

```json
{
  "request_id": "fill_order_1",
  "method": "locator.fill",
  "target": {
    "type": "page",
    "id": "page_example",
    "locator": [{"method":"get_by_label","params":{"text":"用户名","exact":true}}]
  },
  "params": {"value":"测试用户","timeout":10000}
}
```

Use a new request ID for a click, `method=locator.click`, locator step `{"method":"get_by_role","params":{"role":"button","name":"保存","exact":true}}`, and `{}` params. Then read the result element, and verify the persisted business record when relevant. Labels and input values must match the actual page; they are not translated automatically.

`locator.inner_text` returns text at `response.result.value.value`, while `page.title` returns it at `response.result.value`. For example, `{"status":"SUCCEEDED","result":{"kind":"json","value":{"value":"已保存","truncated":false}}}`. Inspect the inner `truncated` field; do not compare the entire object as text.

Only the explicit method subset is supported. Params use snake_case, default timeout 10000 ms, range 1–30000. Arbitrary Python, `evaluate`, callbacks, and Node-local file paths are not accepted. See [protocol](../reference/工具调用协议.en.md) and [33 methods](../reference/Playwright方法表.en.md).

## 4. Timeouts, disconnects, and repeated requests

Even HTTP 200 requires checking the result: SUCCEEDED is technical completion, FAILED a known error, UNKNOWN an unconfirmed final outcome. `OUTCOME_UNKNOWN` can mean a click, upload, or submit already happened.

HTTP 202 means the request is still running. Keep the original ID and query `GET /v2/sessions/{session_id}/commands/{request_id}`; use the same approach after a disconnected HTTP request.

Within one lease/session, identical method/target/normalized params with the same ID return the original state or cache. Different content returns `REQUEST_ID_CONFLICT`. New sessions, restarts, or cache expiry do not replay actions. `result_available=false` / `RESULT_EXPIRED` means the full result is unavailable, not that execution never happened.

Repeated matching session creation returns the same allocation even after it closes. Browser sessions default to 300 seconds, up to 3600, bounded by lease expiry. A new task needs a new creation ID.

## 5. Frames and agents

Subscribe using returned `visual.stream_path`; see [streaming](浏览器画面流接入.en.md). Agents use [MCP](MCP浏览器接入.en.md), whose exact schemas are returned by `tools/list`. Both use the Node execution flow.

## 6. Return Node after the task

```bash
.venv/bin/python node_lease.py status --access-file access.json
.venv/bin/python node_lease.py release --access-file access.json
```

The release helper waits for reclaim. RELEASED confirms handoff; QUARANTINED remains unavailable and needs review. Retain the original access file and query with its token after errors. Complete cleanup on success, cancellation, and failure, typically in `finally`. The helper retains the file for later terminal-state queries.

Renew with the original token at `POST /v1/grants/{grant_id}/renew`, e.g. `{"lease_seconds":3600}`. Renewal never shortens expiry, resets idle time, or extends an existing browser session. Status polling, MCP handshakes, frames, and keepalive do not maintain idle occupancy.
