# Hub 接入检查

[文档导航](../README.md) · [部署 Hub](../deployment/部署与运行.md) · [Hub 配置与凭据](../reference/部署配置与凭据.md)

本文用于检查已经部署的 Hub 0.5.1，并交接远程 Node 和接口调用方。安装、监听、MCP 和凭据准备统一按部署指南完成。

## 1. 确认服务从远程可达

在需要接入 Hub 的网络中执行，将地址替换为实际值：

```bash
curl --fail http://192.168.50.10:8787/health
```

返回 `{"status":"ok","protocol_version":1}` 说明健康入口可达。它不证明 Node 已登记或浏览器可执行。

## 2. 交接 Node 所有者

向所有者提供 Hub 基址和同一份登记纯文本文件，由其按照 **RunBridge Node 项目**的部署指南在浏览器设备完成登记和资源准备。

请所有者回报以下信息：

| 信息 | 用途 |
| --- | --- |
| 实际 Node ID | Hub 查询目标 |
| 资源 ID 和模式 | 区分受管理 Chromium 和已有 Chrome |
| 在线与就绪状态 | Node 应为 ONLINE，能力未过期，所需资源 READY/FREE |
| 调用许可文件 | 所有者签发给指定调用方，包含 Hub 地址和访问令牌 |

登记凭据用于准入，调用许可用于接口访问；Hub 的登记文件不作为调用方认证材料。

## 3. 调用方验证

取得访问文件后，按[调用方指南](调用方对接与使用.md)在独立调用目录查询节点与资源。HTTP、SDK 和 MCP 都连接 Hub 的公开地址；MCP 还要求服务已开放 `/mcp`。

SDK 会话应从 READY 进入 ACTIVE，结束时检查实际 cleanup。业务成功由调用方自己的断言验证。画面能力、可用入口和真实新帧分别核对，见[画面流接入](浏览器画面流接入.md)。

## 4. 异常处理

健康失败先查 Hub 服务和网络；登记或资源失败由 Node 所有者检查自己的设备；401 核对当前使用的是调用许可及其有效期。Hub 运行与代理配置问题见[运行与排障](../deployment/运行与排障.md)。
